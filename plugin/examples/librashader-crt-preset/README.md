# librashader CRT preset on a generated frame sequence

## Intent and scope

- Tool ID and version/build: `librashader`, `librashader-cli` 0.12.1 (crates.io, built from source with `cargo install --locked`), features `metal,wgpu`.
- VCR job and exact claim: "`librashader-cli render` applies a pinned RetroArch slang CRT preset to each frame of a generated image sequence, headlessly on the Metal runtime, with a visible CRT look (curved screen, dark corners, scanline and mask modulation), deterministic output, identical in any frame order."
- Explicit exclusions: other presets (only `crt-lottes`, plus `crt-geom` for one frame), multi-pass or LUT-texture presets, parameter overrides (`--params`), the OpenGL, Vulkan and Direct3D runtimes, history/feedback effects across frames (each frame is a separate invocation), video encode, other machines or GPUs. Not a judgment of how faithful the look is to a real CRT.
- Licences, checked 2026-11-27: `librashader-cli` is `MPL-2.0 OR GPL-3.0-only` (crate metadata). Shaders are fetched, never committed, from `libretro/slang-shaders` commit `02bf134555c4595bd6b69be89feaff923da83754`, each with its own licence:

| Shader | Licence (from its header) | Redistribution |
| --- | --- | --- |
| `crt/shaders/crt-lottes.slang` | "PUBLIC DOMAIN CRT STYLED SCAN-LINE SHADER" (Timothy Lottes) | free |
| `crt/shaders/crt-geom.slang` | GPL-2.0-or-later (cgwg, Themaister, DOLLS) | GPL terms; used here only as a downloaded second preset |

  The repository itself has no single shader licence; always read the header of the preset you use.
- Environment: macOS 26.6 arm64 (Apple M3), Metal GPU, rustc/cargo 1.95.0. The crate declares no `rust-version`; 1.95.0 built it, so no MSRV block.
- Input: generated by `run.sh` with FFmpeg `testsrc2` 320x240, frames 0..2. No third-party assets.
- Dependencies, installation, network: `cargo install ... --root output/cargo` (ignored directory, not `~/.cargo/bin`); the default `full` feature set failed here because OpenGL's `glfw-sys` needs `cmake`, which is not installed, so `--no-default-features --features metal,wgpu` was used. Network: crates.io at install, `raw.githubusercontent.com` for four shader files (sha256 pinned in `run.sh`). `run.sh` also needs `ffmpeg`, `magick`, `jq`.
- Output paths: `examples/librashader-crt-preset/output/` (ignored). Only `expected/summary.json` is retained.

## Plan, before running

- Commands: `librashader-cli render -p <preset>.slangp -i f<N>.png -o out.png -r metal -d 960x720 --frame <N>` for N = 0,1,2 in order (out-a), in order 2,0,1 (out-b), and again in order (out-c); `crt-geom` for frame 0; one `-r wgpu` attempt.
- Predeclared checks:
  1. Output dimensions 960x720 for every render.
  2. Each output differs from a point-sampled upscale of its input: normalised MAE >= 0.02.
  3. Screen curvature: mean luminance of the 4x4 bottom-left corner <= 0.05 where the input corner luminance > 0.2.
  4. Scanline modulation: luminance stddev down a 300-row slice of a flat input column >= 0.01, input stddev < 0.001.
  5. Frames 0 and 1 differ; `crt-lottes` and `crt-geom` outputs of frame 0 differ.
  6. Shuffled-order outputs are byte-identical to sequential; the rerun is byte-identical.
  7. The `wgpu` runtime also renders frame 0. (Added after a first probe showed the failure; kept as predeclared so it cannot be dropped.)
  8. `expected/summary.json` (hashes, rounded metrics, booleans) matches on later runs.
- Failure handling: a false check is recorded in `expected/` and printed as `KNOWN FAIL`; `run.sh` exits 0 only while the run reproduces the record.
- Inspect: `output/inspect-presets.png`, `inspect-sequence.png`, `inspect-zoom.png`.

## Observation, after running

- 2026-11-27, Claude agent, `Conors-MacBook-Pro-2.local`.
- Checks 1 to 6 and 8 pass; check 7 is a **KNOWN FAIL**: `-r wgpu` exits with `Unsupported features were requested: PIPELINE_CACHE` on this machine.
- Measurement fix before recording: the first run reported corner luminance 0.50 because ImageMagick's `fx:mean` included the PNG alpha channel. Adding `-alpha off` corrected the measurement; no threshold changed.
- Observed: corner luminance 0.00, scanline stddev 0.04 (input 0), all hashes stable over three renders per frame.
- Looked at at intended scale: the output shows barrel curvature, dark rounded corners, colour desaturation and bloom, and an 8x zoom shows a visible RGB-style mask with horizontal scanline gaps. `crt-geom` gives a recognisably different, rounder bezel. Test-card text and noise patches stay readable.
- Establishes: Metal route, macOS arm64, one machine; byte determinism on that machine. Does not establish: wgpu, other GPUs (hashes are GPU-specific), other presets, sequences longer than 3 frames or temporal presets.
- Verdict: **partial**.
