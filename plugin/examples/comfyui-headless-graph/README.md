# ComfyUI headless graph fixture

## Intent and scope

VCR job and claim: a headless ComfyUI server bound to 127.0.0.1 in CPU mode accepts
an API-format workflow JSON posted to `/prompt`. The workflow loads a generated input
PNG, applies built-in nodes (nearest-exact scale 2x, invert, blend with a generated
solid colour at factor 0.5) and saves the result. The output image has the predeclared
size and predeclared pixel values at four known positions. `/history` records the run.
Resubmitting the same workflow to the same server is expected to give a byte-identical
output; the result is recorded either way.

Tool: ComfyUI `v0.46.0`, pinned to commit `a277b5bf213e8a44fa34817b7770b54f86ef4cea`
(tag `v0.46.0`, committed 2026-11-18), cloned from `https://github.com/Comfy-Org/ComfyUI`
into `output/src/` (git-ignored). Route: the HTTP API (`/prompt`, `/history`, `/view`)
with the server started by `run.sh` and stopped by a shell trap.

Explicit exclusions:
- No model of any kind: no checkpoint, VAE, LoRA, ControlNet, embedding or upscaler is
  downloaded or loaded. The graph uses only built-in image nodes.
- No custom nodes (`--disable-all-custom-nodes`), no ComfyUI-Manager (not enabled), no
  auto-update, no telemetry (`DO_NOT_TRACK=1`, `--offline`), no auto-launched browser.
- No GPU, no MPS, no `--fast` or precision flags. CPU only (`--cpu`).
- No frontend interaction: the browser UI is not exercised. The claim is the HTTP API.
- No websocket progress stream, no queue management, no `/interrupt`.
- No sampler, text encoder, latent space or diffusion step. Graph runtime only.
- No semantic claim about generative output; the pixels are arithmetic on a
  procedural input.
- Only one input image (64x48 RGB, four quadrants) and one workflow. No batch,
  no video, no mask input, no alpha channel.
- Byte identity is observed on this machine (macOS arm64, CPU torch, PIL PNG encoder)
  only; not a cross-machine, cross-torch or cross-Python claim.

## Plan, before running

Commands (after the install above):
```
examples/comfyui-headless-graph/run.sh            # start server, submit twice, check, diff expected/
examples/comfyui-headless-graph/run.sh --record   # only after a deliberate change
```

How the server is run (in `run.sh`):
```
DO_NOT_TRACK=1 output/venv/bin/python output/src/main.py --cpu --listen 127.0.0.1 --port 8188 \
  --base-directory output/comfy --disable-auto-launch --disable-metadata \
  --disable-all-custom-nodes --disable-product-tips --offline --cache-none
```
- Started in the background by `run.sh`; its PID is held in `SERVER_PID` and it is killed
  in an `EXIT` trap, so a failed run does not leave a server behind. It is also killed
  explicitly after the two submissions.
- The run refuses to start if the port already answers.
- `--cache-none` disables the node result cache, so run B is meant to be a real second
  execution, not a cache replay. Each run is recorded in `output/results/run-*.json` with
  its `/history` message events and any `execution_cached` node ids.
- `--disable-metadata` keeps prompt JSON out of the PNG, so the output is pixels only.

Workflow (`workflow.json`, API format, six nodes):
1. `LoadImage` `vcr-fixture-input.png` (64 x 48 RGB).
2. `ImageScale` nearest-exact to 128 x 96, crop disabled (exact 2 x 2 blocks).
3. `ImageInvert`.
4. `EmptyImage` 128 x 96, batch 1, colour `0x3366CC` (51, 102, 204), integer 3368652.
5. `ImageBlend` `image1` = node 3, `image2` = node 4, `blend_factor` 0.5, `blend_mode` normal.
   In normal mode the node computes `image1*(1-f) + image2*f` (source:
   `comfy_extras/nodes_post_processing.py`), so each channel is `0.5*(255-v) + 0.5*c`.
6. `SaveImage` `filename_prefix` `vcr-fixture`.

Input quadrants (64 x 48, `fixture.py`), and the predicted output at each probe. The output
probe is the centre of the 64 x 48 quadrant of the 128 x 96 output:

| Quadrant (input colour) | Input RGB | Probe (output x, y) | Predicted output RGB |
| --- | --- | --- | --- |
| top_left | (200, 50, 30) | (32, 24) | (53, 153.5, 214.5) |
| top_right | (10, 120, 220) | (96, 24) | (148, 118.5, 119.5) |
| bottom_left | (90, 200, 40) | (32, 72) | (108, 78.5, 209.5) |
| bottom_right | (240, 240, 240) | (96, 72) | (33, 58.5, 109.5) |

Predeclared checks (`check.py`; the tolerance is a fixture parameter):
1. Output is a PNG in RGB mode of size 128 x 96, for both runs.
2. Exactly one output image in each `/history` entry (frame count = 1 still per run).
3. Each `/history` entry is completed with `status_str` `success`.
4. No node is served from cache in either run: the `/history` `execution_cached` message
   lists no nodes, and the message sequence ends in `execution_success`. (Planned first as
   "all six nodes reported executed", but `/history` v0.46.0 has no per-node executed
   event; see the deviation in the observation.)
5. Pixel probes: at each of the four probes, every channel of each run is within 1 of the
   predicted value above (predicted values are unrounded; integer output may truncate).
6. Server listens on `127.0.0.1:<port>` only (`lsof` report of LISTEN sockets, saved by
   `run.sh`; no `*`, `0.0.0.0` or `::` listener).
7. Resubmission byte identity: the sha256 of run A's PNG equals that of run B. This is
   reported either way and is not a gating check (see result rules).
- Measured, not gating: input sha256, output sha256 of both runs, probe values of both runs,
  `/history` message events of both runs.
- Shuffled-order check: not applicable (the graph has no seek and no per-frame state).

Result rules (predeclared):
- pass: checks 1 to 7 all true.
- partial: checks 1 to 6 true and check 7 false (the rerun is not byte-identical). The
  scope will say the rerun was not byte-identical and report the difference.
- fail: any of checks 1 to 6 false.
- blocked: clone, venv install, server start, or submission failure, so no output exists.
  The record stays `not-validated`.

Expected failure modes and stop conditions:
- Install or import failure, server not ready in 240 s, or server exit: stop, keep
  `output/server.log`, report blocked.
- A prompt rejected by `/prompt` (node errors) or a `/history` entry that does not
  complete: stop and report blocked (the graph was not executed).
- A gating check failing: `check.py` exits 1, `run.sh` stops, `--record` is never run on
  failure, and the baseline is not rewritten to hide it.
- Missing model files: not expected, since no model node is in the graph; any such error
  would be a deviation and is recorded as blocked.

Inspection: `output/checks.json` lists every value. The contact sheet (the generated
input and the output, side by side, at display scale) is made with ImageMagick outside
`run.sh`, as the template does. It is inspection only, not a gating check.

Reproduction: the same `run.sh` on the same machine; the install steps above.
