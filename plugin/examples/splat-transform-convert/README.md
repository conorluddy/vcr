# splat-transform convert

Status: not validated. The predeclared run failed its bounds check (check 3) on 2026-11-24 (macOS arm64, splat-transform 3.12.0). The predicted bounds in this plan assumed the translate acted in the PLY file's coordinate frame; the tool does not do that for this file. See the observation below.

## Intent and scope

- Tool: splat-transform (`@playcanvas/splat-transform`, npm), pinned to 3.12.0 in this example's `package.json` (npm `latest` on 2026-11-24; the catalogue card recorded 3.6.6 on 2026-11-15). The CLI is run as `node_modules/.bin/splat-transform`. No global install.
- Claim: splat-transform reads a synthetic 3D Gaussian splat PLY, applies a predeclared translate and uniform scale, keeps only splats with linear opacity above 0.5, and writes a PLY, a compressed PLY and a SOG. Reading each output back gives the predeclared splat count and transformed bounds within tolerance, and reruns are byte-identical for the PLY and compressed PLY.
- Exclusions: the `.spz`, `.html`, `.glb`, `.csv`, Streamed SOG, LOD, voxel and image writers; the `.lcc`, `.ksplat`, `.splat` and `.mjs` readers; decimation, morton reorder, floater and cluster filters, SH band filtering, rotation and the NaN filter; Playwright, browsers and any rendering of the output; splat visual quality; semantic preservation of colour or opacity through the SOG and compressed PLY quantisation (measured only as bounds and counts); real captured scenes (none are used); other operating systems or architectures.
- Documentation and licence: https://github.com/playcanvas/splat-transform (README and CLI help, read 2026-11-24), user guide https://developer.playcanvas.com/user-manual/splat-transform/. Licence MIT: npm metadata and the package `LICENSE` (PlayCanvas Ltd, 2011-2026), checked 2026-11-24. The dependencies in the package (`@adobe/spz`, `webgpu`) are not separately validated here.
- Environment: macOS arm64, Node 22.19.0 (workspace `engines` is `>=22`). No GPU is used for PLY or compressed PLY writes. The SOG write is run with `--gpu cpu` (see the plan). The `webgpu` native build is not built by this workspace install (pnpm reported its build script as ignored), so WebGPU is not relied on.
- Input: no download. `make-input.ts` writes `output/input.ply`, a 100-splat synthetic binary little-endian 3DGS PLY on a 5 x 5 x 4 lattice, generated from closed-form values (no randomness). Written for this fixture; no external rights.
- Dependencies and side effects: `@playcanvas/splat-transform@3.12.0` and `tsx` in this example's `package.json`, installed by `pnpm install` at the workspace root. No network use during the run. Writes only `output/` (ignored) and `expected/summary.json` on `--record`.
- Unseeded randomness: the CLI bundle (`dist/cli.mjs`) calls `Math.random` at 8 sites, all inside SOG palette k-means code (`GpuKmeans`, `kmeansInterleaved`, `splitEntries`, `pickRandomIndices`, `chooseSplits`, `uploadEmeansPoints`). I have not traced whether the PLY or compressed PLY writers reach them, so their reruns are gated (check 6) and the run fails if they differ. The SOG rerun is measured and may not be byte-identical; if it is not, SOG is excluded from the byte-identical claim and named in the scope. Its read-back is still checked.
- Selected workspace: `examples/splat-transform-convert/`. Generated paths: `output/` (ignored, removed and recreated by `run.sh`).

## Plan, before running

- Commands: `pnpm install` at the workspace root, then `examples/splat-transform-convert/run.sh --record`, then `examples/splat-transform-convert/run.sh`.
- `run.sh` runs `make-input.ts` (writes `output/input.ply`), then `convert.ts` (two full conversion runs in `output/run-1/` and `output/run-2/`), then diffs `output/summary.json` against `expected/summary.json`.
- Each conversion run invokes the CLI once per format, with the same actions:
  - `splat-transform [global] output/input.ply -t 10,-2,0.5 -s 2 -V opacity,gt,0.5 <output>`
  - `<output>` is `out.ply`, `out.compressed.ply` or `out.sog`. The SOG run adds the global `--gpu cpu`. The PLY and compressed PLY runs use the default device, which does not matter for them.
- Transform arithmetic: lattice x index i in 0..4 maps to x = (i + 10) * 2 = 2i + 20; y index j in 0..4 maps to y = (j - 2) * 2 = 2j - 4; z index k in 0..3 maps to z = (k + 0.5) * 2 = 2k + 1. The filter keeps splats with linear opacity above 0.5. Opacity is 0.9 for i < 3 and 0.2 otherwise, so the kept set is exactly i in {0, 1, 2}.
- Predeclared checks (values fixed in `convert.ts` before the first run):
  1. Input read-back: 100 splats, bounds min (0, 0, 0), max (4, 4, 3), exact.
  2. Every output (both runs, all three formats): splat count exactly 60.
  3. Every output: transformed bounds min (20, -4, 1), max (24, 4, 7), within a per-format tolerance. PLY (float32, exact values): 1e-4 world units. Compressed PLY and SOG (quantised): 0.01 world units. The measured maximum error is recorded either way.
  4. PLY output, read by the fixture's own minimal PLY parser (not splat-transform): header is `binary_little_endian`, every property is `float`, 60 rows, and the opacity logit maps to linear opacity 0.9 within 1e-4 for every row. This is the only check that reads the filter's effect on opacity directly.
  5. Compressed PLY and SOG are read back with `splat-transform <file> --stats json null`, using `numGaussians` and the finest LOD's `min`/`max` for columns x, y and z.
  6. Byte identity across run-1 and run-2: required for `out.ply` and `out.compressed.ply` (a mismatch throws and the run fails). For `out.sog` it is measured and recorded in `output/rerun.json`, not gated.
  7. `output/summary.json` equals `expected/summary.json`. It holds only deterministic fields: versions, input and predicted values, the per-format counts and bounds, and the PLY and compressed PLY sha256. It excludes the SOG hash and the SOG rerun result, which are not guaranteed.
- Checks that do not apply: frame count, dimensions, alpha range, distinct-hash and shuffled-order checks, because the output is splat data, not frames. Determinism is covered by check 6.
- Expected result mapping: all of checks 1 to 7 pass, with the SOG rerun identical, is `pass`. Checks 1 to 5 and 7 pass but the SOG rerun differs, or the SOG write fails, is `partial`, with SOG named in the scope. Any count, bounds or PLY opacity failure, or a PLY or compressed PLY rerun difference, is `fail`.
- Expected failure modes and stop conditions: the SOG writer could fail without a GPU; that is recorded as partial, and I will not install or build the `webgpu` native module to fix it. A CLI parse change in `--stats json` output would stop the read-back and be reported as blocked for that format. Compressed PLY quantisation exceeding 0.01 would be a fail for that format, and the tolerance is not widened after the run.
- Reproduction and inspection: run `run.sh`, then read `output/summary.json` and `output/rerun.json`. The contact sheet is not applicable (no frames); instead I inspect the readback numbers and the input and output splat bounds directly.

## Observation, after running

- 2026-11-24, Conors-MacBook-Pro-2.local, macOS arm64. Versions: splat-transform 3.12.0 (CLI banner `v3.12.0 (5d5be2b)`, pinned in `package.json`), Node v22.19.0, tsx 4.23.15. Playwright and Chromium are not used by this example. Command: `run.sh --record`, which failed at the first output read-back.
- The predeclared run did not finish. `make-input.ts` wrote a 100-splat PLY; the input read-back passed (count 100, bounds (0,0,0) to (4,4,3), exact). Both conversion runs wrote `out.ply` with 60 splats, and run-1 and run-2 `out.ply` were byte-identical (check 6 passed). The read-back of run-1 `out.ply` then failed check 3: count 60 (passed), bounds min (-20, 4, 1), max (-16, 12, 7) against the predicted min (20, -4, 1), max (24, 4, 7). Maximum error 40 world units against a tolerance of 1e-4. `run.sh` exited 1 there, so checks 4, 5 and 7, and the compressed PLY and SOG read-back, were never reached in the predeclared run. No `expected/summary.json` was written, so `run.sh` without `--record` cannot print `OK`.
- Cause, measured by single-action diagnostics outside the predeclared run (scratchpad, not committed). Applying one axis at a time to `output/input.ply`: `-t 1,0,0` moves x to [-1, 3] (x - 1); `-t 0,1,0` moves y to [-1, 3] (y - 1); `-t 0,0,1` moves z to [1, 4] (z + 1). `-s 2` alone gives x, y, z ranges [0, 8], [0, 8], [0, 6], as predicted. `-t 10,-2,0.5 -s 2` gives x in [-20, -12], y in [4, 12], z in [1, 7] over all 100 splats; the kept 60 have x in [-20, -16]. So for this 3DGS PLY, `-t` shifted x and y in the opposite sense to the vector given, and z in the same sense. The library keeps a source transform for PLY and converts on write (`computeWriteTransform`, `dist/cli.mjs`), which is consistent with the translate acting in an internal frame, but I did not confirm that convention from the documentation. The predicted bounds assumed the file frame, so they were wrong. The predicted values were not changed after the run.
- Diagnostic, outside the predeclared run (not evidence): the compressed PLY and SOG written from the same action list, twice each into scratchpad (`--gpu cpu` for SOG), were byte-identical across the two writes (`cmp`). Both read back with `--stats json` as 60 splats with bounds (-20, 4, 1) to (-16, 12, 7), the same frame as the PLY. With 60 splats the k-means palette path may be trivial, so this does not show the unseeded `Math.random` sites are never reached at larger sizes.
- Inspection: no frames, so no contact sheet. The evidence is the read-back numbers above.
- Deviations from the plan: the predicted bounds were wrong, as above. The run was not re-planned after the failure, so the failed check stands.
- What this establishes: splat-transform 3.12.0 reads this synthetic 3DGS PLY, applies the translate, scale and linear-opacity filter, and writes a PLY whose count (60) matches the prediction and whose two runs are byte-identical. Its compressed PLY and SOG diagnostics read back with the same count and bounds as the PLY. The translate's sign convention for this PLY differs from the file frame for x and y.
- What it does not establish: the predeclared bounds (failed); a documented coordinate convention for `-t`; SOG rerun identity at larger sizes; any other writer or reader; visual correctness; other operating systems or architectures.
- Reviewer and follow-up: none. A new plan would need to declare the frame convention before running, from documentation or a single-axis test, and would be a new run, not an edit to this one. Revisit if splat-transform changes its PLY coordinate handling or `-t` semantics.
