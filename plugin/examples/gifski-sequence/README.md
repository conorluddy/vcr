# Gifski PNG sequence fixture

## Intent and scope

- Tool ID and version/build: `gifski` 1.34.0.
- VCR job and exact claim being tested: encode a three-frame, 64×64 RGB PNG sequence to a 3 fps animated GIF while preserving frame count and dimensions.
- Explicit exclusions: alpha, video/Y4M input, arbitrary color fidelity, large-image downscaling, alternate quality settings, other versions and platforms.
- Tool documentation and licence sources, checked 2026-11-15: [official README](https://github.com/ImageOptim/gifski) and [release page](https://github.com/ImageOptim/gifski/releases); AGPL-3.0-or-later. Inputs are generated by this fixture; FFprobe is a measurement helper, not credited as part of the claim.
- Environment: macOS 26.6 arm64; Gifski 1.34.0; FFprobe 9.0.2 for stream metadata.
- Input: three deterministic, fixture-authored PNG frames made by `generate_frames.py` using only Python's standard library.
- Dependencies, installation plan, permissions, network and expected side effects: Gifski and FFprobe are installed on the selected machine. No installation or network access is required. Generated files stay in ignored `output/`.
- Selected workspace, generated output and cleanup paths: this example directory; PNGs, GIFs and probe output under ignored `output/`.

## Plan, before running

- Exact commands: `python3 generate_frames.py output/frames`; `gifski --fps 3 --quality 100 --output output/sequence.gif output/frames/frame*.png`; repeat the encode to `output/repeated.gif` and compare bytes.
- Expected artifacts and predeclared checks: 64×64 GIF, exactly three decoded frames at timestamps 0.00, 0.33 and 0.67 seconds (±0.01s), duration 1.0 second within 1 ms, valid GIF codec, repeat output byte-identical, and exact Gifski/FFprobe versions plus SHA-256. FFprobe's average-rate field is recorded but not used as the timing assertion because GIF frame timing is stored in hundredths of a second.
- Intended consumer and handoff settings: standalone animated GIF. FFprobe reads metadata; ImageMagick coalesces frames only for visual inspection.
- Delivery constraints: RGB input and opaque GIF output; no transparency or external media.
- Expected failure modes and stop conditions: wrong tool version, dimensions/frame count/rate/duration mismatch, repeat-output mismatch, decode failure or visual corruption.
- Reproduction: `./run.sh --record` records the inspected baseline; `./run.sh` checks it.

## Observation, after running

The first run showed FFprobe reporting `avg_frame_rate` as `100/33` even though the GIF duration was 1.000000 seconds and its frame timestamps were 0.000000, 0.330000 and 0.670000. The check asserts those timestamps and total duration directly instead of treating `avg_frame_rate` as an exact requested rate.

Pass on 2026-11-15: Gifski 1.34.0 encoded the three frames to a 64×64 GIF of 552 bytes; FFprobe 9.0.2 reported three frames at 0.00/0.33/0.67 seconds and a 1.000000-second duration. Repeated output matched byte for byte. A coalesced visual inspection showed the square at all three expected positions. This is not a color-fidelity or transparency test.
