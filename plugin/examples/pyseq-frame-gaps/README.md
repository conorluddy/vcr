# pyseq frame-sequence ranges and gaps

## Intent and scope

- Tool/version: pyseq 0.9.3 (PyPI, uploaded 2026-07-25), BSD-3-Clause, no dependencies. Pinned in `requirements.txt`.
- Claim: given a folder of numbered image files, pyseq reports each sequence with its range and the exact missing frames, so a capture folder can be checked before encoding.
- Exclusions: pixels (it reads names only), real renders, duplicate frames, `scopy`/`smv`/`srm`/`sdiff`/`sstat`/`sfind`/`stree`, and Python other than 3.12.
- Docs and licence: https://github.com/rsgalloway/pyseq, https://pypi.org/project/pyseq/; BSD-3-Clause from PyPI metadata, checked 2026-11-27.
- Environment: macOS arm64, Python 3.12, venv in `output/venv` (git-ignored), built by `run.sh` from `requirements.txt`; needs network on the first run only.
- Input: empty files generated by `check.py` under `output/frames/`.
- Cleanup: remove `output/`.

## Plan, before running

- Commands: `./run.sh --record`, then `./run.sh`. `check.py` runs twice in separate processes; the JSON must be identical.
- Predeclared checks (all gating):
  1. `frame.%04d.png` frames 1-3, 6, 7, 10 give missing `[4, 5, 8, 9]`.
  2. Its `%R` range is `[1-3, 6-7, 10]` and length 6.
  3. `clean.%04d.png` frames 1-5 give no missing frames.
  4. `shot.%04d.exr` frames 1001, 1002, 1004, 1005 give start 1001, end 1005, missing `[1003]`. The lookup key was first written `shot.%04d.exr`; pyseq names it `shot.%d.exr` because 1001 has no leading zero. The key was corrected before the first successful run; the expectation itself is unchanged.
  5. A folder with `a` frames 1-3, `b` frames 1 and 3 and a `notes.txt` gives exactly two sequences, `b` missing `[2]`, and the text file ignored.
  6. `lss` prints `6 frame.%04d.png [1-3, 6-7, 10]`.
  7. `pad.001`, `pad.002` plus `pad.0100` (different padding) report no false gaps.
- Failure rule: a failed check stays failed and is recorded; no tolerance is loosened. Any failure gives `partial`.

## Observation

Executed 2026-11-27 on `Conors-MacBook-Pro-2.local`. Checks 1 to 4 and 6 pass and the two processes agree. Two fail and are recorded in `expected/metrics.json`; `run.sh` prints `KNOWN FAIL` and exits 0:

- Check 5: `notes.txt` comes back from `get_sequences` as a one-item "sequence" with an empty name, so non-frame files must be filtered by the caller.
- Check 7: `pad.001`, `pad.002` and `pad.0100` merge into one `pad.%03d.png` `[1-2, 100]` with 97 reported missing frames. Mixed padding in one folder gives a false gap report, as the lead warned.

This shows pyseq finds real gaps from names; it does not show it handles mixed padding or stray files without help, nor anything about frame contents.
