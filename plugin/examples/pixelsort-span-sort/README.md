# pixelsort span-sort fixture

## Intent and scope

- **Tool/version:** pixelsort 1.0.2 (PyPI, MIT) with Pillow 10.4.0, both pinned in `requirements.txt`. Lead (2026-11-20 digest) said 1.0.2, published 2026-09-03; confirmed on PyPI at check time.
- **Claim:** pixelsort sorts runs of pixels along rows (or columns at an angle) by a chosen key, deterministically except for its interval randomness, and a script can verify that independently.
- **Exclusions:** speed at 4K, image sequences, `edges`/`waves`/`file` interval functions, saturation/intensity/minimum keys, output quality or taste.
- **Input:** generated by `check.py` (colour ramps, three shapes, 1500 speckles from `random.Random(1234)`), 240x135, no external files.
- **Environment:** macOS arm64, Python 3.12, venv at `output/venv` built by `run.sh` (ignored). No system install. Network only at first venv build.
- **Finding before planning:** unpinned `pip install pixelsort` pulls the newest Pillow, where `from PIL import PyAccess` fails at import. Pillow 10.4.0 is pinned for that reason.

## Plan, before running

- **Commands:** `./run.sh --record`, then `./run.sh`. `run.sh` runs `check.py` twice in separate processes and diffs them, then diffs `expected/metrics.json`.
- **Predeclared checks (all gating):**
  1. `versions`: pixelsort 1.0.2, Pillow 10.4.0.
  2. `threshold_spans_sorted_by_lightness`: spans computed independently from the input (cut at every pixel whose lightness is outside 0.25..0.8 of 255); in the output each span is non-decreasing in (min+max)/2, each row is a permutation of the input row, and some pixels changed.
  3. `none_rows_sorted_by_hue`: with interval `none` and key `hue`, every row is non-decreasing in hue (colorsys, tolerance 1e-9).
  4. `mask_protects_unmasked_pixels`: with the left half masked in, the right half is unchanged and left rows are sorted.
  5. `angle_90_sorts_columns`: size stays 240x135 and every column is monotone in lightness from one end.
  6. `cli_matches_api`: CLI output pixels hash equals the API output for the same options.
  7. `randomness_100_is_identity`: randomness 100 leaves the image unchanged.
  8. `seeded_random_repeats_across_processes`: `random.seed(7)` before the `random` interval function gives equal output in two processes, and seed 8 differs.
  9. `cli_random_is_unseeded`: two CLI runs with `-i random` differ (the CLI has no seed option).
  10. Repeat: two `check.py` processes give byte-identical JSON.
- **Stop conditions:** import failure. A failed check stays recorded in `expected/`, the run prints `KNOWN FAIL`, evidence is partial; thresholds are never loosened.
- **Inspect:** `output/sheet.png` (input, threshold, hue, CLI random).

## Observation, after running

- **Date and executor:** 2026-11-27, onboard-pixelsort worker, macOS arm64, Python 3.12.13, pixelsort 1.0.2, Pillow 10.4.0.
- **Result: pass.** 9 of 9 gated checks and the two-process repeat diff pass on the first run; `./run.sh` exits 0 and prints `pixelsort-span-sort: OK`. Numbers are in `expected/metrics.json` (3646 threshold spans, none unsorted; 19913 pixels changed; 240 of 240 columns sorted at angle 90).
- **Inspection:** `output/sheet.png` shows the input, the threshold sort (horizontal streaks bounded by dark and bright pixels, shapes still readable), the hue sort (whole rows ordered into hue bands) and an unseeded CLI random sort (short light-to-dark smears). It looks like pixel sorting, not corruption.
- **Direction:** sorting is ascending, so brighter pixels end up to the right of each span; at angle 90 columns sort from the top down.
- **Seed:** the CLI has no seed option. The API is repeatable only if the caller seeds Python's global `random` before the call (`random.seed(7)`).
- **Does not establish:** `edges`, `waves`, `file` intervals; saturation, intensity and minimum keys; timing at 4K or over sequences; other Pillow versions (a newer Pillow fails at import); other platforms.
