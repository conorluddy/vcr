# libultrahdr gain-map encode fixture

## Intent and scope

- Tool ID and version/build: `libultrahdr` (record `catalog/tools/libultrahdr.json`), `ultrahdr_app` lib v2.0.2 from the Homebrew formula (`/opt/homebrew/bin/ultrahdr_app`; the formula ships the CLI). libjpeg-turbo 3.2.1.
- VCR job and exact claim: `ultrahdr_app` encodes a generated SDR image plus a generated HDR image (HLG, P3, RGBA1010102) into one Ultra HDR JPEG; the file carries a gain map (MPF with two images, gain map metadata the library probe reads), a plain JPEG reader decodes the SDR base, and the library decodes HDR highlights back.
- Explicit exclusions: browser or Android display as HDR; the P010 input route; encoding from an existing SDR JPEG (scenarios 2 to 4); PQ or linear HDR; real photographs and noisy content; downsampled or single-channel gain maps; AVIF/HEIC output; metadata interoperability with other writers (Android, Pixel, Adobe).
- Sources, checked 2026-11-27: https://github.com/google/libultrahdr (Apache-2.0 per Homebrew; GitHub reports NOASSERTION); flags from `ultrahdr_app -h` output. Input is generated by `generate_input.py` with numpy; no third-party assets.
- Environment: macOS 26 arm64, Homebrew; exiftool 13.50, ImageMagick 7.1.2-36, ffmpeg 9.0.2, numpy 1.26.4, Python 3.12.2.
- Input: 128x96. SDR: smooth RGB gradient with a grey highlight bar topping out at 0.75. HDR: same gradient, bar reaches 1.0, packed little-endian RGBA1010102.
- Dependencies, permissions, side effects: all tools already on PATH; nothing installed, no network, writes only to ignored `output/`. `run.sh` exits 127 with the install command when a tool or numpy is missing.

## Plan, before running

- Commands: `python3 generate_input.py output`; `ultrahdr_app -m 0 -w 128 -h 96 -p hdr.rgba1010102 -a 5 -t 1 -C 1 -y sdr.rgba8888 -b 3 -c 0 -z uhdr.jpg` (twice); a plain JPEG made with `magick` as negative control; `-m 1 -P` probe; `-m 1` decode to HLG RGBA1010102 and to sRGB RGBA8888; `check_output.py` writes `output/metrics.json`; `run.sh --record` copies it to `expected/`, `run.sh` diffs it.
- Predeclared checks (10):
  1. File starts with JPEG SOI.
  2. exiftool `MPF:NumberOfImages` is 2.
  3. XMP `hdrgm:GainMapMax` is present in the gain map image (named in the lead as the XMP check).
  4. Probe prints `Ultra HDR Image: Yes` and `maxContentBoost` > 1.
  5. `magick identify` and `ffmpeg` both decode the file as 128x96.
  6. SDR base vs SDR input PSNR >= 30 dB.
  7. HLG decode: peak 10-bit channel in the highlight region >= 900 (SDR input there is at most about 767).
  8. sRGB decode is 128x96x4 bytes.
  9. Negative control: probe of a plain JPEG exits non-zero.
  10. Two encodes are byte-identical.
- Stop conditions: a failing check is recorded as a KNOWN FAIL in `expected/metrics.json`, never loosened; `run.sh` exits 0 only while a rerun reproduces the record.
- Inspection: `output/contact.png` (SDR base beside gain map, 3x).

## Observation, after running

- Date and executor: 2026-11-27, Conors-MacBook-Pro-2.local, agent in an onboarding worktree.
- Commands: `./run.sh --record`, then `./run.sh` (exit 0, OK).
- Results: 9 of 10 pass. Failing: `xmp_hdrgm_gain_map_max_present`. The file has no XMP at all; instead both the primary and the gain map image carry an APP2 `urn:iso:std:iso:ts:21496:-1` segment (ISO 21496-1 gain map metadata), plus MPF. Probe reads it: maxContentBoost 9.462, hdrCapacityMax 4.926. File 7410 bytes (gain map 4024). SDR base PSNR 50.39 dB. HLG decode highlight peak 1023. Plain JPEG probe exit 255 ("does not contain gainmap image"). Repeat encode identical.
- Inspection: SDR base shows the gradient with a flat grey bar; the gain map shows a bright-to-white ramp inside the bar and dim values elsewhere, as built. Nothing blank or misplaced.
- Result: partial.
- Establishes: on this machine the Homebrew CLI produces a gain-map JPEG whose SDR base any JPEG reader decodes and whose HDR the library reconstructs. Does not establish XMP/Google-style metadata (absent here; readers that only parse XMP may not see the gain map), display as HDR, or other writers.
- Revisit if the formula version changes or a reader needing XMP matters.
