# Pts geometry capture

## Intent and scope
Pts 1.0.3 (`dist/pts.min.js`, global `Pts`); the VCR job is geometry built from Pts primitives and drawn with a `CanvasForm` onto a `CanvasSpace` bound to an existing `<canvas>`. The scene uses `Pt`, `Create.radialPts` (static ring), `Line.subpoints` (static ticks), `Polygon.fromCenter`, `Group.rotate2D`, `Polygon.centroid`, `Circle.fromCenter`, `Geom.interpolate` and `CanvasForm` drawing calls. Each frame is computed from `t` in `seek(t)`, which clears the space and draws explicitly; the scene does not call `space.play()`, `space.add()` or any animate callback, so Pts' own loop (`Space.play` uses `requestAnimationFrame` recursively) never runs. Proves: 90 alpha PNG frames at 1280x720, 30 fps, from a seek-driven Pts scene; shuffled capture equals sequential. Excludes every helper that calls `Num.random` (unseeded `Math.random` unless `Num.seed` is set): `Pt.random`, `Num.randomRange`, `Create.distributeRandom`, `Create.noisePts`, `Create.sampling`, `Create.flock`, `PoissonDisk`, physics, UI and pointer or keyboard events, SVG and DOM spaces, `Num.seed`, animation loops, other browsers and GPU behaviour. `Util.uniqueId` (reached from the `CanvasSpace` constructor through `Math.random`) only sets the space's element id, which is overwritten because the space is bound to a selector, so it does not touch pixels. Procedural original shapes; no media or fonts. Code Apache-2.0, checked 2026-11-11: the installed `pts@1.0.3` package `LICENSE` and `package.json` `license` field; docs https://ptsjs.org/ . No codec, model or asset dependency.

## Observation, after running
2026-11-11, evidence-runner agent on Conors-MacBook-Pro-2.local (`hostname`), macOS Darwin 25.6.0 arm64, Node 22.19.0, Pts 1.0.3 (`dist/pts.min.js`), Playwright 1.64.1, Chromium 156.0.8078.4 (queried from the installed Playwright; the capture report does not carry it), ImageMagick 7.1.2-15, tsx 4.23.15. Screenshot capture route (`captureMode: screenshot`), Canvas 2D backend. GPU details unknown and not claimed.

First `--record` attempt failed the determinism check: shuffled and sequential hashes differed at frames 0 and 1, so nothing was recorded and `expected/` stayed empty. Cause: a canvas-bound `CanvasSpace` runs `_ready` about 100 ms after construction, which resizes and clears the canvas, so seeks made before that moment were wiped. The scene now exposes `window.__scene` from the space's ready callback. Predeclared checks were not changed.

After that fix: `--record` exited 0 and the second run printed `pts-capture: OK`. 90 frames at 1280x720; 90 distinct hashes; `mismatched_frames` empty, so shuffled equals sequential; frame 45 alpha min 0 and max 1. Measurements are in `expected/summary.json`; hashes are in the ignored `output/report.json`.

Inspected the contact sheet (frames 0, 15, 30, 45, 60, 75) and frame 45 at native 1280x720. The frames show a static ring of 16 blue points (`Create.radialPts`); a blue horizontal `Line` with 11 ticks (`Line.subpoints`); an orange marker sliding left to right and back along that line (`Geom.interpolate`); and a translucent lime hexagon (`Polygon.fromCenter`, rotated with `Group.rotate2D`) that drifts on a circle and pulses in size, with an orange dot at its centroid (`Polygon.centroid`, `Circle.fromCenter`). Background is transparent. No blank frames or clipping. Defect in the fixture, not in Pts: the hexagon is drawn fill-only because `fillOnly` follows `strokeOnly` and clears the stroke, so no outline appears. Agent visual review only; no human approval claimed.

Result: pass for the stated claim. Scope limits: the `Num.random`-based helpers are not exercised; the scene does not call `space.play()`, so Pts' own loop never runs; the drawing uses the `CanvasForm` on a `CanvasSpace` bound to an existing canvas. Does not establish interaction or pointer events, SVG or DOM spaces, other browsers, GPU behaviour or cross-platform byte equality. Revalidate on Pts, Playwright or Chromium changes.
