# dssim perceptual still comparison fixture

## Intent and scope

- Tool ID and version/build: `dssim` 3.4.0 (kornelski's Rust CLI, Homebrew formula `dssim` 3.4.0 bottle `arm64_tahoe`, installed at `/opt/homebrew/bin/dssim`). `dssim --help` prints `Version 3.4.0`; the CLI has no `--version` flag.
- VCR job and exact claim being tested: dssim scores a generated PNG against itself as 0, against progressively degraded versions (JPEG q90, q50, q10 made by ImageMagick and decoded back to PNG) with strictly increasing scores, and writes a difference map; reruns give identical scores.
- Explicit exclusions: the score scale and absolute values (dssim says they are not comparable across tools or versions); tolerance thresholds for any particular use; the difference map's visual meaning beyond "it is non-blank and grows with degradation"; alpha images (the base is opaque RGB); 16-bit or greyscale inputs; other dssim versions and platforms; the library API (`dssim-core`), C API and any linking into shipped code; timing or speed; `-o` maps for the 90 and 50 cases being judged beyond the checks below; ImageMagick's JPEG encoder beyond being the degradation source. ImageMagick is used to make the degraded inputs and is not credited as part of the claim.
- Tool documentation and licence sources, checked 2026-11-24: the tool card's [github.com/kornelski/dssim](https://github.com/kornelski/dssim) README (usage, `-o` difference map, 1/SSIM-1 scale, version note) and the GitHub licence API (`AGPL-3.0`). The card's dual licence note (commercial option at supso.org) is not re-verified here. The Homebrew formula reports `AGPL-3.0-or-later`; the card says `AGPL-3.0`. Inputs are generated by this fixture, so no external asset terms apply.
- Environment: macOS 26.6 arm64 (Conors-MacBook-Pro-2.local); dssim 3.4.0; ImageMagick 7.1.2-35 Q16-HDRI (`magick`); Python 3.12.2 (standard library only, generator and checker). No GPU involved. Playwright, Chromium and Node do not apply.
- Input: one 256×256 8-bit RGB PNG made by `generate_frames.py` (standard library only, no `random`, no clock). It has a vertical gradient, a fine 4-pixel grid, sharp-edged filled circles and a deterministic integer texture, so JPEG quantisation has visible high-frequency content to damage. The degraded inputs are JPEGs made by `magick base.png -quality {90,50,10}` and decoded to 8-bit RGB PNG with `magick ... PNG24:`.
- Correction to the catalogue record: the record's install `python3 -m pip install dssim` installs PyPI `dssim` 1.3.0, a discrete-event simulation framework by majvan (Apache-2.0), not this tool. It was checked on PyPI JSON metadata and not installed. The route used here is `brew install dssim`, which the user approved. The record's `install` field is corrected to match.
- Dependencies, installation plan, permissions, network and expected side effects: dssim 3.4.0 installed by `brew install dssim` (approved; Homebrew bottle, no build from source). Nothing installed into this repository, no `pnpm` dependency, no venv. The fixture needs no network. Writes go only to the ignored `output/` directory.
- Selected workspace, generated output and cleanup paths: `examples/dssim-still-compare/`; inputs, degraded files, score files, difference maps and metrics under ignored `output/`. Only `expected/metrics.json` is committed, and it holds no media.

## Plan, before running

- Exact commands: `python3 generate_frames.py output/input`; `magick output/input/base.png -quality Q output/degraded/qQ.jpg` then `magick output/degraded/qQ.jpg -depth 8 PNG24:output/degraded/qQ.png` for Q in 90, 50, 10; then twice (into `output/scores` and `output/scores-repeat`): `dssim base base` (self), `dssim base q90 q50 q10` (sequential), `dssim base q10 q50 q90` (reversed), and `dssim -o <dir>/maps/qQ.png base qQ.png` for each Q. `check_output.py` parses the score lines, runs the checks and writes `output/metrics.json`. The dssim version is read from `dssim --help`; the ImageMagick version from `magick -version`.
- Predeclared checks (any failure stops the run and the result is not `pass`):
  1. `dssim --help` reports exactly `Version 3.4.0`.
  2. `base.png` is 256×256, colour type 2 (RGB), bit depth 8. The three degraded PNGs are 256×256 too, so dssim accepts them against the base.
  3. Frame count: the base plus three degraded PNGs (four PNG inputs), and three difference maps per run, each 256×256.
  4. Self-score: `dssim base base` gives exactly `0` in both runs.
  5. Strictly increasing: in both runs, `0 < score(q90) < score(q50) < score(q10)`.
  6. At least two distinct hashes across the four PNG inputs (the base, and the decoded q90, q50, q10 PNGs). The checker records all four and asserts at least two distinct values.
  7. Order: the reversed-order run gives the same score text for each degraded image as the sequential run (the shuffled-equals-sequential check, applied to scoring).
  8. Difference maps: `dssim -o maps/qQ.png` writes five per-scale PNGs, `qQ.png-0.png` to `qQ.png-4.png`. The check uses scale 0 (the full-resolution map): it is 256×256, non-blank (max and mean above 0), and its mean grows with degradation (`mean(q90) < mean(q50) < mean(q10)`). All five scale files must exist.
  9. Rerun identity: the second run's score files are byte-identical to the first, and every map file is byte-identical to its first-run counterpart (checked by file comparison; scale-0 sha256 recorded).
  10. Expected artifacts: `expected/metrics.json` with dssim and ImageMagick versions, the four input hashes, the score lines, the map hashes and the map statistics.
- Alpha range: not applicable (opaque RGB base); not part of the claim.
- Expected failure modes and stop conditions: dssim not 3.4.0; a degraded file that decodes at a different size; a self-score that is not exactly zero; a non-monotone score; a blank or all-zero map; a score or map that differs between runs (nondeterminism, which would falsify the claim and is reported as `fail`); a decode failure in ImageMagick.
- Expected output format: the score is the first whitespace-separated field of each dssim output line (dssim prints per-file scores on stdout). The checker stops if a line cannot be parsed as a number.
- Reproduction instructions: `./run.sh --record` after inspecting `output/contact.png`, then `./run.sh`, which must print `dssim-still-compare: OK`.
- Amendment, before any run passed: the first `--record` attempt stopped in the checker because `dssim -o` writes per-scale files (`qQ.png-N.png`), not a single `qQ.png`. Scores from that attempt were correct (self 0.00000000; q90 0.00087072, q50 0.02181509, q10 0.05846345). Check 8 was changed to use scale 0 and to require all five scale files. No other predeclared check changed.
- Amendment 2, before any run passed: the first rerun failed only on the four input PNG file hashes. Cause: ImageMagick writes `date:create`, `date:modify` and `date:timestamp` tEXt chunks from wall-clock time when decoding the JPEG to PNG. Decoded pixels were identical (`magick compare -metric AE` gave 0). The decode now uses `-strip`, which makes the PNG bytes reproducible (verified across a 2 s gap, with no date chunks). The expected input hashes were re-recorded from this build. No scoring check changed.

## Observation, after running

Run on 2026-11-24 on `Conors-MacBook-Pro-2.local` (macOS 26.6, arm64) by a Claude agent in a VCR worktree. Versions: dssim 3.4.0 (Homebrew bottle `arm64_tahoe`, `/opt/homebrew/Cellar/dssim/3.4.0`, binary `/opt/homebrew/bin/dssim`); ImageMagick 7.1.2-35 Q16-HDRI (`magick -version`); Python 3.12.2 (generator and checker, standard library only). Playwright and Chromium do not apply. Node was not used by this fixture.

Installation: `brew install dssim` (approved). The catalogue record's `python3 -m pip install dssim` was not used; PyPI `dssim` 1.3.0 is a discrete-event simulation package (majvan, Apache-2.0), checked from PyPI metadata only and never installed.

Commands: `./run.sh --record` (recorded `expected/metrics.json`, all checks passed), then `./run.sh` printed `dssim-still-compare: OK`. Both write only under ignored `output/`.

Measured results, from `expected/metrics.json`:

- Self-score, `dssim base base`: `0.00000000` in both runs.
- Degraded scores, sequential and reversed order identical: q90 `0.00087072`, q50 `0.02181509`, q10 `0.05846345`. Strictly increasing and above zero.
- Difference maps (scale 0, 256×256): mean `0.0874834` (q90), `0.342268` (q50), `0.623992` (q10); maxima `1.0` in all three; mean increases with degradation. dssim also writes four smaller scale maps per run (`qQ.png-1..4.png`), which the checks require to exist but do not inspect.
- Repeat run: all score files and all 15 map files byte-identical to the first run; check passed.
- Input hashes (file SHA-256): base `6fafed73…`, q90 `df5134ec…`, q50 `ca6f5075…`, q10 `6378b467…`; four distinct.
- The JPEG files themselves are byte-identical across runs.

Contact sheet (`output/contact.png`, 1024×512): top row is the base and the q90, q50 and q10 decodes. The base is a gradient with a dark grid, three hard-edged circles with diagonal bands and a fine texture. The degraded versions show increasing blockiness and ringing, most visible in q10. Bottom row: a grey placeholder (self-comparison has no map), then the three scale-0 maps. Maps are dark for q90, with faint edge highlights on the circles and grid, and become bright and textured across most of the frame at q10. Nothing is blank or clipped, and the maps follow the damage visible in the top row.

Result: pass. Every predeclared check held on the second run.

What this establishes: on this machine, dssim 3.4.0 scores a generated 256×256 opaque RGB PNG against itself as exactly zero, scores the same image after ImageMagick JPEG q90, q50 and q10 round trips as strictly increasing positive values, writes a non-blank, degradation-growing difference map at each scale, and gives identical scores, identical maps and identical order-independent results across two runs.

What it does not establish: other dssim versions (the score scale changed between versions and is not comparable across them); tolerance thresholds for any use; alpha or 16-bit or greyscale input; real photographs or other content; other OSes; the library or C APIs; the AGPL versus commercial licence question for deployment; that the maps are perceptually correct beyond the visual inspection above; and anything about the other ImageMagick JPEG encoders or quality curves. ImageMagick is the degradation source only and is not credited.

Deviations, limitations and nondeterminism: three changes were made before any pass, all recorded above as amendments. (1) The check reads scale-0 of dssim's per-scale map output. (2) The decode of JPEG to PNG uses `-strip` because ImageMagick writes wall-clock `date:*` tEXt chunks, which made PNG bytes vary by run while the pixels did not. (3) The expected input hashes were re-recorded after (2). The catalogue install line was wrong and is corrected in `catalog/tools/dssim.json`. dssim's licence is AGPL-3.0 on GitHub; the Homebrew formula says AGPL-3.0-or-later; the commercial option is not checked here.

Reviewer, decision and follow-up: none yet. Revisit on any dssim upgrade (the score scale changes between versions), any change to the ImageMagick JPEG encoder or decoder, or if a tolerance threshold is adopted for a real VCR use.
