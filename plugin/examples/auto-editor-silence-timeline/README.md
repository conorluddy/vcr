# auto-editor silence cuts exported as timelines

## Intent and scope

- Tool/version: auto-editor 29.3.1 (PyPI, Unlicense), pinned in `requirements.txt`. The PyPI wheel is a launcher: on first run it downloads the native binary (`auto-editor-macos-arm64`, from the GitHub 29.3.1 release) into the venv. The lead named Homebrew 31.10.0; that build was not tested (no brew installs).
- Claim: on audio with a known silent span, `--edit audio:threshold=0.04 --margin 0sec` marks exactly that span silent, and the `v1`, `v3` and `premiere` timeline exports and a rendered cut all agree with it.
- Exclusions: motion edit, other exports (Resolve, Final Cut, Shotcut, Kdenlive, clip sequence), the 31.x series, real speech, thresholds other than 0.04, margins other than 0, import into opentimelineio, render quality.
- Docs and licence: https://github.com/WyattBlue/auto-editor; Unlicense per the lead, not rechecked against the installed package.
- Environment: macOS 26 arm64, Python 3.12.2 (pyenv), FFmpeg on PATH, venv in `output/venv` (git-ignored). Network needed once, at install and first launch.
- Input: generated by `run.sh`: 2 s 440 Hz sine, 3 s silence, 2 s 660 Hz sine, `testsrc` 320x240 at 30 fps, 7 s, so silence is frames 60 to 150.
- Install (venv local to the example): `python3 -m venv output/venv && output/venv/bin/pip install -r requirements.txt && output/venv/bin/auto-editor --version`. Cleanup: remove `output/`.

## Plan, before running

- Commands: `./run.sh --record`, then `./run.sh`. `check.py` runs twice in separate processes and the JSON must be identical.
- Checks (all gating): version 29.3.1; `v1` chunks are `[0,60,1.0]`, `[60,150,99999.0]`, `[150,210,1.0]`; `v3` video and audio clips are (start,dur,offset) (0,60,0) and (60,60,150); Premiere XML first video track has clipitems start/end/in/out `0,60,0,60` and `60,120,150,210`; FFmpeg `silencedetect` independently reports one silence at 2.0 and 5.0 s within 0.05 s; rendered cut has video and audio durations 4.0 s within 0.1 s.
- Stop conditions: version differs, or the two processes differ.
- Failure interpretation: any failed check is `fail`; no claim about real speech.

## Observation

Executed 2026-11-27 on `Conors-MacBook-Pro-2.local`. All 7 checks pass and the two processes agree. Findings: `-ex json` and `cmx-3600` are not export names in 29.3.1 (`v1`, `v3`, `premiere` work; the `-o` extension does not pick the format, and `.v3` is the name that `v3` accepts); the `premiere` XML embeds an absolute source path, so only its clip numbers are checked; the `v1` silent chunk has speed 99999.0, which means cut. This proves cut points on synthetic silence, not behaviour on speech or room noise.
