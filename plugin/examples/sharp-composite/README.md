# Sharp composite

Status: validated on macOS arm64, 2026-11-05 (sharp 0.35.5, libvips 8.18.7 as reported by `sharp.versions`, Node 22.19.0, ImageMagick 7.1.2-15 for the cross-check).

Composites two generated RGBA layers and a tiny committed SVG (`mark.svg`, rasterised by sharp) onto a half-transparent background, then checks the PNG keeps its alpha. No browser, no timeline: this is the native image path.

```text
./run.sh            # composite, diff against expected/summary.json
./run.sh --record   # rewrite expected/ after a deliberate change or upgrade
```

## Plan, before running

- Claim: sharp 0.35.5 composites generated RGBA layers and a rasterised SVG onto a background with transparent regions and returns a 4-channel PNG whose alpha is preserved and correctly blended.
- Exclusions: JPEG, WebP, AVIF and GIF output; ICC and colour management; large images and speed (the card's 4x to 5x claim is not tested); streams; other operating systems or architectures; SVG features beyond one filled circle; any use as a frame pipeline.
- Input: generated by `composite.ts`, plus `mark.svg` (a 100x100 viewBox with one green circle, written for this fixture, no external rights).
- Command: `./run.sh`, which runs `tsx composite.ts` (sharp 0.35.5, published 2026-09-27; Node 22.19.0).
- Layers on a 640x360 canvas: left half opaque navy (20, 30, 90), right half transparent; a 200x200 red overlay at alpha 0.5 placed at (220, 80), straddling the navy/transparent edge at x = 320; `mark.svg` rasterised at density 288 and resized to 128x128, placed at (480, 200).
- Predeclared checks, retained in `expected/summary.json`:
  - 640x360, 4 channels, `hasAlpha` true, format png.
  - Pixel probes (RGBA, non-premultiplied): (50, 50) navy opaque 20,30,90,255; (600, 20) fully transparent 0,0,0,0; (250, 100) red over navy about 138,15,45,255 (within 2 per channel); (380, 100) red over transparent 255,0,0,128; (544, 264) SVG circle centre 0,200,100,255; (485, 205) SVG bounding-box corner outside the circle, alpha 0.
  - Raw-pixel hash and PNG hash identical across two runs. If either differs, say so and drop that hash.
- Versions recorded: `sharp.versions.sharp` and `sharp.versions.vips` (libvips) in the summary.
- Stop condition: a probe outside tolerance, lost alpha (3 channels), or any difference between two runs of the same hash is a failure, never a value to record.
- Inspect: open `output/composite.png` on a checkerboard (or `magick output/composite.png -background '#888' -flatten`) at 1x.

## Observation, after running

- 2026-11-05, macOS arm64, Conors-MacBook-Pro-2.local. `sharp.versions`: sharp 0.35.5, libvips 8.18.7. `./run.sh --record`, then `./run.sh` twice: both printed OK.
- Output 640x360, 4 channels, `hasAlpha` true. Independent check: `magick identify -format "%[channels] %A"` reported `srgba` and `Blend`.
- Probes matched the plan. Red over navy came out 137,14,44,255 (plan: about 138,15,45, within the stated 2). Red over transparent 255,0,0,128; SVG centre 0,200,100,255; both transparent probes 0,0,0,0.
- The raw-pixel hash and the PNG hash were identical across the record run and both checks, so both are kept. They are tied to this sharp and libvips build: a different libvips or libpng can change the PNG bytes without changing a pixel, so after an upgrade compare the raw-pixel hash first.
- Inspected `output/composite.png` flattened on mid grey at 1x: navy left half, grey where transparent, red square translucent across the edge (darker over navy), green circle with a clean edge.
- This proves one composite-and-rasterise job on this machine. It does not prove other output formats, colour management, performance, other platforms, or SVG beyond a single filled circle.
