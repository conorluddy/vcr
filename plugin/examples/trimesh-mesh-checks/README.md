# trimesh mesh checks fixture

## Intent and scope

VCR job and exact claim: trimesh builds two analytic primitives (a box and an
icosphere), reports their watertightness, volume, surface area and bounds against
analytic values within predeclared tolerances, loads a GLB, applies a rigid-plus-scale
transform to the box, and re-exports it as GLB and STL. Each export reloads with the
same vertex and face counts as the in-memory mesh, and two independent runs of the
whole script produce byte-identical exports.

Tool: trimesh, Python package `trimesh`, pinned `5.2.2` (PyPI latest on 2026-11-24).
Catalogue record: `catalog/tools/trimesh.json` (candidate, `checked_at` 2026-11-24).

Explicit exclusions:
- No materials, textures, lighting or rendering. 3D is not a creative pillar; the
  materials and lighting paths of trimesh and any renderer are untested.
- No optional extras. Only `trimesh` and its required `numpy` are installed. Operations
  that need `scipy`, `networkx`, `rtree`, `shapely`, `manifold3d`, `pyglet`, `lxml`
  or other extras are not exercised; the checks here do not depend on them.
- Formats: GLB and binary STL only. No OBJ, PLY, 3MF, USD or DAE.
- No boolean operations, repair, decimation, subdivision of user meshes, ray queries
  or collision queries.
- The GLB input is generated by trimesh in the same run (no GLB asset is committed in
  this repository; the search of tracked files found none). So the GLB reader is tested
  on trimesh's own writer output, not on an independent GLB file.
- The icosphere is a polyhedron inscribed in the unit sphere. Its volume and area are
  compared with the sphere's analytic values within a tolerance; they are not equal.
- Determinism is observed on this machine only, with one Python and one numpy build.
- Surface, vertex and face counts are compared between the in-memory mesh and its reload;
  no claim is made about vertex order.

Input: none from outside the repository. The box and icosphere are constructed in

## Plan, before running

Install (after creating the venv as above):
```
examples/trimesh-mesh-checks/output/venv/bin/python -m pip install -r examples/trimesh-mesh-checks/requirements.txt
```

Commands:
```
examples/trimesh-mesh-checks/run.sh            # runs the script twice, diffs both against expected/
examples/trimesh-mesh-checks/run.sh --record   # only after a deliberate change
```

`mesh_checks.py OUTPUT_DIR` does, in order:
1. Box: `trimesh.creation.box(extents=(2, 4, 6))`, i.e. half-extents (1, 2, 3).
2. Icosphere: `trimesh.creation.icosphere(subdivisions=4, radius=1.0)`.
3. Icosphere exported to `OUTPUT_DIR/icosphere.glb`, reloaded with `trimesh.load(..., force='mesh')`.
4. Transform `M = compose_matrix(scale=2, angles=(0, 0, pi/2), translate=(1, 2, 3))`
   applied to a copy of the box.
5. Transformed box exported to `box-transformed.glb` and `box-transformed.stl`, each reloaded.
6. Writes `OUTPUT_DIR/checks.json` (measurements, every check, and the SHA-256 of each export).
   Exits 1 if any gating check is false.

Analytic values, derived before running:
- Box volume 2·4·6 = 48. Surface area 2(2·4 + 4·6 + 6·2) = 88. Bounds [-1,-2,-3] to [1,2,3].
- Transformed box: volume 8 · 48 = 384 (scale 2 cubed; rotation and translation preserve
  volume). Bounds, from scaling to half-extents (2, 4, 6), rotating 90° about z
  (x' = -y, y' = x) to (4, 2, 6), then translating by (1, 2, 3): min [-3, 0, -3],
  max [5, 4, 9].
- Icosphere (subdivisions n = 4): vertices 10·4^n + 2 = 2562, faces 20·4^n = 5120,
  Euler characteristic 2; every vertex on the unit sphere. Sphere volume 4π/3 and area 4π;
  the inscribed polyhedron is expected to be slightly smaller.

Predeclared checks (all gating; tolerances fixed before running):
- G1 box volume equals 48 within relative 1e-6.
- G2 box surface area equals 88 within relative 1e-6.
- G3 box bounds equal ±(1, 2, 3) within absolute 1e-9.
- G4 box is watertight, winding-consistent, Euler characteristic 2.
- G5 icosphere has 2562 vertices and 5120 faces, and max |‖v‖ − 1| ≤ 1e-9.
- G6 icosphere is watertight, winding-consistent, Euler characteristic 2.
- G7 icosphere volume relative error against 4π/3 ≤ 0.5%.
- G8 icosphere area relative error against 4π ≤ 0.5%.
- G9 GLB reload of the icosphere: vertex and face counts equal the in-memory mesh;
  volume relative difference ≤ 1e-6.
- G10 transformed box volume equals 384 within relative 1e-6; bounds equal
  [-3, 0, -3] to [5, 4, 9] within 1e-9; still watertight.
- G11 transformed GLB reload: vertex and face counts equal the in-memory transformed mesh;
  volume within relative 1e-6.
- G12 transformed STL reload: vertex and face counts equal the in-memory transformed mesh;
  volume within relative 1e-6.
- G13 rerun byte-identical: `run.sh` runs the script into `output/run-a` and `output/run-b`;
  the two `checks.json` files (which include the SHA-256 of every export) must be identical
  byte for byte, and `run-a/checks.json` must equal `expected/checks.json`.

Not applicable: shuffled-order check and frame-count, dimension and alpha checks. There are
no frames; the claim is mesh geometry, not pixels.

Expected failure modes and stop conditions:
- Import failure or a non-zero exit from the script: stop, keep the log, report `blocked` or `fail`.
- A gating check false: stop; the expected file is not rewritten to hide it. The result is
  `fail`, or `partial` if only the reload or determinism checks fail, with the failing check named.
- If `trimesh.load` of a GLB returns a scene with no mesh, that is a G9/G11 failure, not a skip.
- Non-identical reruns: a G13 failure, reported as such.

Inspection: `output/run-a/checks.json` lists every measured value. Because there are no
frames, the sanity inspection is the printed analytic-versus-measured table in
`output/run-a/checks.json`, plus a text summary of vertex, face and bounds counts per export
in `output/run-a/summary.txt`. No contact sheet is produced: the output is not an image.

## Observation, after running

Executed 2026-11-24 on Conors-MacBook-Pro-2.local (Darwin 25.6.0, arm64), from
`examples/trimesh-mesh-checks`. Versions: trimesh 5.2.2 (MIT), numpy 2.5.5, Python 3.12.2
(pyenv, in `output/venv`). `output/dependencies.txt` lists the freeze, which is only these
two packages. Playwright, Chromium and Blender are not used. Node 22.19.0 ran only the
catalogue commands, not the fixture.

Commands: `run.sh --record` then `run.sh`. The first `--record` run failed once inside the
script, before any expected file was written: `relative_error` returned a numpy float, so
a comparison produced a numpy bool that `json.dumps` could not serialise. The fix wraps the
value in `float()` and changes no tolerance or expected value. The second run after the
fix recorded `expected/checks.json`; the verify run printed `trimesh-mesh-checks: OK`.

Measured (from `output/run-a/checks.json`, identical to `output/run-b/checks.json` and the
recorded expected file):
- Box: 8 vertices, 12 faces, volume 48, area 88, bounds ±(1, 2, 3). Watertight, winding
  consistent, Euler 2. All exactly on the analytic values.
- Icosphere (subdivisions 4): 2562 vertices, 5120 faces, max | |v| − 1 | 0.0. Volume
  4.17974 against 4π/3 = 4.18879, relative error 0.216% (tolerance 0.5%). Area relative
  error 0.119% (tolerance 0.5%). Watertight, Euler 2.
- Icosphere GLB (`icosphere.glb`, 92880 bytes, written by trimesh and reloaded): 2562 vertices,
  5120 faces, volume agrees with the in-memory mesh to better than 1e-6.
- Transformed box (scale 2, rotate 90° about z, translate (1, 2, 3)): volume 384, bounds
  [-3, 0, -3] to [5, 4, 9], all as derived. Watertight.
- Transformed GLB reload and transformed STL reload: 8 vertices, 12 faces, volume 384, the
  same as in memory.
- Export SHA-256 (identical across both reruns): `icosphere.glb`
  32541d2080f1753adab240ccda94fdf204e82663aa33fd4f71e90fe28e085abc;
  `box-transformed.glb` 75a34e5487a228fac81afa0dc743d04c50b073622f9a0b1a858d7d5152ce4ef8;
  `box-transformed.stl` 5ac4c824939230bd00500f2da26c6ba9e5995397b047b40a8b360cbf388f12af.
  `output/rerun.diff` is empty.

All 15 gating checks passed. The inscribed-polyhedron deficit (0.216%) is an expected
property of the icosphere, not a defect; the 0.5% tolerance was fixed before the run.

Inspection: there is no image, so no contact sheet. The output was read as text in
`output/run-a/summary.txt` and `checks.json`: the vertex, face, volume and bounds lines are
the values listed above, and the transformed bounds are the hand-derived ones, not
re-derived from the output. Nothing was rendered, so the mesh surface was not seen.

Pass, on the predeclared checks: primitive volume, area, bounds, counts and watertightness;
GLB reload of a trimesh-written GLB; transform; GLB and STL re-export reload counts; rerun
byte-identical. The result does not establish materials, lighting or rendering; optional
extras (scipy, networkx, shapely, manifold3d and others); OBJ, PLY, 3MF or USD; boolean
or repair operations; loading of an independent GLB produced by another tool (none was
committed or generated outside trimesh); or byte identity across machines, Python builds
or numpy versions. The GLB determinism result is one machine.
