# audiowaveform peaks from a known sox envelope: JSON, DAT and PNG

Status: partial on macOS arm64, 2026-11-24. Ten of eleven predeclared checks pass; `dat_header` fails (the DAT header version is 1, the plan said 2) and is not edited to pass. No `expected/` is kept, so the evidence is Fixture-reported. See "Observation, after running". Checked 2026-11-24.

## Intent and scope

- Tool: `audiowaveform` 1.11.1 (Homebrew bottle `audiowaveform 1.11.1_1`, `/opt/homebrew/bin/audiowaveform`, already installed; `brew info` gives licence `GPL-3.0-only`). Tool documentation: https://github.com/bbc/audiowaveform (the repository README points to the current home at https://codeberg.org/chrisn/audiowaveform). Licence from `brew info`, checked 2026-11-24. The catalogue card says `GPL-3.0 (repository label; exact variant and dependencies require review)`.
- VCR job and claim: `audiowaveform` turns a WAV with a known amplitude envelope into waveform data (JSON and DAT) at a predeclared samples-per-pixel and bit depth, and renders a PNG of predeclared dimensions. The data's length and per-segment min/max peaks match the envelope within tolerance: silence is about 0, a -6 dBFS tone about 0.5 of full scale, a -20 dBFS tone about 0.1. Two reruns are byte-identical.
- Input envelope (3.0 s, 48 kHz, mono, 16-bit): 1.0 s silence, 1.0 s 1 kHz sine at -6 dBFS (amplitude 10^(-6/20) = 0.501187), 1.0 s 1 kHz sine at -20 dBFS (amplitude 0.1). Each segment is generated by a separate sox `synth` call and concatenated.
- Predeclared parameters: 480 samples per pixel (100 pixels per second at 48 kHz, so 300 pixels for 3 s and each segment is exactly 100 pixels), 16-bit, PNG 300 by 200 pixels, transparent background (`--background-color 00000000`), no axis labels. A 1 kHz sine has a period of 48 samples, so each 480-sample pixel holds exactly 10 cycles and its peak equals the segment amplitude.
- Exclusions: no claim about 8-bit output (not run); no multi-channel output (`--split-channels` not run); no other input formats (mp3, ogg, flac, opus, raw, DAT or JSON input); no other zoom levels; no waveform style other than `normal`; no visual or perceptual claim beyond the inspection described below; no claim about the audiowaveform build on other hosts or platforms, nor on other versions; no claim about waveform data from real music or noise; no claim about sox beyond generating the input, and no claim about any tool-to-tool edge.
- Mapping of the template's frame checks: "frame count" is the JSON `length` (pixels); "dimensions" is the PNG width and height; "at least two distinct hashes" is the set of output hashes; "shuffled order equals sequential" does not apply (there is no seeked frame sequence, the tool is a one-shot file conversion). The rerun byte-identity check stands in for determinism.
- Alpha range: the template's alpha check is applied to the single PNG: with a transparent background the alpha channel must span from 0 to 255 (background transparent, waveform opaque).
- Environment: macOS 26.6 arm64 (Darwin 25.6.0), Homebrew audiowaveform 1.11.1, no GPU, CPU only, no network use by `run.sh`.
- Input: none committed. `run.sh` generates the envelope procedurally with sox `synth` (deterministic sine waves, no random or unseeded source). sox writes the 16-bit output with `-D` (dither disabled), so the envelope bytes are reproducible.
- Dependencies and installation: `audiowaveform` (already installed), `sox` (already installed, Homebrew `sox 14.4.2_6`), `magick` (ImageMagick 7, for the alpha range and contact sheet), `jq` and `shasum` and `sips` (macOS built-in). No install is performed by this example and no npm package is used.
- Catalogue tools used by the fixture: `audiowaveform` (the tool under test), `sox` (input generation), `imagemagick` (alpha range check and contact sheet).
- Workspace and cleanup: writes only `output/` (git-ignored). Remove with `rm -rf examples/audiowaveform-peaks/output`.
- Sound design and data visualisation pillars: `SOUND-` (sound-design) and `DATA-` (data-visualisation) are the pillars this waveform fixture would serve; no rule in them is tested here, and no threshold here is VCR policy.

## Plan, before running

- Versions: audiowaveform 1.11.1 (`audiowaveform --version`), sox 14.4.2 (`sox --version` and `soxi`), ImageMagick 7 (`magick -version`), jq (any), shasum and sips (macOS).
- Input (`run.sh`), sox, 48000 Hz, mono, 32-bit intermediate, then written as 16-bit with `-D`:
  1. `synth 1 sine 1000 vol 0` (silence, 1.0 s)
  2. `synth 1 sine 1000 vol 0.501187` (-6 dBFS, 1.0 s)
  3. `synth 1 sine 1000 vol 0.1` (-20 dBFS, 1.0 s)
  Concatenated to `output/envelope.wav` (3.0 s, 144000 samples).
- Command (`run.sh`), primary run:
  `audiowaveform -q -i output/envelope.wav -o output/envelope.json -z 480 -b 16 --output-format json`
  `audiowaveform -q -i output/envelope.wav -o output/envelope.dat -z 480 -b 16 --output-format dat`
  `audiowaveform -q -i output/envelope.wav -o output/envelope.png -z 480 -b 16 -w 300 -h 200 --no-axis-labels --background-color 00000000 --output-format png`
- Rerun: the same three commands write to `output/rerun/`. The rerun must match the primary run byte for byte.
- Predeclared checks (any failure exits 1 and writes `output/summary.json`; the `expected/summary.json` diff is the final gate):
  1. Length and header: JSON `length` is 300, `samples_per_pixel` 480, `sample_rate` 48000, `bits` 16, `channels` 1, and the `data` array has 600 values (min and max per pixel).
  2. Silence: pixels 0 to 99 have every min and max within 0.001 of 0 after dividing by 32768.
  3. -6 dBFS: pixels 100 to 199 have every max within 0.01 of 0.501187 and every min within 0.01 of -0.501187 (after dividing by 32768).
  4. -20 dBFS: pixels 200 to 299 have every max within 0.01 of 0.1 and every min within 0.01 of -0.1.
  5. DAT: the first 20-byte header reads version 2, flags 0 (16-bit), sample rate 48000, samples per pixel 480, length 300; the file is 1220 bytes; its 600 int16 values equal the JSON `data` values exactly.
  6. PNG: 300 by 200 pixels, format png (`sips`); alpha channel minimum 0 and maximum 255 (`magick`, transparent background with opaque waveform).
  7. Reruns byte-identical: JSON, DAT and PNG from `output/rerun/` are `cmp`-equal to the primary run.
  8. Distinct hashes: SHA-256 of the input WAV, JSON, DAT and PNG: at least two distinct values (all four are expected to differ).
  9. `expected/summary.json` matches `output/summary.json` exactly (measured peaks rounded to 4 dp, hashes, and the check results).
- Visual inspection after the run: `output/contact.png` is the PNG scaled 2x on a grey background, read with `Read`. It must show three blocks: a flat line for silence, a larger block for -6 dBFS, and a smaller block for -20 dBFS, in the predeclared 300 by 200 frame on a transparent background.
- Stop conditions: `audiowaveform`, `sox`, or `magick` missing: report blocked and do not substitute another tool. Any predeclared check failing: report fail or partial with the failing check named. Do not move a tolerance or a bound to make a check pass. If the JSON or DAT field names or value scaling differ from the description above, the check fails and is reported; the plan is not edited to fit.
- Reproduce: `examples/audiowaveform-peaks/run.sh --record`, then `examples/audiowaveform-peaks/run.sh` (expect `audiowaveform-peaks: OK`). Inspect `output/summary.json` and `output/contact.png`.
