# PlayCanvas engine capture

## Intent and scope
PlayCanvas Engine 2.24.0 (`pc.Application`, WebGL2 device forced by the Application constructor, which cannot create WebGPU) on a transparent canvas: a camera with `clearColor` (0,0,0,0), one directional light and three primitive render entities (box, sphere, cylinder) whose local transforms are set purely from t. Alpha PNG capture via the `packages/capture` Playwright route. Excludes WebGPU, app.start() tick timing, scripts, physics, materials with textures, particles, Gaussian splats, glTF, shadows, post-processing, interaction, other browsers and GPUs. Procedural original shapes; no media or fonts.
Licence: MIT (`LICENSE` in playcanvas 2.24.0, copyright PlayCanvas Ltd), checked 2026-11-11 from the installed package. Docs: https://playcanvas.com/products/engine. No codec, model or asset dependency.
Nondeterminism audit of `build/playcanvas.min.js` (grep, 2026-11-11): `Math.random` occurs in GUID creation (`guid.create`, used for entity ids), particle emitters, the sprite/splat helper `circlePoint` and the splat/particle random uniforms. `performance.now` occurs in splat sorting and profiling timers; `Date.now` occurs in input click timing, asset retry and zip writing. None of these are on the primitive render path used here, and this fixture uses no particle, splat, sprite or input feature. Entity ids (from GUID creation) are not expected to affect pixels; cross-run hash stability is checked in the observation below rather than assumed.

## Plan, before running
Install pinned `playcanvas@2.24.0` in this example only (pnpm workspace, approved rollout); reuse Playwright 1.64.1 and tsx 4.23.15 from the template. Run `pnpm install`, then `examples/playcanvas-capture/run.sh --record`, visually inspect frame 45 at 1280×720 and the contact sheet, then `examples/playcanvas-capture/run.sh`.

Frame driving: no `app.start()`, so the engine's requestAnimationFrame tick loop never runs and no engine timing is involved. Each `seek(t)` schedules one animation frame (as the template does), inside which the scene sets all transforms from t, calls `app.update(0)` (dt fixed at 0, no scripts) and then `app.render()` exactly once. `preserveDrawingBuffer: true` keeps the drawing buffer readable for the screenshot.

Predeclared checks: 90 frames at 30 fps, 1280×720, at least two distinct frame hashes, every shuffled hash equal to its sequential hash, frame 45 alpha minimum 0 and maximum 1. Stop on missing dependencies, a missing UMD build, blank output or any mismatch. Intended consumer is the existing browser capture harness; units are seconds and pixels. Transparent PNG sequence only; no delivery byte budget or compression claim. Outputs and reports in ignored output/; delete that directory to clean up. No cross-machine byte equality asserted.

## Observation, after running
2026-11-11, evidence agent on Conors-MacBook-Pro-2.local (`hostname`), macOS Darwin 25.6.0 arm64, Node 22.19.0, playcanvas 2.24.0 (engine revision 0d07e10, UMD `build/playcanvas.min.js`), Playwright 1.64.1, Chromium 156.0.8078.4 (launched by Playwright for the capture and separately), tsx 4.23.15, ImageMagick 7.1.2-15. Screenshot capture route (`captureMode` screenshot), WebGL2 context.

Commands: `run.sh --record` exited 0 (recorded `expected/summary.json`); `run.sh` printed `playcanvas-capture: OK`; a third run also passed. Results: 90 frames, 1280×720, 90 distinct hashes, shuffled order matches sequential in every run, frame 45 alpha min 0 max 1. Frame hashes were identical across the second and third runs (all 90 frames), so output is reproducible on this machine. Probe of the scene page: `getContext('webgl2')` returned a context with `alpha: true`, `preserveDrawingBuffer: true`, `antialias: false`, and a `webgpu` context was not available on the canvas, so the WebGL2 path was used.

Visual inspection: the contact sheet (`output/contact.png`, six frames at 0, 15, 30, 45, 60, 75) shows the green box rotating and bobbing on the left, the orange sphere orbiting in front of and behind the box, and the blue cylinder tilting and pulsing on the right, lit from one side with shaded faces. Nothing is blank or clipped at 1280×720. The grey backdrop in the sheet is the montage flatten colour, not the frames, which are transparent outside the shapes. The contact sheet needs `+repage` after each `+append`, because `-flatten` otherwise crops to the first tile's page geometry; the instructed command produced a 640×360 image without it. Agent visual review only; no human approval claimed.

Result: pass for the stated claim: PlayCanvas primitives rendered from t on a transparent WebGL2 canvas, 90 alpha PNG frames, deterministic in this run set. Not established: WebGPU, the engine's own tick loop or `app.start()`, scripts, physics, splats, glTF, textures, other browsers or GPUs, other OS, or delivery quality. Revalidate on engine, Playwright or Chromium changes.
