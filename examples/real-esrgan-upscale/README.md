# Real-ESRGAN upscaling fixture

## Intent and scope

VCR job and exact claim: `realesrgan-ncnn-vulkan` with the fixed model
`realesrgan-x4plus`, `-s 4`, upscales a 4x box-downscaled synthetic image to exactly
4x its own dimensions, and its output is closer to the original high-resolution image
than plain bicubic upscaling of the same input, by a predeclared margin, measured with
PSNR and SSIM. Determinism across two reruns is recorded either way.

Tool: Real-ESRGAN, the ncnn-Vulkan executable `realesrgan-ncnn-vulkan`, from the
official release asset `realesrgan-ncnn-vulkan-20220424-macos.zip` (Real-ESRGAN GitHub
release v0.2.5.0). The release binary is a universal (x86_64 + arm64) Mach-O with
MoltenVK statically linked; it needs no Python or PyTorch.

Explicit exclusions:
- One model only: `realesrgan-x4plus`. Not tested: `realesr-animevideov3`,
  `realesrgan-x4plus-anime`, the `realesr-general-*` models, the PyTorch route, `-s 2`
  and `-s 3`, and `-x` (TTA).
- One synthetic still (640x480, generated from primitives and a system font). No
  photographs, no compression artefacts, no scanned material, no video or sequences.
- "Better" is measured only against the original high-resolution image of this scene,
  using PSNR and SSIM. Perceptual quality, hallucinated texture and preference are not
  measured. The margins are fixture parameters, not a quality bar.
- Tile size and GPU are left at the tool defaults. Tiling seams are judged only from the
  1:1 crops in the contact sheet.
- Determinism is observed on this machine only (Apple M3, Metal via MoltenVK). No
  cross-GPU, cross-driver or cross-machine byte identity claim.
- Metrics are ImageMagick `compare` (PSNR, SSIM). dssim is not used.
- No claim about the Python `realesrgan` package or the PyTorch weights; the ncnn build
  is a converted model and may differ from the PyTorch output.

MoltenVK (statically linked in the binary; no system Vulkan SDK). ImageMagick
7.1.2-35 Q16-HDRI from Homebrew. No CUDA.

randomness. Construction recipe below. No third-party image asset; no rights question.

Construction recipe (synthetic original, 640 x 480 RGB):
1. Vertical gradient background `#16213e` to `#e9c46a`.
2. Hard-edged white circle (centre 160,240; radius 120) and a dark rectangle
   (400,300 to 600,440).
3. Fine 1 px vertical stripes every 4 px across x = 280 to 360 (high-frequency edges).
4. Text "VCR 4x" in Arial Bold, 64 pt, white, at +330+150.
5. Written as 8-bit PNG with `-strip` (no file dates, so bytes are reproducible).

Downscale (the known kernel): `magick original.png -filter Box -resize 25% input.png`,
a 4x4 box (area) mean of the original, 160 x 120 RGB.

Baseline: `magick input.png -filter Catrom -resize 400% bicubic.png` (Catmull-Rom, a
bicubic kernel), 640 x 480.

Real-ESRGAN: `realesrgan-ncnn-vulkan -i input.png -o realesrgan.png -n realesrgan-x4plus -s 4 -m output/bin/release/models`
(tile size and GPU at defaults). The same command is repeated in a fresh process into
`realesrgan-rerun.png`.

## Plan, before running

Commands (after the install above):
```
examples/real-esrgan-upscale/run.sh            # build the original and input, upscale twice, measure, diff expected/
examples/real-esrgan-upscale/run.sh --record   # only after a deliberate change
```

Predeclared checks (all measured by `run.sh`; the thresholds are fixture parameters):
1. Input is 160 x 120 (original 640 x 480 divided by 4 exactly).
2. Real-ESRGAN output is exactly 4 x input: 640 x 480.
3. Bicubic output is 640 x 480 (baseline sanity check).
4. PSNR margin: PSNR(realesrgan, original) >= PSNR(bicubic, original) + 1.0 dB.
5. SSIM margin: SSIM(realesrgan, original) >= SSIM(bicubic, original) + 0.010.
6. Distinct hashes: original, input, bicubic and realesrgan sha256 values are pairwise
   different (the output is not a copy of any other image).
7. Determinism (recorded, not gating): the rerun in a fresh process is byte-identical
   (sha256 equal). Either outcome is recorded; a non-identical rerun is recorded with its
   maximum per-channel difference.
8. Frame count: one still per run. Shuffled-order check and alpha range: not applicable
   (no seek, opaque RGB output).

Result rules (predeclared):
- pass: checks 1 to 6 all true.
- partial: checks 1 to 3 and 6 true, and exactly one of checks 4 and 5 true.
- fail: checks 1 to 3 or 6 false, or both checks 4 and 5 false (no margin over bicubic).
- blocked: binary, model or font missing, a model hash mismatch, or a non-zero exit.

Expected failure modes and stop conditions:
- Hash mismatch, missing font, or a non-zero exit from the binary: stop, keep the log in
  `output/`, report blocked. No substitution of another model or route.
- Vulkan or device not found by the binary: blocked, with the log. Do not switch to the
  PyTorch route inside this fixture.
- Output dimensions not exactly 4x: fail (check 2), not a rescale to fit.
- A margin failure is a result, not an error: `run.sh` still writes it to
  `output/checks.json`; only `--record` writes the baseline.

Inspection: `output/contact.png` (original, input, bicubic, Real-ESRGAN, and 1:1 crops of
the text and stripes) is made with `magick` after the run. It is inspection only; the
verdict follows the predeclared checks and what the crops show.

Reproduction: `run.sh` writes `output/checks.json`; inspect it and the PNGs in `output/`.

## Observation, after running

Executed 2026-11-24 on Conors-MacBook-Pro-2.local (macOS 26.6, Darwin 25.6.0, arm64),
from `examples/real-esrgan-upscale`.

Versions (as run):
- Real-ESRGAN: `realesrgan-ncnn-vulkan` from `realesrgan-ncnn-vulkan-20220424-macos.zip`
  (Real-ESRGAN release v0.2.5.0). The binary has no version flag; the release asset date
  20220424 is the version. Binary sha256 `c1c35d92079085de96b9d547fd7e4464bc8a2e9ccf28d7b8c712d72ade91b7cc`
  (universal, x86_64 and arm64; arm64 slice used). Model `models/realesrgan-x4plus.bin`
  sha256 `713ee713b0353afaa27976f0563a64a5043bd70b9bd8936c2e26e25ebcdbcddf` (33,424,520
  bytes); `models/realesrgan-x4plus.param` sha256
  `35330ececcea33b6c397a72548e788d5d53becee4734c50b7fada36e89f10a86`.
- Vulkan device reported by the binary: `Apple M3 Pro` (via MoltenVK, statically linked).
- ImageMagick: 7.1.2-35 Q16-HDRI aarch64 (`output/versions.txt`).
- Playwright and Chromium: not used. Node v22.19.0 is present; not used by this fixture.
- Python: not used. No venv, no PyTorch.

Commands: `./run.sh --record`, `./run.sh --record` (second record, after the SSIM fix
below), then `./run.sh`, which printed `real-esrgan-upscale: OK`. Each run executes the
upscale twice, in separate processes.

Measured (`expected/checks.json`):
- Original 640x480 (sha256 `31198073...9206`); input 160x120 (`7b4ce73b...4478`).
- Bicubic (Catmull-Rom, 400%): 640x480. PSNR 20.2670 dB; SSIM 0.9210.
- Real-ESRGAN x4plus (`-s 4`): 640x480 (exactly 4x the input). PSNR 20.4595 dB; SSIM 0.9258.
  Output sha256 `0431c54c054002fc07615f413b61d234cc89841746451b9c9176ec9220756567`.
- Margins: PSNR gain +0.19 dB, need >= +1.0 dB: not met. SSIM gain +0.0048, need >= +0.010:
  not met.
- Rerun in a fresh process: byte-identical (same sha256, 0 differing pixels). The same
  output hash also appeared in every other invocation (two record runs, the verify run).
- Checks 1, 2, 3, 6 and 7: true. Checks 4 and 5: false. Claim result: `fail` (both
  margins missed, per the predeclared rules).

Inspection: `output/contact.png` (1920 x 720). Row 1: original, bicubic and Real-ESRGAN at
640 x 480. Row 2: 1:1 crop of the text "VCR 4x". Row 3: 1:1 crop of the 1 px stripes
and the disc edge. What I see: the text is recovered in both upscales; Real-ESRGAN's
letter edges are crisper, with a faint lighter halo along the white disc and the dark
rectangle. The 1 px stripes are not recovered by either method: the box downscale has
averaged them into a flat band, and both upscales show a soft band, not stripes. The
frame is not blank or clipped and the library's work is visible, but the gain over bicubic
is small on these edges, below the predeclared margins.

Deviations, recorded rather than silently edited above:
1. Bundled models. The brief expected the ncnn-Vulkan wrapper v0.2.0 macOS zip to bundle
   models. It does not (no `models/`, binary only, 8.5 MB). The macOS asset from the
   Real-ESRGAN v0.2.5.0 release (`realesrgan-ncnn-vulkan-20220424-macos.zip`, 51.8 MB)
   bundles models and was used. The v0.2.0 zip was downloaded and deleted, unused.
2. Execute bit. Unzipping dropped the execute bit; the first `run.sh` stopped with
   `blocked` before any run. Fixed with `chmod u+x` on the one binary; no quarantine change.
3. SSIM parsing (a bug in my measurement, found on inspection). `magick compare -metric
   SSIM` prints `distortion (normalised)`, for example `5175.4 (0.0789715)`, where identical
   images print `0 (0)`. The first `--record` read the quantum-scaled first field as SSIM
   (values near 5000), which would have made the 0.010 margin meaningless. The parser now
   takes SSIM = 1 minus the normalised distortion. The margins were not changed. The
   first record was overwritten; the PSNR, sizes and hashes in it were identical to the
   corrected run. The corrected SSIM values were used for the result.

Licence, as checked 2026-11-24: Real-ESRGAN repository BSD-3-Clause (GitHub licence
metadata). The wrapper's `LICENSE` in the v0.2.0 zip is MIT (Copyright (c) 2021 Xintao
Wang); the v0.2.5.0 asset zip has no licence file. Model weights: no separate weight
licence in the release; their terms are NOT verified, so the model files are not redistributed.

What this result does and does not establish: on one generated 640x480 still, the
ncnn `realesrgan-x4plus` route at `-s 4` produces an exact 4x output on macOS arm64 with
Vulkan via MoltenVK, and reruns in fresh processes are byte-identical on this machine. It
does not establish that Real-ESRGAN beats bicubic by the predeclared margins on this
content: it beats bicubic by 0.19 dB and 0.0048 SSIM, which fails the predeclared rule.
Not established: photographs or compression artefacts, other models, `-s 2` or `-s 3`,
TTA, the PyTorch route, GPUs or drivers other than this machine, or cross-machine bytes.
The margins are fixture parameters; a different margin would be a new claim, not this one.
