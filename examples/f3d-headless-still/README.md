# f3d headless still fixture

## Intent and scope

- Tool ID and version/build: `f3d` 4.0.1 (Homebrew, `/opt/homebrew/bin/f3d`; `f3d --version` prints `F3D 4.0.1`, build date 2026-10-31, VTK 9.7.1, Module ImGui ON, FFmpeg/OpenEXR/WebP/Raytracing OFF).
- VCR job and exact claim being tested: f3d renders a small glTF/GLB asset to a PNG still offscreen (`--output`, fixed `--resolution`, fixed camera options, no window) with predeclared dimensions, a non-background object covering a predeclared region, and transparent background; reruns are byte-identical.
- Explicit exclusions: formats other than GLB (USD, STEP, OBJ, PLY, Gaussian splats); textures, animation, morphs, skinning and extensions; materials and lighting fidelity; `--hdri-*`, ambient occlusion, colormaps and scalar coloring; video output; other rendering backends. Only the `cocoa` backend is available on this macOS host (`f3d --list-rendering-backends`: egl, glx, osmesa and wgl unavailable), so a true headless or EGL/OSMesa path is not tested.
- "No window" is not assumed. f3d's `--output` path on this host runs through the windowed cocoa backend. The windowless part of the claim is tested by a separate observation (see the plan) and is not established unless that observation shows zero f3d windows.
- Tool documentation and licence sources, checked 2026-11-24: <https://f3d.app> and <https://github.com/f3d-app/f3d>; the licence is BSD-3-Clause as recorded on the catalogue card and printed by `f3d --version`. Input geometry is generated locally, so no asset licence applies. The fixture uses ImageMagick only for an inspection contact sheet, not in `run.sh`.
- Environment: macOS 26.6 arm64, f3d 4.0.1 on the cocoa backend, Python 3 standard library only (`zlib`, `struct`, `hashlib`, `json`). Exact host details are in the Observation section.
- Input: generated by `make-input.py`: a unit cube of half-size 0.5 centred at the origin, one orange `pbrMetallicRoughness` material (`baseColorFactor` 0.9, 0.35, 0.1, 1.0), no textures and no external buffers. Geometry is 24 vertices with normals and 36 `uint16` indices. The file is written by this repository's script, so it has no third-party rights. Its SHA-256 is printed in the Observation section.
- Dependencies, installation plan, permissions, network and expected side effects: f3d is already installed through Homebrew and is not installed or upgraded by this fixture. No package is added to any `package.json`. No network access is needed. Side effects are limited to `output/`, which is git-ignored. The `--no-config` and `--no-cache` flags keep user configuration and f3d caches out of the run.
- Selected workspace, generated output and cleanup paths: this example directory; generated GLB, PNG stills, logs and metrics go under `output/`. `expected/metrics.json` is the only committed result file. No media is committed.

## Plan, before running

- Exact commands: `python3 make-input.py output/cube.glb`, then `f3d --version | head -n 1`, then three renders with the same fixed options:
  - `f3d output/cube.glb --no-config --no-cache --rendering-backend auto --output <png> --resolution 320,240 --no-background --coloring-mode=material --camera-position <pos> --camera-focal-point 0,0,0 --camera-view-up 0,1,0 --camera-view-angle 30 --verbose=info`
  - view A (`output/view-a.png`) at `2,1.5,2.5`; view B (`output/view-b.png`) at `0,0,3`; view A again after B (`output/view-a-after-b.png`) at `2,1.5,2.5`.
- Expected artifacts and predeclared checks (all asserted by `check-output.py`, with no pixel tolerance):
  1. `f3d --version` first line is exactly `F3D 4.0.1`.
  2. Each still is 320x240, 8-bit RGBA (colour type 6).
  3. Corner check: all four 8x8 corner blocks have alpha 0 in every view.
  4. Transparency: at least 50% of pixels have alpha 0 in every view.
  5. Object region: the alpha>0 bounding box lies within x 40..280 and y 30..210, and is at least 80 px wide and 80 px tall in every view.
  6. Opaque object pixels: at least 4000 with alpha 255 in every view.
  7. Centre pixel: alpha 255 and R > G > B (orange) in every view.
  8. Distinct hashes: views A and B have different SHA-256 (at least two distinct hashes).
  9. Order independence: view A rendered after view B has the same SHA-256 as the first view A render (byte-identical, shuffled equals sequential).
  10. Middle frame alpha range (view A): minimum 0 and maximum 255, with 100 to 10000 partially transparent pixels.
  11. Reruns: `run.sh` without `--record` must reproduce `expected/metrics.json` exactly; the SHA-256 values are the byte-identity check.
  12. Windowless observation (not in `run.sh`): while a view A render runs, `osascript -e 'tell application "System Events" to count windows of (first process whose name is "f3d")'` must return 0. If System Events cannot be queried, the windowless part is recorded as not established. Report `partial` if it fails.
- Intended consumer and handoff settings: a still PNG for review or contact-sheet inspection. Not a handoff to a video encoder, and not a Blender or Three.js consumer.
- Delivery constraints and units: 320x240 pixels; no byte budget; one fixture GLB of under 1 KB.
- Expected failure modes and stop conditions: f3d version other than 4.0.1; non-zero f3d exit; output not RGBA8 or not 320x240; corners opaque; object outside the region; view A equal to view B (camera ignored); rerun or order hash mismatch. A failed check stops the run with the assertion message.
- Reproduction instructions: `./run.sh --record` records `expected/metrics.json` after the first clean run; `./run.sh` must print `f3d-headless-still: OK`. To inspect the stills: `open output/view-a.png`, or the contact sheet command in the Observation section.

- Inspection of the contact sheet (`output/contact.png`, frames view A, view B, view A after B, left to right): three clean renders of one opaque orange cube on a transparent background (the grey is the contact sheet's backdrop). View A shows three shaded faces in oblique view with a crisp silhouette and no clipping or stray pixels; the bottom corner sits about 12 px above the frame edge. View B is a flat orange square with uniform shading, consistent with a front-on camera. View A after B is identical to view A. Nothing is blank, clipped or background-coloured.
- Pass / partial / fail / blocked: **partial**. The render, dimensions, RGBA output, transparent background, distinct camera results and byte-identical reruns hold. Two predeclared checks fail: the view A object region (the object is fully in frame, but its bottom edge is 17 px past my predeclared limit of y=210), and the partial-alpha count (f3d 4.0.1 on cocoa writes hard edges, so my predicted antialiased fringe of 100 to 10000 pixels did not occur). The windowless part of the claim is not established. The limits were predeclared and are not edited, so `run.sh` still fails; no `expected/` is committed and `example.json` stays `not-validated`.
- Deviations, limitations, nondeterminism and side effects: `--rendering-backend auto` (the help text lists `auto|glx|wgl|egl|osmesa`, so `cocoa` was not passed explicitly) resolved to cocoa. Only one backend is available, so no headless EGL/OSMesa path was tested. The renders ran on the cocoa window backend and the windowless part is open. Reruns were byte-identical on this host only; cross-host or cross-version hashes are not claimed. Output files, logs and the window probe scripts are under the git-ignored `output/`.
- What this result does and does not establish: f3d 4.0.1 renders a generated GLB cube to a 320x240 RGBA8 PNG with `--output`, fixed resolution and camera options, a transparent background, distinct outputs for distinct cameras, and byte-identical reruns in one order and in an A-B-A order on macOS arm64 with cocoa. It does not establish that f3d renders without a window, the predeclared object region in view A, antialiased edges, other formats, lighting fidelity or other hosts.
- Reviewer, decision, follow-up and invalidation triggers: the decision here is the reviewer's to make. Follow-up options: (a) predeclare a corrected region and edge check in a new run rather than editing these limits; (b) a windowless check with Accessibility permission for the terminal, or an EGL/OSMesa build; (c) a second cocoa host. Revisit on any f3d upgrade or Homebrew rebuild, and on any change to `--rendering-backend` availability.
