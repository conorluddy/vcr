# aubio onsets, beat and pitch on generated audio

## Intent and scope

- Tool ID and version/build: `aubio`, Homebrew bottle `0.4.9_4` (formula `aubio` 0.4.9, revision 4). CLIs `aubioonset`, `aubiotrack`, `aubiopitch`. The CLIs have no version flag; the bottle revision is the version identifier.
- VCR job and exact claim being tested: "aubioonset detects the click onsets within a predeclared tolerance (ms) of their true times with no more than a predeclared number of misses/extras; aubiotrack's beat estimate matches the BPM within a tolerance; aubiopitch reports each tone's frequency within a predeclared cents tolerance; reruns identical."
- Explicit exclusions:
  - Only synthetic input: a 120 BPM click track and five pure sine tones. No recorded or musical audio, no swing, tempo drift, vibrato, polyphony or noise.
  - Onset detection uses aubio's default algorithm (`hfc`) and default thresholds. Other `-O` methods, `-t` values and `-M` values are not tested.
  - Beat phase (whether beats land on the clicks) is printed but not checked; only the BPM is in the claim.
  - Pitch uses the default `yinfft` method with `-u freq`. Only five frequencies in 220 to 523 Hz are tested. No latency, sample rate other than 44.1 kHz, or Python binding.
  - No tool-to-tool edges: no FFmpeg encode, no librosa comparison, no mux.
  - Sound-design and pacing quality are not judged. Pillars cited for context only: `SOUND-BEAT-ALIGN` (beats to frames) and `PACE-BEAT-06` (cuts on markers). Neither rule is checked here.
- Tool documentation and licence sources, checked 2026-11-24: `https://aubio.org/` and `https://github.com/aubio/aubio`. Licence GPL-3.0-or-later per the tool card and `brew info aubio`. No aubio code or media is committed or redistributed. Inputs are generated by FFmpeg's `aevalsrc` filter, so there are no third-party assets.
- Environment: macOS 25.6 (Darwin), arm64 (Apple M3), Homebrew at `/opt/homebrew`, CPU only, no GPU. FFmpeg 9.0.2 from Homebrew.
- Input: generated in `run.sh` from constants written in the script. Origin: this repository. Rights: none needed. Hashes are recorded per run in `output/run-*/` (ignored), and the rerun check compares them.
- Dependencies, installation plan, permissions, network and expected side effects:
  - Installed for this backfill, as approved: `brew install aubio`. Bottle `0.4.9_4`, plus libsndfile and numpy. Brew also upgraded numpy 2.5.4 to 2.5.5 as an aubio dependency, a machine-wide side effect.
  - No npm packages, no Node dependencies, no new repo dependencies. `run.sh` needs only `ffmpeg`, `ffprobe`, `aubio` CLIs, `jq`, `awk`, `sort`, `shasum` and `cmp`.
  - No network access during the run.
- Selected workspace, generated output and cleanup paths: `examples/aubio-onsets-pitch/output/` (ignored by `.gitignore`), which `run.sh` clears on each run. `expected/summary.json` is the only retained file.

## Plan, before running

- Exact commands and versions:
  - `ffmpeg -f lavfi -i "aevalsrc='<click expr>':s=44100:d=10" -ac 1 -c:a pcm_s16le output/run-X/click.wav`
  - `ffmpeg -f lavfi -i "aevalsrc='<tone expr>':s=44100:d=4.5" -ac 1 -c:a pcm_s16le output/run-X/tones.wav`
  - `aubioonset -i click.wav`, `aubiotrack -i click.wav`, `aubiopitch -i tones.wav`, each with default options. Output is text on stdout, one line per event.
  - The whole pipeline runs twice (`run-a`, `run-b`) from generation onward.
  - Click expression: a 0.8 amplitude 1 kHz sine burst at each click, `exp(-60 tau)` decay, gated to the first 0.05 s after each click. Clicks at 120 BPM (period 0.5 s), first at 0.25 s, 20 clicks in 10 s.
  - Tone expression: five 0.6 s sine tones at 0.5 amplitude, one per 0.9 s slot, separated by 0.3 s silence. Frequencies 220, 261.63, 329.63, 440 and 523.25 Hz. Total 4.5 s.
- Expected artifacts and predeclared checks:
  1. Inputs: `ffprobe` reports 44100 Hz, 1 channel for both files. Click duration is 10.000 s and tone duration 4.500 s, each within ±0.01 s.
  2. Onsets: 20 true onsets at `0.25 + 0.5k` s, k = 0..19. Each detection must lie within ±25 ms of a true onset, one detection per onset. Misses ≤ 0 and extras ≤ 0.
  3. Beat tempo: 60 / median inter-beat interval from `aubiotrack` is within ±2.0 BPM of 120. At least 10 beats are reported.
  4. Pitch: for each tone, the median of `aubiopitch` values with time in `[slot + 0.1 s, slot + 0.5 s]` and pitch > 0 is within ±10 cents of the generated frequency. Each tone needs at least 5 voiced frames.
  5. Rerun: all five aubio outputs and both input WAV files are byte-identical between `run-a` and `run-b`.
  6. Recorded `expected/summary.json` (counts, rounded values and check booleans, no media) must match on a later run. `run.sh` exits 1 without recording if any check is false.
- Intended consumer and handoff: an analysis step that reads onset, beat and pitch events from audio. The onset-to-timeline contract is not declared in VCR yet (see the tool card), so no handoff is tested.
- Delivery constraints and units: times in seconds, pitch in Hz, tolerances in ms, cents and BPM as stated above. No byte budget.
- Expected failure modes and stop conditions:
  - If an aubio CLI prints a different column layout than assumed (time first, pitch second), the pitch parsing is wrong. Stop and amend the plan in this README before rerunning; do not loosen the checks.
  - Onset misses or extras above the bound: report as failed, do not raise the tolerance to pass.
  - Non-identical reruns: report as failed.
- Reproduction instructions: `examples/aubio-onsets-pitch/run.sh` (add `--record` once to write `expected/summary.json`). Inspection PNGs are written to `output/inspect-*.png`.

- Beat detail: `aubiotrack` emitted beats only from 1.761 s to 5.747 s (9 beats), with none in the remaining 4 s of clicks. The BPM estimate is accurate, but the beat-count check fails.
- Pitch rerun detail: the `aubiopitch` output is not byte-stable. In 8 repeated invocations on one file, the SHA-256 of stdout was `3e2262cf7352…` six times and `4ccbe8a94424…` twice. The differences are about 1e-4 Hz in the per-frame values, including frames inside the measurement windows. The medians move by about 5e-5 Hz, far inside the tolerance. The rerun verdict was `true` in 2 of 5 `run.sh` invocations and `false` in 3.
- Inspection: `output/contact.png` (ignored, rebuilt with `magick`). The waveform shows 20 evenly spaced clicks, as expected. The spectrogram shows five tone blocks starting at 0, 0.9, 1.8, 2.7 and 3.6 s, lasting 0.6 s each. The blocks have abrupt edges, which show as broadband transients at each start and end. The pitch steps are not readable at this scale. There was no listening test.
- Result: **partial**. The onset claim passes exactly. The BPM estimate is within tolerance, but the predeclared beat check also requires at least 10 beats, and that fails. Pitch is within 10 cents on 3 of 5 tones. The rerun claim fails byte-for-byte for `aubiopitch`.

**Amendments made after the first run** (no pass/fail threshold was changed):
1. The first run aborted: `index` is an awk builtin, so the tone loop failed. Renamed the variable to `toneIndex`.
2. The first `--record` path refused to write a failing summary. It now writes the observed summary, including false checks, and exits non-zero, following `typst-title-card`. Reruns therefore reproduce the same verdict.
3. The stored baseline no longer holds the rerun verdict, because it flips between runs. The gate still uses it. The stored pitch values are rounded to 1 dp (they were 3 dp), because the 1e-4 Hz noise flipped the third decimal between runs. The tolerance decisions use unrounded values.
4. The check named `beat_bpm_within_tolerance` also requires at least 10 beats. Its name covers less than what it tests. It was not renamed, to keep the predeclared check unchanged.

- What this result does and does not establish:
  - Establishes: `aubioonset` with default `hfc` settings finds all 20 onsets of a clean 120 BPM click track within 9 ms, with no extras. `aubiotrack` estimates the BPM within 0.4 BPM on this input. `aubiopitch` gets 3 of 5 pure tones within 10 cents, on this machine, with the Homebrew 0.4.9_4 bottle.
  - Does not establish: complete beat coverage (`aubiotrack` stopped after 5.7 s here); beat phase against the clicks; pitch accuracy below 330 Hz (the two failing tones are the lowest); byte-identical `aubiopitch` output across processes; other onset methods, thresholds, sample rates, platforms or the Python binding; any musical or real-audio behaviour.
  - The cause of the low-tone pitch error and the beat stop has not been investigated. The abrupt tone edges are a possible factor for the pitch error. Changing the generator to add fades would be a new fixture with a new claim, not a fix of this one.
