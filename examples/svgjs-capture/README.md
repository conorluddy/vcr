# SVG.js scene capture

## Intent and scope
SVG.js 3.2.8 (`@svgdotjs/svg.js`, pinned exactly) builds an SVG scene in the page: a linear gradient, a rounded rect in a group, a quadratic path and a circle. `seek(t)` rewrites attributes (`plot`, `from`/`to`, `transform`, `center`, `opacity`) from `t` alone, so state is rebuilt from `t` on every seek and no previous frame is relied on. Claim: 90 alpha frames at 1280×720, 30 fps, shuffled capture equals sequential. Excludes the `.animate()` runner and timeline (its clock is real time, per the catalogue card), interaction, events, Node/svgdom output, rasterisation by resvg, other browsers and any quality claim. Procedural original shapes; no media or fonts. Licence: MIT, checked 2026-11-11 from the package's `LICENSE.txt` and `package.json`; docs https://svgjs.dev/ (catalogue card, same date). No codec, model or asset dependency. Unseeded APIs: the browser build contains one `Math.random()` inside the core-js `Symbol` polyfill helper (symbol key names only); it is not on the drawing path and is not used by this scene. No `performance.now`, `Date.now` or `new Date` in the build. The `requestAnimationFrame` calls in the build belong to the runner, which this claim excludes. Seek is idempotent per t: each frame sets every attribute absolutely from t, so order cannot leak state.

## Plan, before running
On macOS arm64, install pinned `@svgdotjs/svg.js@3.2.8` in this example's `package.json` (pre-approved), reuse Playwright 1.64.1 and tsx 4.23.15, then `pnpm install`. Run `examples/svgjs-capture/run.sh --record`, inspect the contact sheet at 1280×720, then run `examples/svgjs-capture/run.sh` and expect `svgjs-capture: OK`. Record the browser version from the capture report. No system-wide changes.

Predeclared checks: 90 frames at 30 fps, 1280×720, at least two distinct frame hashes, every shuffled hash equal to sequential, frame 45 alpha minimum 0 and maximum 1. Stop on a missing browser build, blank or clipped output, an unexpected frame count, or any mismatch. Intended consumer is the existing browser capture harness; units are seconds and pixels. Transparent PNG sequence only; no delivery byte budget or compression claim. Outputs go to ignored `output/`; delete that directory to clean up. No cross-machine byte equality asserted.

## Observation, after running
2026-11-11, evidence agent on Conors-MacBook-Pro-2.local (hostname), macOS Darwin 25.6.0 arm64, Node 22.19.0, `@svgdotjs/svg.js` 3.2.8, Playwright 1.64.1, Chromium 156.0.8078.4 (read by launching Playwright's bundled build; the capture report does not record the browser version), ImageMagick 7.1.2-15. Screenshot capture route, Chromium default backend; GPU details unknown and not claimed.

Both `run.sh --record` and `run.sh` exited 0; the second printed `svgjs-capture: OK`. Measured: 90 frames, 1280×720, 30 fps; 90 distinct SHA-256 frame hashes; `shuffled_matches_sequential` true with `mismatched_frames` empty; frame 45 alpha min 0, max 1. Capture ran at 19.5 frames/s (wall 4.6 s). `expected/summary.json` retains the measurements; hashes stay in ignored `output/report.json`.

What the frames show (contact sheet at output/contact.png, frames 0, 15, 30, 45, 60, 75, read at native size): a blue quadratic SVG path arcing across the frame and its bulge changing over time; a rounded gradient square (blue to lime) centred near 640,360 that turns 300° across the six frames (120° per second, so 60° between neighbours; square symmetry makes that read as a smaller turn) and shrinks and grows in scale; the gradient direction shifts as the square turns; an orange circle travels left to right and rises in opacity, with a vertical wobble. Transparent background, nothing clipped, no blank frames. The rotation and scale changes confirm the group transform is being written from t, not stuck at its initial value.

The montage step in the template failed here: ImageMagick has no configured font, so `magick montage` exits 1 on its annotation. The contact sheet was built with `magick ... +append` and `-append` over the same six frames, flattened onto #808080. Same frames, no labels.

Result: pass for the stated claim. Not covered: the `.animate()` runner or timeline (excluded; the card says its clock is real time), interaction, export, Node/svgdom output, resvg rasterisation, other browsers or platforms, and any quality judgement beyond the agent's visual check. No human approval claimed. Revalidate on svg.js, Playwright or Chromium changes.
