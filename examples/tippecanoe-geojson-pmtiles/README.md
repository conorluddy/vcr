# tippecanoe: GeoJSON to PMTiles

## Intent and scope

- Tool ID and version/build: `tippecanoe` v2.79.0 (Homebrew bottle), with its companions `tippecanoe-decode` and `tile-join`.
- VCR job and exact claim: a self-authored GeoJSON builds to a `.pmtiles` with pinned flags, `tippecanoe-decode` and `tile-join` show the expected layers and per-zoom feature counts, and output bytes repeat across runs.
- Explicit exclusions: no rendering of the tiles (chiitiler and maplibre-native not tried), no real-world data, no FlatGeobuf or CSV input, no `-zg` beyond recording the zoom it picks, no large inputs where feature dropping is forced by tile size.
- Sources, checked 2026-11-27: https://github.com/felt/tippecanoe and `brew info tippecanoe`. Licence BSD-2-Clause. Inputs are generated by this repository, no third-party assets.
- Environment: macOS 26 (Darwin 25.6), arm64, Apple M3, CPU only.
- Input: `data/points.geojson` (500 random points near Dublin, seeded LCG), `data/route.geojson` (one 201-vertex line), `data/region.geojson` (one 64-vertex polygon). Hash prefix recorded in `expected/summary.json`.
- Dependencies: `brew install tippecanoe` (done with approval before this run), plus `jq`, `shasum`. No network.
- Output: `output/` (ignored), cleared each run. `expected/summary.json` is the only retained file.

## Plan, before running

- Commands: `tippecanoe -q -o out.pmtiles -Z0 -z8 --drop-densest-as-needed --force -L points:... -L route:... -L region:...`, run twice in `output/run-a` and `output/run-b`, once with another output name, once with `-zg` on points only, plus `tile-join -l points`.
- Predeclared checks:
  1. File starts with `PMTiles`.
  2. Metadata: minzoom 0, maxzoom 8, format pbf.
  3. Layers are exactly points, region, route, with tilestats counts 500, 1, 1.
  4. Distinct point ids per zoom are non-decreasing and at most 5 at z0.
  5. All 500 points are present at z8.
  6. Route and region have at least one feature at every zoom 0 to 8.
  7. `-zg` picks a maxzoom between 1 and 14.
  8. `tile-join -l points` leaves only the points layer, with 500 points at z8.
  9. Two runs of the same command give byte-identical archives.
- Threads: `tippecanoe --help` lists no thread-count option (only `--read-parallel`, off by default), so single-thread mode cannot be tried. Reproducibility is measured as is.
- Stop conditions: a false check is recorded and printed as KNOWN FAIL, never loosened.

## Observation, after running

- 2026-11-27, Claude agent, `Conors-MacBook-Pro-2.local`. `./run.sh --record`, then repeated runs.
- All 9 checks pass. Archive is 11376 bytes. Distinct points per zoom 0 to 8: 1, 1, 2, 5, 13, 32, 80, 201, 500. Route and region: 1 feature per zoom, 2 at z8 (tile boundary split). `-zg` on the points chose maxzoom 6.
- Feature lines at z8 total 565 for points but only 500 distinct ids: points near a tile edge appear in both tiles because of the tile buffer. Count distinct ids, not lines.
- Reproducibility: byte-identical in 8 of 8 early runs and in every `run.sh` rerun, when the command, output file name and relative input paths are identical. Changing only the output file name changes the bytes, because name and paths are written into the metadata (`description`, `generator_options`). Tile data is the same. Absolute input paths would make archives differ between checkouts.
- Inspection: no image to look at; the decoded tile JSON was read and the thinning gradient and clipped polygon and line geometry are as expected.
- Result: pass. Establishes the build and read-back route on one machine. Does not establish rendering, large-input behaviour, or reproducibility across versions or machines.
