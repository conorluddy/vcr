# FluidSynth offline MIDI render

## Intent and scope

- Tool ID and version/build: `fluidsynth` 2.6.3 (Homebrew bottle `fluid-synth` 2.6.3; runtime reports `FluidSynth runtime version 2.6.3`).
- VCR job and exact claim: `fluidsynth -ni -F out.wav -r 48000` renders a generated type-0 MIDI file with a pinned SoundFont to a WAV of the predeclared rate and channels, with duration matching the MIDI end time plus release within tolerance. An onset and pitch check finds the predeclared notes at the predeclared times and pitches within tolerance. Two renders in one run, and a rerun against the recorded hash, must be byte-identical (recorded either way).
- Explicit exclusions: real-time playback and MIDI ports; other SoundFont formats (SF3 and DLS are not tested); other MIDI features (controllers, pitch bend, SysEx, multiple channels, tempo changes beyond the one set-tempo event); musical or timbral quality; loudness standards; other platforms or other FluidSynth builds; tool-to-tool edges (MIDI writers, audio encoders, DAWs). Sound design judgement is out of scope; the sound design pillar (`SOUND-`) informs the framing only.
- Tool documentation and licence sources, checked 2026-11-24: FluidSynth is LGPL-2.1-or-later. Checked from the installed package (`/opt/homebrew/Cellar/fluid-synth/2.6.3/LICENSE`) and the Homebrew formula licence field (`LGPL-2.1-or-later`). The project page `https://www.fluidsynth.org/` is the documentation source listed on the record; this run did not fetch it live.
- SoundFont: `VintageDreamsWaves-v2.sf2`, SHA-256 `52132b2b83994f0067d3a66b93b4f1b67d53ff8c0d3be90d39f23f92b4585cdd`, 314 640 bytes, shipped inside the Homebrew `fluid-synth` 2.6.3 install (`share/fluid-synth/sf2/`). Licence: its `COPYRIGHT.txt` (Ian Wilson, 1996) is freeware; redistribution is allowed only unaltered, and the 2020 note grants FluidSynth permission to convert it to SF3. This fixture uses it unaltered, locally, for private use, copies it only into the git-ignored `output/`, and never commits it. Checked 2026-11-24 from the on-disk copy.
- MIDI input: generated by `score.py` in this directory from original numbers (no external MIDI content). Rights: original to this repository.
- Environment: macOS arm64 (Darwin 25.6.0), Homebrew FluidSynth 2.6.3, system Python 3.12.2 (standard library only, no virtual environment, no pip packages).
- Dependencies and installation plan: none new. `fluidsynth` is already installed by Homebrew; the only other requirement is the SoundFont already on disk. No network access, no `pip install`, no global changes.
- Selected workspace, generated output and cleanup: `output/` (git-ignored) holds the MIDI, copied SoundFont, WAV renders, envelope PNG and metrics. `expected/render.json` is the only committed evidence; it holds predeclared checks and the WAV hash, never media or SoundFont bytes.

## Plan, before running

- Exact commands: `./run.sh --record` (first run; writes `expected/render.json` only if all checks pass), then `./run.sh` (must print `OK fluidsynth-midi-render`).
- Render command, per run, twice: `fluidsynth -ni -F output/render-a.wav -r 48000 output/soundfont/VintageDreamsWaves-v2.sf2 output/score.mid`, and the same to `render-b.wav`. Soundfont preset 0 (bank 0, program 0) is used on channel 0.
- Predeclared score (120 BPM, 480 ticks per beat, so one beat is 0.5 s): C4 (MIDI 60) at 0.5 s for 0.4 s; E4 (64) at 1.0 s for 0.4 s; G4 (67) at 1.5 s for 0.4 s; C5 (72) at 2.0 s for 0.4 s; C4 at 3.0 s for 0.5 s. MIDI end time = 3.5 s (last note-off). Velocity 100.
- Predeclared checks (all must hold for `pass`):
  1. WAV is PCM, 2 channels, 16-bit, 48 000 Hz.
  2. Duration is within [3.5 s, 5.5 s]: MIDI end plus at most 2.0 s of release.
  3. Peak absolute sample is between 5% and 99% of full scale (not silent, not clipped).
  4. Onset: for each note, the 100 ms-window Goertzel power at the predeclared pitch, hop 5 ms, first reaches 50% of its maximum over [onset - 0.2 s, onset + 0.4 s]; the estimated onset must be within ±0.05 s of the predeclared onset.
  5. Pitch: over [onset + 0.1 s, onset + 0.3 s], among MIDI pitches 48–84 the largest Goertzel power is at the predeclared pitch (exact semitone).
  6. Determinism: `render-a.wav` and `render-b.wav` have identical SHA-256; that hash equals the one in `expected/render.json`; the MIDI bytes are identical across two writes.
- Expected artifacts: `output/score.mid`, `output/render-a.wav`, `output/render-b.wav`, `output/envelope.png` (inspection image, not committed), `output/metrics.json`; committed: `expected/render.json`.
- Intended consumer and handoff settings: a WAV handed to a downstream audio step at 48 kHz stereo 16-bit. No downstream tool is exercised here.
- Delivery constraints: none for this claim. WAV size is about 2 × 2 × 48 000 × 5 s ≈ 1 MB; not a delivery budget.
- Expected failure modes and stop conditions: `fluidsynth` missing or not 2.6.3 (report `blocked`, do not install); SoundFont SHA-256 mismatch or missing from the Homebrew path (stop); a check fails (report `partial` if the WAV renders and is deterministic but note checks fail, `fail` if no WAV or not deterministic). FluidSynth's fast render may cut off the release tail, which would still pass check 2 at its lower bound.
- Reproduction: `./run.sh --record` then `./run.sh`. Inspect with `open output/envelope.png` or `cat output/metrics.json`.

## Observation, after running

- Executor and date: Claude agent (claude-haiku-5-5), 2026-11-24. Host `Conors-MacBook-Pro-2.local`, macOS 26 (Darwin 25.6.0) arm64.
- Versions: FluidSynth 2.6.3 (`FluidSynth runtime version 2.6.3`, Homebrew bottle `fluid-synth` 2.6.3, LGPL-2.1-or-later). Python 3.12.2 (pyenv, standard library only). Node, Playwright and Chromium: not used. The SoundFont is `VintageDreamsWaves-v2.sf2` (SHA-256 `52132b2b…585cdd`, verified by `shasum -c` on every run).
- Commands: `./run.sh --record` (exit 1), then `./run.sh` (exit 1). Neither run wrote `expected/`, because a predeclared check failed before recording. Both runs printed `FAIL checks: - duration 7.256 s outside [3.5, 5.5]`.
- Measured (run 1, identical in run 2):
  - Render: 48 000 Hz, 2 channels, 16-bit PCM, 348 288 frames, 7.256 s; WAV 1 393 196 bytes; peak 0.1807 of full scale (check 3 passes).
  - Check 1 (format) passes. Check 2 (duration) fails: the MIDI ends at 3.5 s, so the tail is 3.756 s against the predeclared 2.0 s allowance.
  - Check 4 (onsets): all five detected within 10 ms of the predeclared times (errors +0.010, +0.005, 0.000, −0.005, +0.010 s; tolerance ±0.05 s). Passes.
  - Check 5 (pitch): all five detected exactly (MIDI 60, 64, 67, 72, 60). Passes.
  - Check 6 (determinism): `render-a.wav` and `render-b.wav` in one run are byte-identical; a separate second invocation (`./run.sh`) produced the same SHA-256 `78148a9363fb509c36923e11177f9c6807a445ca353cd0d442b0a29ce7763b57`. The two MIDI writes are byte-identical (SHA-256 `be88cb5a…4a12`). The comparison with a recorded `expected/` hash could not run because no record was kept.
- Why the duration failed: FluidSynth's fast render keeps going until the voices and default reverb have decayed. Measured last non-silent sample: above 1 LSB until 5.46 s; above −46 dBFS (164 LSB) only until 3.88 s; residual values to 7.256 s. The predeclared 2.0 s allowance was too tight for this SoundFont's release and FluidSynth's default reverb. The bound was not changed to pass; a different bound would need a new predeclared plan and a new run.
- Inspection: `output/envelope.png` (stdlib-drawn, 1200 × 300, not committed). It shows five decaying bars starting at the predeclared onsets (red markers), with detected onsets (green) on top of them. Decays are clear and no clipping is visible. Audible content ends around 4 s; the image's remaining width is near-silent reverb residue. This is an envelope image, not a listening test. A contact sheet was not produced because the claim is audio, not frames.
- Result: **partial**. The WAV renders with the predeclared rate, channels, depth and pitch and onset content, and it is byte-deterministic on this machine. The duration-plus-release check fails as predeclared.
- Deviations and limitations: `fluidsynth` prints `Sample 'SineWave': ROM sample ignored` (the SoundFont has no ROM samples; no effect on the render). Default reverb and chorus are on, unaltered. The render is from one machine with one FluidSynth build and one SoundFont. This does not establish other MIDI features, SF3/DLS, real-time playback, or sound quality.
- What the result establishes: `fluidsynth -ni -F … -r 48000` renders this predeclared 5-note type-0 MIDI with a pinned SoundFont to a 48 kHz stereo 16-bit WAV, with note onsets and pitches within tolerance and repeat renders that are byte-identical on macOS arm64. It does not establish that the duration follows MIDI end plus a 2.0 s release.
- Reviewer and follow-up: a follow-up fixture could predeclare a release allowance matching the measured tail (for example, a reverb-off render with `-R 0` or a separate bound of ~4.5 s) in a new plan, with its own run. Not done here.
