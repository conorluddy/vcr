# Demucs stem separation of a synthetic four-source mix

History: the first run (2026-11-24, commit 57f5e77) was **blocked**: `demucs` 4.1.0 could not be
imported because `numpy` was not installed, and it is not declared for arm64. The coordinator
approved `numpy` into the same venv. The plan below was then run unchanged; its outcome is in
"Observation, after running".

## Intent and scope

VCR job and claim: `demucs` separates a generated ten-second stereo mix at 44.1 kHz into the
four standard `htdemucs` stems (`drums`, `bass`, `other`, `vocals`) at the input's sample rate
and length. Each estimated stem correlates more with its own true source than with the others,
by a predeclared margin, and the drums, bass and vocals SDR against ground truth exceed predeclared
floors. The four outputs sum back to the mix within a predeclared tolerance. Determinism across
two reruns is recorded, not gated.

Tool: Demucs 4.1.0 (PyPI, released 2026-11-07, pinned exactly), model `htdemucs` (one model,
weights from Hugging Face `adefossez/HTDemucs`, file `955717e8.safetensors`).
The original `facebookresearch/demucs` repository is archived; 4.1.0 is maintained from
`adefossez/demucs`. The card records the original archive as a maintenance concern.

Explicit exclusions:
- No `htdemucs_ft`, `htdemucs_6s`, `hdemucs_mmi`, `mdx*` or quantised models. One model only.
- No real music, no MUSDB, no third-party audio. Synthetic sources may not resemble the
  training data; a low SDR on these sources says nothing about quality on real recordings.
- No `--two-stems`, no MP3/FLAC output, no 24-bit output, no other devices (CPU only).
- No claim about Demucs's benchmark SDR (9.0 dB on MUSDB HQ), which is a different dataset.
- No tool-to-tool edges: the stems are not passed on to another tool here.
- Random shifts (`--shifts`) are disabled (set to 0) so the run is reproducible; the default
  of random time-shift averaging is outside the claim.

Licence and documentation sources, checked 2026-11-24:
- Code: https://github.com/adefossez/demucs (`LICENSE` MIT; PyPI metadata MIT).
- Weights licence status, exactly as found (2026-11-24): **unclear; likely CC-BY-NC**. The
  repository README "License" section says the weights' licence is "not clear", because MusDB
  contains research-only data, and that the 6-source variant trained on Meta-internal data
  "likely means CC-NC-BY", as for FAIR models. The Hugging Face model card for
  `adefossez/HTDemucs` has no licence field. This is an internal, non-redistributed fixture; the
  weights stay in the git-ignored `output/cache` and are never committed.
- Card: `catalog/tools/demucs.json` (checked 2026-10-29, verdict keep, maintenance unmaintained).
- Documentation: https://github.com/adefossez/demucs/blob/main/README.md

Environment: macOS 26.6 (Darwin 25.6.0), arm64 (Apple M3), CPU only, 18 GB RAM.
Python 3.12.13 at `/opt/homebrew/bin/python3.12` (the pyenv 3.12.2 build lacks `_lzma`).

Input (to be generated by `run.sh`, not committed): ten seconds, 44.1 kHz, stereo, 16-bit.
- `drums`: a kick (sine sweep 90→40 Hz with exponential decay) on each beat at 120 BPM and a
  snare (1.8 kHz burst with fast decay) on beats 2 and 4 (every 1.0 s from 0.5 s). Synthesised
  in numpy from closed-form expressions (`make_input.py`); no random generator. Amended before
  the run: the plan first said ffmpeg `aevalsrc`, which is awkward to quote; the signal
  definition is unchanged.
- `bass`: a sequence of low sine notes (55, 65.4, 73.4, 82.4 Hz), 0.5 s each, with decay.
- `vocals`: macOS `say -v Samantha` speaking a fixed sentence, resampled to 44.1 kHz stereo.
- `other`: not part of the mix (the mix has three sources); the ground truth for `other` is
  silence, so its estimate is checked only in the sum and correlation checks.
- Mix: `0.8*drums + 0.6*bass + 0.5*vocals`, summed with ffmpeg `amix` at `normalize=0`,
  peak-limited by a fixed gain of 0.7 if it would clip. Ground-truth stems are scaled by the same
  gains so they are the exact components of the mix.
- Hashes of generated WAVs are not gated, because `say` output can change with the macOS version.

## Plan, before running

Commands:
```
examples/demucs-stem-separation/run.sh            # builds input, separates twice, checks, diffs expected/
examples/demucs-stem-separation/run.sh --record   # only after a deliberate change
```

Pipeline:
1. Preflight: `output/venv/bin/python -c "import numpy, demucs.separate"`. If it fails, print the
   blocker and exit non-zero. The rest does not run.
2. Build `output/input.wav` and the three ground-truth stems as above, with fixed gains.
3. `ffprobe` on `output/input.wav` into `output/input-ffprobe.json`.
4. `python -m demucs -n htdemucs --shifts 0 -d cpu --float32 -o output/sep1 output/input.wav`,
   then the same into `output/sep2` for the rerun.
5. `check.py`: reads the stems through the ffmpeg CLI into numpy (`audio_io.py`, no resampling),
   computes the checks below, writes `output/checks.json` (gated) and `output/metrics.json`.
   `run.sh` refuses to record or pass unless `all_gated_checks_pass` is true.
6. `run.sh` diffs `expected/checks.json` against `output/checks.json`, and prints OK.

Predeclared checks (fixed before any run):
- C1 format: each stem is WAV at 44100 Hz, 2 channels, and has the same sample count as the
  input, exactly.
- C2 correlation margin: for each true source `s` with estimate `e_s`, Pearson correlation of
  `e_s` with `s` exceeds the correlation of `e_s` with each other true source by at least 0.10
  (`drums`, `bass`, `vocals`).
- C3 SDR floors against ground truth (`SDR = 10 log10(|s|^2 / |e - s|^2)`, after the best
  scalar gain is not applied): drums at least 4 dB, bass at least 4 dB, vocals at least 2 dB.
- C4 sum: the sum of the four estimates vs the mix, residual SNR at least 15 dB.
- C5 determinism: sha256 of each stem identical between the two runs. Recorded, not gated.
- Informational: wall time per run, demucs and torch versions, and the Hugging Face weight hash.

Expected failure modes and stop conditions:
- Import failure: stop, report `blocked`, keep the message. Do not install any further package
  without approval.
- Model download failure: stop, report `blocked`.
- Any C1 to C4 failure: `fail` (or `partial` if only C2/C3 margins fail and C1/C4 pass), with the
  measured figures as scope. Predeclared bounds are not changed after running.
- A rerun that differs (C5): recorded as nondeterminism; it does not fail the claim on its own.

Inspection: no image contact sheet, because the output is audio. Inspection is the
`metrics.json` table and a waveform image (`ffmpeg showwavespic`) of each estimate, if the
run reaches separation.

## Observation, after running

Executed 2026-11-24 on Conors-MacBook-Pro-2.local: macOS 26.6 (Darwin 25.6.0), arm64 (Apple M3),
CPU only, from `examples/demucs-stem-separation`. Commands: `run.sh --record`, then `run.sh`
(printed `demucs-stem-separation: OK`). Both ran after the numpy approval.

Versions (from `output/venv`, freeze in `output/freeze.txt`, git-ignored):
- demucs 4.1.0 (PyPI, MIT); torch 2.15.0 and torchaudio 2.11.1 (PyTorch CPU index, macOS arm64);
  numpy 2.5.5 (added after the approval, pinned in `requirements.txt`); huggingface-hub 2.4.0;
  sphn 0.2.1; julius 0.2.8; lameenc 1.9.0.
- Python 3.12.13 (`/opt/homebrew/bin/python3.12`). ffmpeg and ffprobe 9.0.2 (Homebrew).
- Model: `htdemucs`, Hugging Face `adefossez/HTDemucs`, file `955717e8.safetensors` (84 MB blob),
  fetched into `output/cache` (80 MB total cache, git-ignored). Licence: unclear, likely CC-BY-NC
  (see Intent and scope). Not redistributed.
- `say`: macOS built-in, voice Samantha (the voice build is not reported by `say`).
- Playwright, Chromium and Node: not used.

Amendments to the plan, both made before the run and disclosed:
- numpy 2.5.5 added to the existing venv, as approved. Nothing global was installed.
- Drums and bass were synthesised in numpy rather than with ffmpeg `aevalsrc`. The signal
  definition is the same, and the predeclared checks are unchanged.
- The run also wrote `output/cache/.agent_harnesses.json` (9 KB) into the cache directory. It is
  not part of the model, and it sits in the git-ignored `output/`, so nothing is committed.

Mix construction, from `output/make_input.json`: 0.8 x drums + 0.6 x bass + 0.5 x vocals. The
unscaled peak was 1.719, above the 1.0 limit, so every source and truth stem was scaled by 0.7
(the predeclared fallback). Vocals: 110,100 samples (2.50 s) of `say`, zero-padded to 10 s.

Measured (`output/checks.json`, `output/metrics.json`; the record run and the verification run
gave identical numbers):
- C1 format: input and all four stems are 44100 Hz, 2 channels, 441,000 samples. Pass.
- C2 correlation margin (correlation of each estimate with each true source):
  - drums estimate: drums 0.921, bass 0.086, vocals -0.001. Margin 0.835. Pass.
  - bass estimate: bass 0.961, drums -0.021, vocals 0.000. Margin 0.961. Pass.
  - vocals estimate: vocals 0.997, drums -0.002, bass 0.001. Margin 0.996. Pass.
  All three margins are far above the 0.10 bound. The correlations are whole-signal figures, so
  they are dominated by the loud events and say little about residual leakage.
- C3 SDR against ground truth: drums 8.02 dB (floor 4), bass 11.10 dB (floor 4), vocals 16.10 dB
  (floor 2). All pass.
- C4 sum: residual SNR of the input against the sum of the four estimates is 20.11 dB (floor 15).
  Pass. The sum does not match exactly; the residual is about 1% of the mix energy.
- C5 determinism: the four stems are byte-identical between the two separation processes in one
  `run.sh` invocation (sha256 match for all four). Recorded, not gated.
- Wall time: about 9 to 10 s per separation for 10 s of audio (tqdm reported about 1.2 s of audio
  per second of wall time), after the model was cached.

Inspection: `output/contact.png` is a stacked log-scale spectrogram (ffmpeg `showspectrumpic`),
top to bottom: input, true drums, true bass, true vocals, estimated drums, bass, other, vocals.
The true drums show a kick and snare on each beat as vertical clicks, and the estimated drums
show the same clicks. True bass shows only low horizontal bands; the estimated bass shows those
bands plus a faint broadband floor, visible because the scale is logarithmic. The speech in the
true vocals appears in the estimated vocals and nowhere else. The estimated other stem shows
faint broadband texture and no clear events. The picture supports the numeric result and shows
residual leakage that the margin does not reveal.

Result: **pass** on the predeclared checks C1 to C4. Both `run.sh --record` and the verification
run gave `all_gated_checks_pass: true`. C5 recorded: identical.

What this establishes: on this arm64 Mac, with demucs 4.1.0 and the `htdemucs` weights as of
2026-11-24, a generated ten-second mix of a synthetic kick and snare, low sine bass notes and a
macOS `say` voice comes back as four 44.1 kHz stereo stems of the same length, each closest to
its own source, with SDR of 8 to 16 dB against the truth and a residual of 20 dB against the
mix. Two separations in one run are byte-identical.

What it does not establish: performance on real music or recordings (the sources are synthetic,
and the SDR floors are not benchmark numbers); the other models (`htdemucs_ft`, `_6s`, `mdx*`);
other devices or GPU output; determinism across machines, OS versions or torch versions; the
randomised shift averaging (disabled, `--shifts 0`); the quality of the `other` stem (it has no
truth here, so it is checked only through the sum); or any licence question. The weights are not
cleared for commercial use; their status is unclear, likely CC-BY-NC.

Deviations and limitations:
- The first run was blocked on numpy, as recorded in the earlier entry (commit 57f5e77). That
  entry is kept as history, and this result is a new entry, rather than an edit of the old one.
- `expected/checks.json` was recorded by `run.sh --record` after one run and not hand-written.
  It holds only booleans and integers, so it is stable across reruns.
- The `say` voice and the macOS build are not pinned, so the vocals source can change between
  machines; the vocals SDR floor is the check most sensitive to that.

Reviewer, decision and revisit triggers: revisit on any change to demucs, torch, torchaudio or
numpy; on a different model; on a licence clarification for the weights (status unclear, likely
CC-BY-NC, so this fixture stays internal only); or when real recordings are tested.
