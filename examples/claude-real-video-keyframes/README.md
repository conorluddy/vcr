# claude-real-video keyframes on a generated three-shot clip

## Intent and scope

- Tool: claude-real-video 0.10.7 (PyPI, MIT), a Python CLI (`claude-real-video`, alias `crv`). Installed with `pip` into `output/venv` only.
- Claim: run locally on a generated 3-shot clip, claude-real-video detects the predeclared scene boundaries (frames 48 and 96, each within ±1 frame) and writes one keyframe per scene: 3 keyframes, each 320x240. Two reruns give identical boundaries.
- Route: `claude-real-video --no-transcribe --scene 0.30 --fps-floor 1000 --frame-width 320 --overwrite`. Its scene gate is ffmpeg's `gt(scene,0.30)`. `--fps-floor 1000` disables the one-frame-per-second density floor, so only frame 0 and scene-gate frames remain; the default floor would add frames every second and blur "one per scene". Frame width is set to the source width so keyframe dimensions are 320x240.
- Explicit exclusions: URL input (yt-dlp download), transcription (whisper, faster-whisper, mlx-whisper), speaker diarisation (`--speakers` downloads models from GitHub), `--adaptive`, `--text-anchors`, `--export llc`, `--viewer`, `--grid`, `--report`, memory and `crv-ask`, the MCP server, and any LLM use. No claim about detection accuracy on real footage, fades, camera motion, or other thresholds.
- No API key, account or credential is used or read. `CRV_NO_MEMORY=1` and `CRV_NO_HINT=1` are set, so the local memory index and upgrade hint are off; `CRV_MEMORY_DB` points under `output/` in case the index is written anyway.
- Network: the local-file path should need none. The observation confirms this by running `run.sh` under `sandbox-exec` with network outbound denied. The install itself fetches from PyPI.
- Licence and documentation sources, checked 2026-11-24:
  - https://github.com/HUANGCHIHHUNGLeo/claude-real-video (README; MIT per the package LICENSE and the tool record).
  - PyPI metadata for 0.10.7: MIT, Requires-Python >=3.10.
  - Dependencies keep their own licences and are not redistributed here: Pillow, yt-dlp, `deno` (bundled by `yt-dlp[deno]`), requests, websockets, mutagen, brotli, pycryptodomex, certifi, charset-normalizer, idna, urllib3, yt-dlp-ejs.
- Environment: macOS 26.6 (Darwin 25.6.0) arm64; Python 3.12.2 (pyenv) for the venv; ffmpeg and ffprobe 9.0.2 from Homebrew.
- Input: generated by FFmpeg lavfi in `run.sh`; no external media. Three 2 s segments at 320x240, 24 fps: `testsrc2`, `mandelbrot`, `smptebars`. Total 144 frames (6 s), x264 CRF 0, yuv420p, no audio. Authored boundaries are the first frame of shot 2 (frame 48) and of shot 3 (frame 96).
- Installation (approved): `python3 -m venv examples/claude-real-video-keyframes/output/venv`, then `output/venv/bin/python -m pip install claude-real-video==0.10.7`. The resolved transitive set is written to `output/dependencies.txt` by `run.sh`. Nothing global, no shell or PATH change.
- Cleanup: remove `examples/claude-real-video-keyframes/output` (venv, clip, outputs, logs).
- Selected workspace and output: `examples/claude-real-video-keyframes/output/` (git-ignored). Committed: this README, `example.json`, `run.sh`, `check.py`, `expected/checks.json`. No media is committed.

## Plan, before running

Commands:
```
examples/claude-real-video-keyframes/run.sh --record   # after a deliberate change only
examples/claude-real-video-keyframes/run.sh            # generates the clip, runs twice, checks, diffs expected/
```
`run.sh` builds the clip, runs claude-real-video twice into `output/run-a` and `output/run-b` (fresh directories each time), then runs `check.py`, which writes `output/checks.json`. It exits 0 and prints `claude-real-video-keyframes: OK` only if that file matches `expected/checks.json`.

Predeclared checks (all gating):
1. Clip (ffprobe, `count_frames`): 144 frames, 320x240, `avg_frame_rate` 24/1.
2. Both claude-real-video runs exit 0 and write `frames.json`.
3. Keyframe count per run is 3, one per shot (`frames/frame_*.jpg`).
4. Each keyframe is 320x240 (Pillow).
5. The keyframe frame indices, `round(timestamp_sec * 24)`, are [0, 48, 96]. Frame 0 is the start; the other two are the boundaries, each within ±1 frame of its authored value.
6. No extra or missing keyframe: the count and the boundary list match exactly.
7. Reruns give identical boundaries and identical `frames.json` (file names, timestamps, selection reasons) across run-a and run-b.

Informational, not gating: keyframe JPEG SHA-256 equality across reruns; the scene-gate selection reasons; the number of frames extracted before dedup (from the tool's log).

Expected failure modes and stop conditions:
- Venv or ffprobe missing: stop, `blocked`.
- Either run exits non-zero: stop, keep logs, `fail`.
- A boundary missing, extra, or beyond ±1 frame: `fail`. The boundary list is not tuned to pass.
- Any dimension or count mismatch: `fail`.
- Boundaries correct but the rerun differs: `fail`.
- The network-deny sandbox run fails: report that part as `blocked`, not as a pass.

Inspection: `output/contact.png` shows the three keyframes side by side, drawn by `magick` from the actual keyframes. Inspection only; it does not gate.

## Observation, after running

Executed 2026-11-24 on Conors-MacBook-Pro-2.local (macOS 26.6, Darwin 25.6.0, arm64), from
`examples/claude-real-video-keyframes`.

Versions: claude-real-video 0.10.7 (installed from PyPI into `output/venv`); Python 3.12.2 (venv);
Pillow 13.0.0; ffmpeg and ffprobe 9.0.2. Installed as dependencies but not exercised on this path:
yt-dlp 2026.11.23, yt-dlp-ejs 0.8.0 and the `deno` 2.9.8 wheel. Playwright, Chromium and Node are
not used. Full freeze: `output/dependencies.txt` (ignored).

Commands and sequence:
1. First `run.sh --record` failed at clip generation (exit 8): ffmpeg rejected `d=2` as an option of
   `mandelbrot`. No tool output was produced. The fix moved the duration to a per-input `-t 2` for all
   three lavfi sources. The recipe is otherwise as predeclared.
2. `run.sh --record` passed all gates and wrote `expected/checks.json`.
3. `run.sh` printed `claude-real-video-keyframes: OK`.
4. `sandbox-exec -p '(version 1)(allow default)(deny network-outbound)' ./run.sh` printed `OK` as well.
   Control: the same sandbox made `curl https://pypi.org/simple/` fail with "Could not resolve host",
   where unsandboxed curl returned 200.

Measured (`output/checks.json`, identical in record, verify and sandboxed runs):
- Clip: 144 frames, 320x240, 24/1 fps, from ffprobe `nb_read_frames`.
- Each run logged "3 frames (deduped from 3 extracted)". The scene gate proposed frame 0 and two
  scene frames. Dedup removed none, so this fixture does not exercise dedup.
- Keyframes at timestamps 0.0, 2.0 and 4.0 s, which are frames 0, 48 and 96. Offsets from the
  authored values are 0 frames for all three, against a tolerance of ±1.
- Keyframe dimensions 320x240 for all three, in both runs.
- Selection reasons: `first`, `global`, `global`. The `global` label is the dedup channel that kept
  the frame. It does not name the scene gate, so the boundary evidence is the timestamps, not this field.
- Rerun: `frames.json` is identical, and the three keyframe JPEGs are byte-identical between run-a and
  run-b (informational).

Inspection: `output/contact.png` (960x240, the three keyframes side by side) shows, left to right, a
testsrc2 frame with its own on-screen timer reading 00:00:00.000, a mandelbrot frame, and a smptebars
frame. Each is the first frame of its shot. None is blank or clipped, and each matches the source
segment, so the tool did pick the shot starts.

Deviations and limits:
- `--fps-floor 1000` was used on purpose, so the density floor does not add frames. With the default
  floor of 1 s, the output would contain more frames than scenes. That default route is not tested here.
- One synthetic clip with hard cuts and no fades, dissolves or camera motion. The scene gate fired only
  at the authored cuts, including through the moving content of testsrc2 and mandelbrot. This is not
  evidence of accuracy on real footage.
- Local path only: `--no-transcribe`, a local file, no `--speakers`, no URL. No memory index, `crv-ask`
  or MCP server was used. `~/.crv` and `~/.cache/crv-mcp` were not created.
- Network: the sandboxed run completed without a network, so the local path does not need one. The
  sandbox does not log attempts, so whether the tool tried to connect and was refused is not observed.
  No API key, account or credential was used or read.
- The install fetched from PyPI, including the yt-dlp, deno and Pillow wheels, which the local path does not use.
- Determinism was observed on this machine only.

Pass, on the predeclared checks, for the claim as scoped: local scene-boundary detection on a generated
three-shot clip, one 320x240 keyframe per shot, identical boundaries on rerun, under a deny-network
sandbox. It does not establish detection on real footage, other thresholds, the default density-floor
output, transcripts, URL inputs, or any remote model path.

Reviewer, follow-up and revisit triggers: revisit on any claude-real-video release (the scene and dedup
logic may change), any ffmpeg major version, or a change to the `--fps-floor` or `--scene` defaults.
