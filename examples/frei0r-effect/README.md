# frei0r effect fixture (MLT route)

## Intent and scope

- **Tool/version:** frei0r 3.7.1 (Homebrew formula `frei0r`, plugins in `/opt/homebrew/lib/frei0r-1/`), applied through MLT 7.42.0_1 `melt` (`libmltfrei0r.so`). The system FFmpeg 9.0.2 has no frei0r filter, so FFmpeg is not used.
- **Route:** route 1 of the batch brief (MLT `melt`). GStreamer's frei0r element was not tried, because route 1 is planned to succeed.
- **Claim:** a generated 64×48 four-quadrant frame passed through `frei0r.invert0r` gives exactly `255 - v` in every pixel and channel; `frei0r.brightness` at parameter 0.25 / 0.5 / 0.75 moves each channel in the predeclared direction within ±1 of the frei0r formula; reruns are byte-identical.
- **Exclusions:** the other 105 frei0r plugins MLT registers; animated parameters or keyframes; alpha behaviour beyond "stays 255"; premultiplied or non-opaque input; colour conversion into video codecs (output is raw RGBA); other hosts (GStreamer, direct frei0r API, Kdenlive, Shotcut); performance; other operating systems.
- **Documentation and licence:** frei0r project <https://frei0r.dyne.org/> and source <https://github.com/dyne/frei0r>; MLT's frei0r notes in `/opt/homebrew/Cellar/mlt/7.42.0_1/share/mlt/frei0r/`. Catalogue card licence: "GPL family and compatible licences (per project; check each plugin and host separately)". The individual licences of `invert0r` and `brightness` were not re-checked. Checked 2026-11-24.
- **Environment:** macOS 26 (Darwin 25.6.0) arm64; Homebrew melt and frei0r; Python 3.12.2 for generating the input and checking raw bytes.
- **Input:** generated by `verify.py` at run time as a binary PPM (P6) with four solid quadrants: top-left `(255,0,0)`, top-right `(0,255,0)`, bottom-left `(0,0,255)`, bottom-right `(128,64,32)`. No external media. It is written to ignored `output/`.
- **Dependencies and side effects:** no new installs. Needs the existing Homebrew `frei0r` and `mlt` formulas. MLT needs `FREI0R_PATH` set to the frei0r plugin directory; without it MLT registers zero frei0r filters and a `frei0r.*` filter passes frames through unchanged. Checked in a scratch run before this plan: the filtered output was byte-identical to the unfiltered one. `run.sh` sets `FREI0R_PATH` from `brew --prefix frei0r`.
- **Workspace:** `examples/frei0r-effect/output/` (ignored) and `expected/render.json`. No media is committed.

## Plan, before running

- **Commands:** `./run.sh --record` (writes `expected/render.json`), then `./run.sh`, which must print `OK`. Each run renders six variants twice (`-a` and `-b`) with `melt quad.ppm out=0 -filter … -consumer avformat:<file>.rgba f=rawvideo pix_fmt=rgba s=64x48 r=25`:
  - `control`: no filter; must equal the input exactly;
  - `invert`: `frei0r.invert0r`;
  - `invert2`: `frei0r.invert0r` applied twice; must equal the input exactly;
  - `bright025`, `bright050`, `bright075`: `frei0r.brightness 0=<p>` with p = 0.25, 0.5, 0.75.
- **Versions:** melt must report `7.42.0`, else `run.sh` exits 1. The frei0r version is `brew list --versions frei0r` (3.7.1), recorded in `expected/render.json`.
- **Predeclared checks** (every pixel of every variant; sample probes at the corners, the seams `(31,24)`/`(32,24)` and `(31,23)`/`(32,23)`, and the quadrant centres):
  1. Each output is exactly one 64×48 RGBA frame, 12288 bytes.
  2. `control` equals the input RGB exactly; alpha is 255 everywhere.
  3. `invert` equals `255 - v` for every RGB channel, tolerance 0; alpha 255. The bottom-right quadrant becomes `(127,191,223)`.
  4. `invert2` equals the input exactly (tolerance 0).
  5. `brightness` at 0.5 equals the input within ±1 (frei0r's identity point).
  6. `brightness` at 0.25 equals `floor(v*0.5)` within ±1 for every channel.
  7. `brightness` at 0.75 equals `v + (255 - v)*0.5` within ±1 for every channel.
  8. Direction: for every pixel and channel, `out(0.25) <= out(0.5) <= out(0.75)`, and `out(0.75) > out(0.25)` strictly.
  9. Reruns: the `-a` and `-b` files of every variant are byte-identical, and each SHA-256 equals `expected/render.json` on a normal run.
  10. Sample probes are recorded in `expected/render.json` for readability.
- **Stop conditions:** melt version mismatch; `frei0r.invert0r` or `frei0r.brightness` missing from the frei0r path; any check failing; wrong frame count or size; non-identical reruns. Any failure is `fail` or `partial`, and the record gets an entry with the observed numbers.
- **Expected failure modes:** a silent no-op if `FREI0R_PATH` is unset (caught by check 3, since `invert` would equal the input); a different frei0r build with other brightness rounding (absorbed only up to ±1).
- **Inspection:** after `--record`, build a contact sheet from the `output/` PNG conversions of the input, invert and brightness variants and look at it with Read.
- **Reproduction:** from `examples/frei0r-effect/`, run `./run.sh --record` then `./run.sh`. Outputs appear under `output/`.

## Observation, after running

- **Result:** pass. `./run.sh --record` passed every predeclared check and wrote `expected/render.json`; a separate `./run.sh` printed `OK`.
- **Executor and date:** 2026-11-24, Conors-MacBook-Pro-2.local, macOS 26.6 (Darwin 25.6.0) arm64.
- **Versions:** frei0r 3.7.1 (Homebrew `frei0r`), MLT 7.42.0 (`melt -version`; Homebrew `mlt` 7.42.0_1), Python 3.12.2. Node, Playwright and Chromium are not used. The FFmpeg 9.0.2 system build is not used.
- **Commands:** `FREI0R_PATH=$(brew --prefix)/lib/frei0r-1` set by `run.sh`; six variants, each rendered twice with `melt output/quad.ppm out=0 [filters] -consumer avformat:… f=rawvideo pix_fmt=rgba s=64x48 r=25`.
- **Measurements:**
  - Each variant is one 12288-byte 64×48 RGBA frame; reruns (`-a`/`-b`) are byte-identical for all six.
  - `control` and `invert2` equal the generated input exactly; `invert` equals `255 - v` exactly. Bottom-right `(128,64,32)` becomes `(127,191,223)`; top-left red becomes cyan `(0,255,255)`.
  - `brightness` 0.5 is the identity; 0.25 gives `(127,0,0)` for red and `(64,32,16)` for the bottom-right colour; 0.75 gives `(255,128,128)` for red and `(192,160,144)` for the bottom-right colour. Direction holds at every pixel and channel.
  - Alpha is 255 everywhere in every variant.
  - Output SHA-256 (`-a`): invert `169f3d7b…`, brightness 0.25 `ad80f9d0…`, 0.5 `8c2dc0ed…`, 0.75 `498cf3b9…`. The full set is in `expected/render.json`.
- **Inspection:** `output/contact.png` (1024×384; each tile is the 2×2 quadrant input at 400%, row 1: input, control, invert, invert2; row 2: brightness 0.25, 0.5, 0.75). The input shows four solid quadrants (red, green, blue, brown). Control and double invert reproduce them; invert shows cyan, magenta, yellow and light blue; brightness 0.25 darkens them and 0.75 lightens them towards white. Empty cells in the bottom-right are padding, not output. The picture matches the claim.
- **Limits:** exact values hold for this route and build, on an opaque RGB-derived input. The brightness check is ±1 against the formula, and it was not tested at other parameter values or animated. `invert0r` and `brightness` only; the other 105 frei0r plugins are unexercised. Silent no-op without `FREI0R_PATH` is a route-specific hazard; `run.sh` sets it.
- **What this establishes:** MLT's `frei0r.*` filters, when frei0r is found through `FREI0R_PATH`, apply the named plugins to a generated frame with the predeclared pixel values and parameter direction, and repeated renders on this host are byte-identical.
- **Does not establish:** GStreamer or direct frei0r host behaviour; other plugins; other platforms; colour conversion into video codecs; non-opaque input or alpha effects; keyframed parameters; plugin licence compliance.
- **Installs:** none. Existing Homebrew `frei0r` 3.7.1 and `mlt` 7.42.0_1 were used as installed; `pnpm install` ran in the worktree only.
