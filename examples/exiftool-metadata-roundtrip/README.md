# ExifTool metadata round trip

## Intent and scope

- Tool: ExifTool 13.50 (`/opt/homebrew/bin/exiftool`, Perl CLI). The catalogue card records `version_seen` 13.59; the installed build is 13.50, and that is the version this run exercises.
- Claim: exiftool writes predeclared XMP and EXIF fields (`XMP-dc:Title`, `XMP-dc:Rights`, `EXIF:Artist`) to a generated PNG and JPEG, reads them back as JSON exactly, and `-all=` removes them while decoded pixels stay identical.
- Exclusions: other formats (TIFF, HEIC, MP4, WAV), other XMP or EXIF fields, IPTC, MakerNotes, maker-specific writes, GPS, thumbnails, writing to a file in place of the original (only copies are edited), tool-to-tool agreement (no second metadata reader is compared), and any quality claim about the pixels beyond bitwise equality of the decoded RGBA samples.
- Documentation and licence: https://github.com/exiftool/exiftool (card); upstream README states the licence as "same terms as Perl itself (either the Perl Artistic License or GPL)". Card licence: GPL-3.0-or-later OR Artistic-1.0-Perl. Both checked 2026-11-24. No model, asset or font terms apply.
- Environment: macOS 26.6 arm64; ExifTool 13.50; ffmpeg 9.0.2 (decode only, and generation of the input); Python 3.12.2 for the checks.
- Input: generated by `run.sh` from ffmpeg's `testsrc` lavfi pattern, one frame, 64x48. The PNG is the source; the JPEG is re-encoded from it by ffmpeg at `-q:v 2`. No media is committed. The generator is deterministic; the pattern is a fixed synthetic test chart, not a photograph.
- Installation: none. ExifTool was already on PATH (Homebrew). Nothing is installed by this example, and no package is added to `package.json`.
- Output: ignored `output/` holds the input, the tagged copies, the stripped copies and the raw JSON read-backs. Only the summary in `expected/summary.json` is retained.

## Plan, before running

- Commands: `./run.sh --record` to write `expected/summary.json`, then inspect the output, then `./run.sh`, which must print `exiftool-metadata-roundtrip: OK`.
- Write, on a copy of each generated file: `exiftool -overwrite_original -XMP-dc:Title="VCR metadata fixture" -XMP-dc:Rights="CC0 fixture; no rights claimed" -EXIF:Artist="VCR fixture"`. Strip, on a second copy: `exiftool -overwrite_original -all=`.
- Predeclared checks, all of which must hold on every run:
  1. ExifTool version is exactly `13.50`.
  2. Input decodes to 64x48 RGBA: raw length is 12288 bytes.
  3. Read-back of the tagged file, `exiftool -j -XMP-dc:Title -XMP-dc:Rights -EXIF:Artist`, equals exactly `{Title, Rights, Artist}` with the three strings above, for both PNG and JPEG.
  4. Read-back of the stripped file for the same three tags is empty (only `SourceFile`).
  5. Stripped file, read with `exiftool -j -a -G1`, has no key in an XMP, EXIF, IFD0, IFD1 or ExifIFD group.
  6. The tagged and stripped files differ in bytes from their input, so the writes and the strip actually touched the file.
  7. SHA-256 of decoded RGBA samples (`ffmpeg -f rawvideo -pix_fmt rgba`) is identical for the original, tagged and stripped file, for each format.
- Expected failure modes and stop conditions: a read-back key missing or with a different string, any metadata key surviving `-all=`, or any pixel-hash difference. Each is a failure of the claim, not a reason to change the predeclared values. A PNG EXIF write failure would make this `partial` for PNG only, and the JPEG results would still count.
- Reproduce with `./run.sh`. Inspect by reading `output/readback-*.json` and `output/all-stripped-*.json`, or by viewing `output/input.png` and `output/tagged.png` (same picture expected).

## Observation, after running

- 2026-11-24, ExifTool 13.50, ffmpeg 9.0.2, Python 3.12.2, macOS 26.6 arm64, `Conors-MacBook-Pro-2.local`. Node v22.19.0 and pnpm 10.29.2 ran the workspace wrapper only; no browser, so no Playwright or Chromium version applies.
- `./run.sh --record` wrote `expected/summary.json`; a second `./run.sh` printed `exiftool-metadata-roundtrip: OK`.
- Read-back of the tagged PNG and JPEG returned exactly `Title` "VCR metadata fixture", `Rights` "CC0 fixture; no rights claimed", `Artist` "VCR fixture". Groups as reported by `-G1`: XMP-dc for Title and Rights, IFD0 for Artist.
- After `-all=`, both stripped files returned no predeclared tags, and no XMP, EXIF, IFD0, IFD1 or ExifIFD key appeared in `-a -G1` output.
- Decoded RGBA SHA-256 was identical for the original, tagged and stripped file in both formats: PNG `c71c1b5f...3e7f1`, JPEG `44dfe21a...dbe8a3`. Raw decoded length was 12288 bytes (64x48 RGBA). Tagged and stripped bytes differed from their inputs.
- Visual check: a contact sheet of input, tagged and stripped (rows PNG and JPEG) shows the same colour-bar test chart in all six panels, with no clipping or blank frames. The sheet was viewed at 800% from a point-filtered resize, kept outside the repository.
- Pass for the declared claim on PNG and JPEG with ExifTool 13.50. The catalogue card records `version_seen` 13.59; this run used the installed 13.50 build, so the claim is for 13.50 only.
- Not established: other formats (TIFF, HEIC, MP4, WAV), other fields, IPTC, MakerNotes, GPS, thumbnails, in-place edits of the user's own files, agreement with another metadata reader, or any Linux or Windows build. Input is a synthetic test chart, not a photograph.
- Deviation from the plan: the plan's `output/readback-*.json` paths were not written; read-back runs inside `check_output.py` and its results are in the checks, not in files.
- No side effects beyond `output/` (ignored) and `expected/summary.json`. No installation was performed.
