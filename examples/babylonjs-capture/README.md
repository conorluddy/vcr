# Babylon.js capture

## Intent and scope
Claim: Babylon.js 9.35.0 (`babylonjs` UMD build, global `BABYLON`) drawing a Scene with an ArcRotateCamera, a hemispheric and a directional light, and three MeshBuilder meshes (box, sphere, torus) with StandardMaterial, where every transform and the camera are set from `t` and rendered with one explicit `scene.render()` per seek, produces 90 transparent-background alpha PNG frames at 1280×720, 30 fps, with shuffled capture equal to sequential capture. Not claimed: `engine.runRenderLoop`, Babylon animations or observables, post-processing, PBR, glTF, physics, interaction, WebGPU, other browsers, other GPUs. Excluded features that reach unseeded randomness or clocks in the library build: particle systems, node geometry and node materials, procedural noise and random textures, grain and SSAO effects, and instance or sprite randomisation (`Math.random` call sites in `babylon.js`, 105 matches). Clock reads (`performance.now`, `Date.now`, `PrecisionDate`) occur in engine frame timing, logging and pointer handling; this scene uses none of them for pixels, which the shuffled-order check tests rather than assumes. Seeking: state is absolute per `t` (positions, rotations, camera angles assigned, never stepped), so a single-jump seek across any boundary matches a sequential run. Procedural original shapes only; no media, fonts or textures. Licence: Apache-2.0, bundled `license.md` in the installed package and npm metadata for `babylonjs@9.35.0` both read on 2026-11-11; docs https://doc.babylonjs.com/ and https://www.babylonjs.com/ (reachable 2026-11-11). Tool card `babylon-js` names `@babylonjs/core`; this fixture uses the pre-approved `babylonjs@9.35.0` UMD package instead, which the brief specifies. No codec, model or asset dependency.

## Plan, before running
On macOS arm64 with Node 22.19.0 and pnpm in this workspace, install `babylonjs` 9.35.0 pinned exactly in this example (pre-approved), reuse Playwright 1.64.1 and tsx 4.23.15 from the Konva template. Run `pnpm install`, then `examples/babylonjs-capture/run.sh --record`, visually inspect frame 45 at 1280×720 and the contact sheet, then `examples/babylonjs-capture/run.sh`. Engine options: `preserveDrawingBuffer: true`, `premultipliedAlpha: true` (Babylon default, correct for a (0,0,0,0) clear and opaque meshes), `antialias: false` for determinism, `alpha: true`, matching the WebGL alpha setup in `examples/three-capture` apart from antialiasing. Scene exposed through `executeWhenReady`, so no blank first frame. Record the Chromium version from the capture report.

Predeclared checks: 90 frames at 30 fps, 1280×720, at least two distinct frame hashes, every shuffled hash equal to its sequential hash, frame 45 alpha minimum 0 and maximum 1. Assert these before recording `expected/summary.json`. Stop on missing dependencies, a missing `BABYLON` global, blank or clipped output, or any mismatch; a mismatch is reported as partial or fail, never re-recorded. Intended consumer is the existing browser capture harness; units are seconds and pixels. Transparent PNG sequence only; no delivery byte budget, compression or cross-machine byte equality claimed. Outputs and reports in ignored `output/`; delete that directory to clean up. Expected failure modes: unseeded randomness in a material path, WebGL context loss, shader compile timing.

## Observation, after running

2026-11-11, evidence agent on Conors-MacBook-Pro-2.local, macOS Darwin 25.6.0 arm64, Node 22.19.0, babylonjs 9.35.0 (UMD `babylon.js`), Playwright 1.64.1, Chromium 156.0.8078.4, ImageMagick 7.1.2-15 Q16-HDRI. Screenshot capture route (default `captureMode`), WebGL2 backend with `preserveDrawingBuffer` and `premultipliedAlpha` true; GPU and driver not recorded and not claimed.

Both `run.sh --record` and `run.sh` exited 0; the second run printed `babylonjs-capture: OK`. Capture report: 90 frames, 1280×720, 30 fps, 90 distinct SHA-256 frame hashes, shuffled capture matched sequential for all 90 frames (`mismatched_frames` empty), 6016 ms wall time for the sequential pass. Frame 45 alpha min 0, max 1, so the background is transparent and meshes are opaque.

Visual inspection: `output/contact.png` (frames 0, 15, 30, 45, 60, 75 at 50%) shows the cyan box turning about its vertical axis, the orange sphere bobbing, the lime torus tumbling, and the ArcRotate camera orbiting. All three meshes are lit by the hemispheric and directional lights; edges are clean; nothing is clipped or blank. The viewer draws transparent pixels as white. The brief's `-flatten` step collapsed all six frames into one overlaid 1280×720 image, so the sheet was built without `-flatten`. Agent visual review only; no human approval claimed.

Result: pass for the stated claim: Babylon.js scene drawn from t with one explicit render per seek, deterministic across shuffled seeks, transparent alpha PNG output. Not established: `runRenderLoop`, Babylon animations, post effects, PBR, particles or node materials (excluded above), other GPUs or drivers, other browsers, WebGPU, byte-identical output across machines, or the `@babylonjs/core` package named on the tool card.
