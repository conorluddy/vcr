# libwebp lossless and animation fixture

## Intent and scope

- Tool ID and version/build: `libwebp` 1.6.0 tools (`cwebp`, `dwebp`, `img2webp`, `webpmux`), with libsharpyuv 0.4.2 reported by the binaries.
- VCR job and exact claim being tested: `cwebp -lossless` round-trips three generated RGBA PNG frames pixel-identically via `dwebp`, and `img2webp` assembles the same three PNG frames into an animated WebP whose frame count and per-frame durations `webpmux -info` reports as declared.
- Explicit exclusions: lossy encoding; `-exact` (transparent-pixel RGB is preserved here only because the generated transparent pixels are `0,0,0,0`); animation pixel round-trip beyond the frame count and durations; GIF input (`gif2webp`); alpha-quality or method tuning; other libwebp versions and platforms; semantic fidelity of any downstream viewer.
- Tool documentation and licence sources, checked 2026-11-24: [libwebp source](https://chromium.googlesource.com/webm/libwebp) (BSD-3-Clause, per the record) and the [v1.6.0 tag](https://chromium.googlesource.com/webm/libwebp/+/refs/tags/v1.6.0). Inputs are generated by this fixture with ImageMagick; no third-party media is used.
- Environment: macOS arm64 (Darwin 25.6.0); libwebp 1.6.0 from the existing Homebrew install on PATH; ImageMagick 7.1.2-35 Q16-HDRI for input generation and raw-pixel hashing.
- Input: three 64×64 RGBA PNG frames generated by `run.sh` with `magick`: a transparent `0,0,0,0` background, a half-transparent teal bar (alpha 128) and an opaque yellow square, placed at a different x offset per frame.
- Dependencies, installation plan, permissions, network and expected side effects: none installed. No network access. Writes only under ignored `output/`; `expected/metrics.json` is the only committed artefact.
- Selected workspace, generated output and cleanup paths: this example directory; `output/` (PNGs, WebP files, PAM decodes, info text) is ignored and can be deleted.

## Plan, before running

- Exact commands and versions:
  - `magick -size 64x64 xc:none ... output/frames/frame{0,1,2}.png` (fixed geometry, no randomness)
  - per frame: `cwebp -quiet -lossless frameN.png -o stillN.webp`, then `dwebp -quiet -pam stillN.webp -o stillN.pam`
  - `img2webp -loop 0 -lossless -d 100 frame0.png -d 250 frame1.png -d 400 frame2.png -o animation.webp`
  - `webpmux -info animation.webp`
  - Versions recorded: `cwebp -version`, `dwebp -version`, `img2webp -version`, `webpmux -version`, `magick -version`, `python3 --version`.
- Predeclared checks (all must hold for `pass`):
  1. Round-trip pixel identity, ×3 frames: SHA-256 of the raw 8-bit RGBA samples (`magick ... -depth 8 rgba:-`) of the decoded PAM equals the SHA-256 of the source PNG's raw RGBA samples.
  2. Alpha kept: the source frame 0 contains alpha values 0, 128 and 255; the decoded alpha channel is therefore identical by check 1, and the check script asserts the three values are present in the source.
  3. Still files keep alpha: `cwebp` exits 0 and `webpmux -info` on each still reports `Features present: transparency` and `Size of the image (with alpha)`. (Amended after the first `--record` attempt; see Observation.)
  4. Animation canvas 64×64, `Number of frames: 3`, feature line includes `animation` and `transparency`.
  5. Per-frame durations from the `webpmux -info` table are exactly `100, 250, 400` ms, in order.
  6. Repeatability: a second `img2webp` run is byte-identical to the first (`cmp`).
  7. Metrics (versions, hashes, durations, byte sizes) match `expected/metrics.json`, with the diff shown on mismatch.
- Expected artefacts: `output/animation.webp`, `output/stillN.webp`, `output/stillN.pam`, `output/webpmux-info.txt`, `output/metrics.json`.
- Intended consumer and handoff settings: standalone WebP stills and an animated WebP. The animation is inspected by coalescing its frames with ImageMagick for a visual check, not as a delivery target.
- Delivery constraints: none; no byte budget is claimed.
- Expected failure modes and stop conditions: a tool missing from PATH; a hash mismatch on any frame (stop: the round trip is not pixel-identical, so the claim fails); frame count or durations differing from the declaration (fail); non-deterministic img2webp output (partial, reported as such).
- Reproduction: `./run.sh --record` writes the baseline to `expected/metrics.json`; `./run.sh` must print `libwebp-lossless-animation: OK`. To inspect: `magick output/animation.webp -coalesce output/contact-frames.png` or open the `output/` files directly.
