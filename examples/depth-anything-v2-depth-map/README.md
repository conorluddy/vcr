# Depth Anything V2 (Small) depth map fixture

## Intent and scope

VCR job and claim: Depth-Anything-V2-Small, run through the Hugging Face
`transformers` depth-estimation pipeline on CPU, produces a relative depth map of
the same size as a synthetic scene with a receding floor and a near and a far
object. Predeclared: the near region scores nearer than the far region; the floor's
depth varies monotonically along the image's vertical axis for at least 90 % of
adjacent row pairs; and a rerun in a fresh process on CPU is identical or within a
predeclared tolerance.

Tool: Depth Anything V2, checkpoint `depth-anything/Depth-Anything-V2-Small-hf`
(the Small checkpoint only), loaded with `transformers==5.24.0`, `torch==2.15.0`.
Catalogue record: `catalog/tools/depth-anything-v2.json`.

Explicit exclusions:
- Only the Small checkpoint. Base, Large and Giant carry CC-BY-NC-4.0 terms and
  are not downloaded or run here.
- Only the transformers pipeline route. The upstream repository's own Python
  scripts, the Gradio demo and the metric-depth checkpoints are not tested.
- Relative depth only. No metric (absolute) depth, no scale or calibration claim.
- One synthetic still image. No photographs, no video or temporal consistency, no
  parallax render, no 2.5D move built from the map.
- The direction "larger value = nearer" is the upstream convention for relative
  inverse depth (disparity). It is what the ordering check tests on this scene; it
  is not a general accuracy claim.
- The monotonicity check and region fractions are fixture parameters for this one
  scene. They are not a general quality threshold.
- Rerun identity is observed on this machine (macOS arm64, torch CPU wheel) only.
  Not a cross-machine, GPU or MPS claim.

Licence and documentation sources, checked 2026-11-24:
- Model card `https://huggingface.co/depth-anything/Depth-Anything-V2-Small-hf`,
  YAML `license: apache-2.0`. Weights are downloaded, not redistributed here.
- Upstream code and paper: `https://github.com/DepthAnything/Depth-Anything-V2`
  (paper arXiv 2406.09414). Not used as code in this fixture; the weights come from
  the Hugging Face checkpoint above.
- Base/Large/Giant checkpoints: CC-BY-NC-4.0 per the catalogue record. Excluded.
- transformers, torch, numpy, Pillow keep their own licences (Apache-2.0, BSD-style);
  not redistributed.

Environment: macOS 26.6 (Darwin 25.6.0), arm64, Python 3.12.13 from
`/opt/homebrew/bin/python3.12` (the pyenv 3.12.2 build lacks `_lzma`, as in the
rembg fixture), torch CPU execution. No GPU, no MPS.

Input: generated by `generate.py` from procedural maths only (no randomness, no
external asset, no third-party rights). Input PNG sha256 is recorded in `expected/`.

Dependencies and installation plan (approved by the launching agent):

  `output/venv/bin/pip install -r requirements.txt` (pins: torch 2.15.0,

## Plan, before running

Commands (after the install above):
```
examples/depth-anything-v2-depth-map/run.sh            # generate, infer twice, check, diff expected/
examples/depth-anything-v2-depth-map/run.sh --record   # only after a deliberate change
```

Scene (`generate.py`, 640 x 480 RGB PNG, no randomness):
- Sky above the horizon at y = 200: flat light blue.
- Floor below the horizon: a plane one unit below a pinhole camera with focal length
  400 px. A pixel at row y (pixel centre y + 0.5) lies on the floor at distance
  Z = 400 / (y + 0.5 - 200). Floor texture: checkerboard in world units, cell size
  0.5, colours light grey (200) and dark grey (120). Rendered at 4 x 4 supersampling
  and box-filtered, so the far rows are not aliased.
- Near object: flat red disc, centre (150, 370), radius 60 px, drawn over the floor.
- Far object: flat blue disc, centre (500, 214), radius 12 px, drawn over the floor.
- Predeclared regions (pixel centres): near region is distance <= 36 px from (150, 370);
  far region is distance <= 6 px from (500, 214).
- Predeclared floor band: rows 210 to 470 inclusive, columns 300 to 340 inclusive.
  No object lies in this band.

Pipeline (`infer.py`, one process per run): `pipeline("depth-estimation",
model="depth-anything/Depth-Anything-V2-Small-hf", device="cpu")` on the scene PNG.
The pipeline's `predicted_depth` (float32, resized by transformers to the input size) is
saved as `output/depth-run-<n>.npy`, and a min-max normalised 8-bit grey PNG is saved as
`output/depth-run-<n>.png` for inspection. Run 1 and run 2 are separate processes.

Predeclared checks (`check.py`; all gating; parameters are fixture parameters):
1. Input is a PNG, mode RGB, 640 x 480.
2. Output dimensions: the depth array has shape (480, 640) and dtype float32.
3. Ordering: the median depth over the near region is greater than the median over the
   far region (larger = nearer).
4. Floor monotonicity: for the floor band, the per-row mean is computed. The fraction of
   adjacent row pairs (r, r+1), r in 210..469, where mean(r+1) >= mean(r) is at least
   0.90, AND mean(470) > mean(210).
5. Non-degenerate output: max minus min of the depth array is greater than 0.
6. Rerun: run 2 (fresh process) differs from run 1 by a maximum absolute difference of at
   most 0.1 % of run 1's range (max minus min). Byte identity of the arrays is recorded.
7. Hashes: the input PNG sha256, the run-1 depth-grey PNG sha256 and the run-2 depth-grey
   PNG sha256 are recorded; at least two distinct values among them.
8. Frame count: one still per run. Shuffled-order check: not applicable, there is no seek.

Result rules (predeclared):
- pass: checks 1 to 8 all true.
- partial: only check 4 (monotonicity) fails, with checks 3, 5 and 6 true; the scope names
  the fraction measured.
- fail: any other check fails (including a reversed ordering in check 3).
- blocked: install or model download fails, so no depth map is produced.

Expected failure modes and stop conditions:
- Install, import or model download failure, or a non-zero exit from `infer.py`: stop,
  keep logs, report blocked.
- Any gating check failing: `check.py` exits 1 and `run.sh` stops; `--record` is never
  run on a failure, and the baseline is not rewritten to hide it.
- Nondeterminism is not a failure by itself: if run 2 differs beyond the tolerance, the
  result is fail and the observation says so.

Inspection: `output/checks.json` lists every measured value. A contact sheet (input and
depth-grey side by side) is made with `magick` outside `run.sh`, as the rembg fixture
does. It is inspection only, not a gating check; `magick` is not listed in `example.json`
because `run.sh` does not call it.

## Observation, after running

Executed 2026-11-24 on Conors-MacBook-Pro-2.local (macOS 26.6, Darwin 25.6.0, arm64),
from `examples/depth-anything-v2-depth-map`. Commands: `./run.sh --record` (exit 0, wrote
`expected/checks.json`), then `./run.sh`, which printed `depth-anything-v2-depth-map: OK`.

Versions (as run):
- Depth Anything V2 Small, Hugging Face checkpoint `depth-anything/Depth-Anything-V2-Small-hf`
  at Hub commit `5426e4f0f36572d16453bbda7a8389317b1bef99` (`refs/main` in the cache).
  `model.safetensors` 99,173,660 bytes, sha256
  `3152477ce0d8d6978d76b995120de97cb5b928701fd0f817769f59e249a16b70` (equal to the Hub's
  LFS etag). Licence on the card: apache-2.0.
- transformers 5.24.0, torch 2.15.0 (default macOS arm64 wheel, CPU device), numpy 2.5.5,
  pillow 13.0.0, safetensors 0.8.0, tokenizers 0.23.3, huggingface_hub 2.4.0. Full freeze in
  `output/dependencies.txt` (ignored).
- Python 3.12.13 from `/opt/homebrew/bin/python3.12`; venv `output/venv` (about 980 MB).
- Playwright, Chromium, Node, blender, rembg: not used by this fixture.
- Weights cache: `output/cache` (about 95 MiB, ignored). Not committed.

Input: `output/scene.png`, 640 x 480 RGB PNG, sha256
`6182d5ce7af76fe5c9e48a8d03b995d40e7781fec36eef405c0532481810bac9`. Made by `generate.py`
(procedural, no randomness). I inspected it before running the model: a receding checkerboard
floor, a red disc at the left foreground and a blue disc near the horizon, as planned.

Measured (from `output/checks.json`; identical in the record and verify runs):
- Output shape (480, 640), float32, same as input. Check 2 true.
- Near region (disc radius 36 px about (150, 370)) median 9.1815; far region (radius 6 px about
  (500, 214)) median 0.9429. Near is greater, so the ordering is correct. Check 3 true.
- Floor band (rows 210 to 470, columns 300 to 340): all 260 adjacent row pairs were
  non-decreasing toward the bottom (fraction 1.0, floor 0.90). Row mean rose from 0.4007
  (row 210) to 8.6280 (row 470). Check 4 true.
- Depth range 9.2812, so non-degenerate. Check 5 true.
- Rerun in a fresh process: byte-identical arrays, maximum absolute difference 0.0 (tolerance
  0.0093). Check 6 true.
- Hashes: depth grey preview sha256 `1f6bca524b73896979b3c96b860160f923ef421c70953f00cf72b0ecdbddb801`
  in both runs, distinct from the input hash. Check 7 true.
- Frame count: one still, two runs. Check 8 true (not a measurement).
- All checks true; the predeclared rule gives pass.

Inspection: `output/contact.png` is input (left) beside the min-max normalised depth map (right),
made with `magick` (`magick \( scene.png depth-run-1.png +append +repage \) -background '#808080' -flatten contact.png`).
A first attempt without the parentheses flattened the two images on top of each other and
was discarded. What the depth map shows: the red disc is bright (nearest), the floor brightens
steadily from the horizon down to the bottom edge, the sky and horizon are black (farthest),
and the blue disc is only faintly visible, a slightly lighter spot against the dark floor
behind it.

Limitation seen in the inspection: the far disc is barely separated from the floor around it.
Its median is 0.9429, against 0.765 on the floor beside it at row 214 (columns 480 to 520) and
0.524 at row 214 in the floor band. The ordering check passes because the near disc is far
brighter (9.18) than everything else, not because the model picks out the far object. The
claim as written is about the near and far regions, and the result supports that, but the
far object is not a strong depth cue in this output.

Deviations from the plan, recorded rather than silently edited above:
1. Python: the plan named `/opt/homebrew/bin/python3.12`, which is what was used; the pyenv
   3.12.2 interpreter was not tried because it is known to lack `_lzma` (as in the rembg fixture).
2. `generate.py` first had a row/column broadcasting bug in the floor supersampling. It was
   rewritten before any run; the scene in the observation is from the corrected code.
3. The first contact-sheet command omitted the parentheses (see above); the sheet was rebuilt
   before inspection.

Not established: Base/Large checkpoints; metric depth; video or temporal consistency; other
hardware (GPU, MPS, other CPUs) or other torch/transformers versions; accuracy against a
ground-truth depth beyond the ordering and monotone checks on this one scene; the far object's
depth beyond the ordering with the near region.

Reviewer and follow-up: revisit if the checkpoint commit changes, if transformers or torch is
bumped, or if the floor check fails on another machine. The rerun tolerance is 0.1 % of the
depth range for this scene only.
