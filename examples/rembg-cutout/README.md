# rembg background removal fixture

## Intent and scope

VCR job and claim: rembg removes the background from a generated test image
(a shaded sphere composited over a busy patterned background) and writes an
RGBA PNG of the same size. Predeclared: the subject region is mostly opaque,
the background region is mostly transparent, the alpha mask's IoU against the
analytic ground-truth disc is at or above a floor, and a rerun in a fresh
process is byte-identical (or within a per-channel tolerance).

Tool: rembg, Python package `rembg[cpu]` from PyPI, pinned `2.0.85`
(the version the catalogue assessment saw, 2026-11-15). PyPI also lists
`2.0.86` and `2.0.87`; they are not used here.

Explicit exclusions:
- Only the default `u2net` model through the library API (`new_session`,
  `remove`). Other models (isnet, birefnet, sam, ...), remote-API backends,
  the CLI route, `alpha_matting`, `post_process_mask`, `only_mask` and `bgcolor`
  options are not tested.
- One synthetic still image only. No photographs, no transparent or hairy
  subjects, no fine edges, no video or frame sequences.
- The IoU floor and the region fractions are fixture parameters for this one
  scene. They are not a general quality threshold for background removal.
- No semantic claim about what the model "understood" beyond this scene's mask.
- Byte identity is observed on this machine (onnxruntime CPU, arm64) only.
  Not a cross-machine, cross-onnxruntime or GPU-provider claim.
- Only the CPU onnxruntime provider; no CoreML or CUDA.

Licence and documentation sources, checked 2026-11-24:
- rembg code: https://github.com/danielgatis/rembg `LICENSE.txt`, MIT
  (Copyright 2020 Daniel Gatis). PyPI metadata for 2.0.85 also reports MIT.
- u2net weights (`u2net.onnx`, fetched by rembg from its GitHub release
  `v0.0.0` on first use): U-2-Net project https://github.com/xuebinqin/U-2-Net,
  `LICENSE` is Apache-2.0. Weights are downloaded, not redistributed here.
  This fixture does not commit or redistribute any model file.
- onnxruntime and the other dependencies keep their own licences; not redistributed.

Environment: macOS 26.6 (Darwin 25.6.0), arm64, Python 3.12.2 from pyenv,
onnxruntime CPU execution provider. No GPU.

Input: generated by `generate.py` from procedural maths only (no randomness, no
external asset, no third-party rights). The input is written to `output/scene.png`
and its sha256 is measured by `check.py`.

Dependencies and installation plan (approved by the launching agent):
- Create `examples/rembg-cutout/output/venv` (git-ignored) with the pyenv Python 3.12.2.
- `output/venv/bin/pip install "rembg[cpu]==2.0.85"`. pip resolves transitive
  dependencies from PyPI; the resolved set is written to `output/dependencies.txt`
  by `run.sh`.
- Model: the first `new_session("u2net")` downloads `u2net.onnx` to `~/.u2net/`
  (the default rembg cache, outside the repository; kept on purpose, as the user
  asked). Its size and sha256 are recorded in the observation below.
- Network: PyPI for installation; GitHub releases for the model, on first use only.
- Nothing system-wide; no global package or shell change.
- Cleanup: remove `examples/rembg-cutout/output` (venv, logs, PNGs). The model
  cache `~/.u2net/` is left in place.

Selected workspace and output: `examples/rembg-cutout/output/` (git-ignored).
Committed: this README, `example.json`, `run.sh`, `generate.py`, `cutout.py`,
`check.py`, `expected/checks.json`. No PNG, model or venv is committed.

## Plan, before running

Commands (after the install above):
```
examples/rembg-cutout/run.sh            # generate, cut out twice, check, diff expected/
examples/rembg-cutout/run.sh --record   # only after a deliberate change
```

Scene (`generate.py`, 512 x 512 RGB PNG, no randomness):
- Sphere centred at (256, 256), radius 120 px, orange base colour, Lambert shading from
  a fixed upper-left light, plus a specular term. Hard, unantialiased edge.
- Background: 24 px checkerboard cells cycling through six saturated colours (red, blue,
  yellow, green, purple, white), each modulated by a fixed sine of x and y. Busy by design.
- Predeclared regions, in pixels from the centre: subject region is distance <= 96 px
  (0.8 radius); background region is distance >= 150 px (1.25 radius). Ground truth is
  distance <= 120 px. Pixel centres are used (x + 0.5).

Pipeline: `cutout.py` runs in its own process per output, with a fresh
`new_session("u2net")` and `remove(bytes)`. `cutout.py` writes `cutout.png` and
`cutout-rerun.png`.

Predeclared checks (`check.py`; all gating; the parameters are fixture parameters):
1. Output is a PNG in mode RGBA with the same width and height as the input.
2. Subject region: fraction of pixels with alpha >= 128 is >= 0.90.
3. Background region: fraction of pixels with alpha < 128 is >= 0.90.
4. IoU of (alpha >= 128) against the analytic disc (distance <= 120 px) is >= 0.90.
5. Rerun: the two cutout PNGs are byte-identical; if not, the maximum per-channel
   difference over all RGBA values is <= 2.
6. Hashes: the cutout sha256 differs from the input sha256 (the background was removed,
   not passed through). Input and cutout hashes are recorded.
7. Frame count: one still per run (no sequence). Shuffled-order check: not applicable,
   there is no seek.

Result rules (predeclared):
- pass: checks 1 to 6 all true.
- partial: only check 4 (IoU) fails, with checks 2, 3 and 5 true; the scope names the IoU.
- fail: any other check fails.
- blocked: install or model download fails, so no cutout is produced.

Expected failure modes and stop conditions:
- Install or import failure, model download failure, or a non-zero exit from `cutout.py`:
  stop, keep logs, report blocked.
- Any gating check failing: `check.py` exits 1 and `run.sh` stops; `--record` is never
  run on a failure, and the baseline is not rewritten to hide it.
- A non-identical rerun within tolerance is not a failure; it is recorded and the scope
  will not claim byte identity.

Inspection: `output/checks.json` lists every measured value. The contact sheet (input,
alpha, cutout over a grey background) is made with `magick` outside `run.sh`, as the
template does; it is inspection only, not a gating check.

## Observation, after running

Executed 2026-11-24 on Conors-MacBook-Pro-2.local (macOS 26.6, Darwin 25.6.0, arm64),
from `examples/rembg-cutout`.

Versions (as run):
- rembg 2.0.85 (`rembg[cpu]==2.0.85`, PyPI, MIT).
- onnxruntime 1.32.0 (CPU provider), numpy 2.5.5, Pillow 12.3.0, scikit-image 0.26.0,
  pooch 1.9.0, pymatting 1.1.16 (pulled in by rembg). Full freeze in `output/dependencies.txt` (ignored).
- Python 3.12.13 from `/opt/homebrew/bin/python3.12`, used to build `output/venv`.
- Node v22.19.0 (present; not used by this fixture). Playwright and Chromium: not used.
- Model: `u2net.onnx`, default rembg model, 175997641 bytes (about 168 MiB),
  sha256 `8d10d2f3bb75ae3b6d527c77944fc5e7dcd94b29809d47a739a7a728a912b491`.

Deviations from the plan, recorded rather than silently edited above:
1. Python. The pinned plan named the pyenv Python 3.12.2. That build lacks `_lzma`, so
   `import rembg` failed at `pooch` (`ModuleNotFoundError: No module named '_lzma'`).
   No new interpreter was downloaded. The venv was rebuilt from the existing
   Homebrew `python3.12` (3.12.13, lzma present) with the same pinned rembg. The first
   failing attempt produced no expected file and no cutout.
2. Model location. The plan said `~/.u2net/`. rembg 2.0.85 caches the model at
   `~/.rembg/models/u2net/u2net.onnx` (`~/.u2net/` was never created). That is the
   default cache, left in place as the user asked.

Commands: `./run.sh --record` (exit 0, wrote `expected/checks.json`), then `./run.sh`,
which printed `rembg-cutout: OK`.

Measured (from `output/checks.json`; identical in the record and verify runs):
- Input: 512 x 512 RGB PNG, sha256 `e93c8e88ab0e241566aaa3a384bbaebfb90cabb888930f5e5625c85b7b00ce0b`.
- Cutout: 512 x 512 RGBA PNG, sha256 `3630315ff3e555d8b326d80fbe7392398442e5e1c5ab323c288145ebeba8a934`.
- Subject region (distance <= 96 px): opaque fraction 1.0 (floor 0.90).
- Background region (distance >= 150 px): transparent fraction 1.0 (floor 0.90).
- IoU of alpha >= 128 against the analytic disc (radius 120 px): 0.995783
  (45151 opaque pixels; 45244 ground-truth pixels; floor 0.90).
- Rerun in a fresh process: byte-identical (same sha256), max channel difference 0.
- All seven checks true; the result rule gives pass.

Inspection: `output/contact.png` (scene, cutout over blue, alpha) shows the busy checker
background behind the sphere, a clean orange sphere with its highlight over flat blue,
and a solid white disc in the alpha. No clipping, no halo, no residual checker pixels
were visible at display scale. The alpha is hard-edged, which fits the hard ground truth.

Pass, on the predeclared checks, for this one generated scene: the default u2net
library route, run twice in separate processes, removes the background of a shaded
sphere over a busy pattern to an RGBA PNG of the same size, with IoU 0.996 against the
analytic disc, and the reruns are byte-identical on this machine.

What this does not establish: other rembg models (isnet, birefnet, sam, ...), the CLI,
alpha matting or post-processing options, photographs, transparent, hairy or
fine-edged subjects, video or sequences, behaviour on other platforms, onnxruntime
versions or GPU providers, or cross-machine byte identity. The subject is a
high-contrast sphere with a clean edge, which is the easy case for a salient-object
model; the IoU is evidence for this scene only. The floors are fixture parameters and
not a quality bar for background removal.

Reviewer, follow-up and revisit triggers: revisit on any rembg upgrade (2.0.86 and 2.0.87
exist on PyPI and are not tested), any change to the u2net file hash above, an
onnxruntime upgrade (the cutout hash may change while the checks still pass), or a
platform change. The model is downloaded on first use, not committed.
