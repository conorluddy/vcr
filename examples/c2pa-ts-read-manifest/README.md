# c2pa-ts reads a c2patool-signed PNG

## Intent and scope

- **Tool/version:** `@trustnxt/c2pa-ts` 0.14.1 (pinned exactly), plus `reflect-metadata` 0.2.2 which c2pa-ts needs under Node.
- **VCR job and claim:** in Node, c2pa-ts reads the active manifest of a PNG that c2patool signed with its built-in development signer, returns the declared title, claim generator name and version, and the exact `org.contentauth.test` payload, validates it (`isValid`, `claimSignature.validated`), and reports the signer as untrusted as c2patool does.
- **Exclusions:** signing, other formats, browser use, trusted signers, truth of the assertions, byte reproducibility of signed output.
- **Documentation and licence:** https://github.com/TrustNXT/c2pa-ts README; Apache-2.0 (npm tarball), checked 2026-11-27.
- **Input:** `fixture/signed.png.base64` (base64 text, since sources may not hold media; decoded in memory), 64x48 RGB, generated by `examples/c2patool-test-signer` (c2patool 0.29.0 built-in test signer) from a Python-generated solid image; our own output, no third-party asset, no private key (the test credential is compiled into c2patool). Committed so the run needs no c2patool.
- **Dependencies, side effects:** two exact npm dependencies in this example; no network at run time, writes only `output/`.

## Plan, before running

- **Commands:** `pnpm install`, `examples/c2pa-ts-read-manifest/run.sh --record`, then `run.sh`. `run.mjs` runs twice in separate processes and the outputs are diffed.
- **Predeclared checks:** (1) installed version 0.14.1; (2) title `VCR c2patool fixture`; (3) claim generator `VCRFixture` `1.0`; (4) custom assertion data equals `{claim: "local test asset only", fixture: "c2patool-test-signer"}`; (5) `isValid` true and `claimSignature.validated` present; (6) status codes contain `signingCredential.untrusted`, matching c2patool's readback of the same file.
- **Stop conditions:** a failure of 1 to 5 gives `fail`. A failure of 6 alone gives `partial`, printed as `KNOWN FAIL`; the check is not loosened.
- **Expected artifacts:** `expected/metrics.json`.

## Observation, after running

- 2026-11-27, Conors-MacBook-Pro-2.local, macOS arm64, Node 22.19.0, pnpm 10.29.2. Record and two further runs identical.
- Checks 1 to 5 passed. The custom assertion has no typed class (`UnknownAssertion`, no `data`); its payload was read from the CBOR box in `assertion.sourceBox.contentBoxes`.
- Check 6 failed: c2pa-ts emitted `signingCredential.trusted` (success) for a signer c2patool reports as untrusted. c2pa-ts documents chain-of-trust validation as not implemented, so its trust code must not be read as a trust verdict. Recorded as `signerReportedUntrusted: false`.
- Result: **partial**. Fixture file SHA-256 `f67bbeee...6f9` (full value in `expected/metrics.json`).
- Without `import "reflect-metadata"` first, c2pa-ts fails at import with "tsyringe requires a reflect polyfill".
