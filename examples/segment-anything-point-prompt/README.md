# Segment Anything (ViT-B) point and box prompt fixture

## Intent and scope

VCR job and claim: Segment Anything, ViT-B checkpoint `facebook/sam-vit-base`, run through the
Hugging Face `transformers` `SamModel` / `SamProcessor` on CPU, returns a mask for each object in
a generated two-object still when given one positive point prompt per object, and a mask when
given a box prompt. Predeclared: each point-prompt mask's IoU with its object's analytic
ground truth is at or above 0.90; the mask excludes the other object (at most 1 % of its pixels
fall on the other object); the box-prompt masks meet the same IoU floor; the masks have the
input's height and width; the disc cutout's alpha is a binary matte with an opaque fraction in
a predeclared range; and a rerun in a fresh process on CPU is identical or within a predeclared
pixel tolerance.

Tool: Segment Anything, catalogue record `catalog/tools/segment-anything.json`. Model:
`facebook/sam-vit-base`, pinned to revision `70c1a07f894ebb5b307fd9eaaee97b9dfc16068f` (checked
2026-11-24). Libraries: `transformers==5.24.0`, `torch==2.15.0` (CPU on macOS arm64).

Explicit exclusions:
- Only the ViT-B checkpoint. ViT-L and ViT-H are not downloaded or run.
- Only the transformers route. The upstream `segment_anything` package, its automatic mask
  generator, its ONNX export and its web demo are not tested.
- Only one positive point per object and one box per object. No negative points, no multi-point
  prompts, no mask-input refinement, no iterative prompting.
- Only the three-candidate multimask output, with the candidate ranked highest by SAM's own
  predicted IoU score. The other two candidates are not checked.
- One synthetic still image. No photographs, no video or temporal consistency, no seek, no frame
  sequences.
- The IoU floor, leak limit, opaque fraction range and rerun tolerance are fixture parameters for
  this one scene. They are not a general quality threshold for segmentation.
- Image treatment: the background texture and the disc shading are procedural and fixed. Image
  treatment is a pillar; see FX-MASK-EDGE below. Only the mask-edge rule is cited; this fixture
  makes no feathering or matte-quality claim.
- Rerun identity is observed on this machine (macOS arm64, torch CPU wheel) only. Not a
  cross-machine, GPU or MPS claim.
- The disc cutout is only the alpha range check; it is not a compositing or colour-spill claim.

FX-MASK citations (image treatment pillar, cited here only): `FX-MASK-EDGE` (`references/fx/fx-knowledge-base.md`,
section 3): feather scales to output resolution and does not animate unkeyed. This fixture writes
binary masks with hard edges and no feather, so the edge rule is not exercised; the cutout's alpha
is measured as binary only.

## Plan, before running

Commands (after the install above):
```
examples/segment-anything-point-prompt/run.sh            # generate, segment twice, check, diff expected/
examples/segment-anything-point-prompt/run.sh --record   # only after a deliberate change
```

Scene (`generate.py`, 512 x 512 RGB PNG, no randomness):
- Background: a grey-green field with a diagonal sine texture and a 32 px grid of darker lines.
- Object 1, disc: centre (160, 176), radius 80 px, base colour red, Lambert shading from a fixed
  upper-left light plus a specular term. Hard, unantialiased edge.
- Object 2, square: pixel-centre region x in [284, 420] and y in [268, 404] inclusive, flat blue
  with a vertical brightness gradient. Hard edge.
- Ground truth: disc = pixel centres within 80 px of (160, 176); square = pixel centres in the
  rectangle above. The two objects do not overlap.
- Prompts (sent one at a time, each its own forward pass):
  - point: positive point at each object's centre, disc (160, 176), square (352, 336).
  - box: disc (72, 88, 248, 264); square (276, 260, 428, 412), `xyxy` pixel coordinates.
- Mask selection: among SAM's three multimask candidates, the candidate with the highest
  `iou_scores` is kept. Rule fixed before running.

Pipeline (`segment.py`, one process per run): `SamModel.from_pretrained("facebook/sam-vit-base",
revision=...)` and `SamProcessor` on CPU, eval mode, `torch.no_grad()`. Masks are post-processed
to the input's original size with `image_processor.post_process_masks`, binarised, and written as
8-bit PNGs (0 or 255). The disc-point mask also becomes `disc-cutout.png`, RGBA, RGB from the
scene with alpha = that mask. Run 1 and run 2 are separate processes into `output/run-1` and
`output/run-2`.

Predeclared checks (`check.py`; all gating; the parameters are fixture parameters):
1. Input is a PNG, mode RGB, 512 x 512.
2. Mask shape: every mask PNG (4 prompt masks) is mode L, 512 x 512 (the input's height and width).
3. Binary masks: every mask pixel value is 0 or 255.
4. Point-prompt IoU: for each object, IoU(point-prompt mask, ground truth) >= 0.90.
5. Box-prompt IoU: for each object, IoU(box-prompt mask, ground truth) >= 0.90.
6. Exclusion: for each mask, the fraction of its pixels that lie on the other object's ground truth
   is <= 0.01.
7. Alpha range on the disc cutout (the middle-frame analogue for a still): alpha min = 0, max = 255,
   and the opaque fraction (alpha == 255 over all pixels) is in [0.05, 0.10].
8. Rerun: for each of the four masks, run 2 differs from run 1 on at most 0.1 % of pixels
   (0.001 fraction). Byte identity is recorded, not required.
9. Hashes: input sha256, the four mask sha256s and the cutout sha256 are recorded; at least two
   distinct values.
10. Frame count: one still per run (four masks plus one cutout). Shuffled-order check: not
    applicable, there is no seek.

Result rules (predeclared):
- pass: checks 1 to 10 all true.
- partial: checks 1, 2, 3, 6, 7, 8, 9, 10 true, and at least one of checks 4 or 5 fails; the scope
  names which IoU fell below the floor and its measured value.
- fail: any other check fails (including exclusion, shape, binary-mask or rerun failures).
- blocked: install or model download fails, so no mask is produced.

Expected failure modes and stop conditions:
- Install or import failure, model download failure, or a non-zero exit from `segment.py`: stop,
  keep logs, report blocked.
- Any gating check failing: `check.py` exits 1 and `run.sh` stops; `--record` is never run on a
  failure, and the baseline is not rewritten to hide it.
- A non-identical rerun within the tolerance is not a failure; it is recorded and the scope will
  not claim byte identity.
- If the transformers SAM output shape differs from `(1, 1, 3, 256, 256)` for the low-res logits,
  stop and report; do not change the mask-selection rule to fit.

Inspection: `output/checks.json` lists every measured value. The contact sheet (input, the four
masks as overlays, the disc cutout over a grey background) is made with `magick` outside
`run.sh`, as the template does; it is inspection only, not a gating check.

What this establishes: on this machine, with this checkpoint and the transformers route, a single
positive point or a single box on each of two synthetic shapes gives a mask at or above the IoU floor,
not leaking onto the other shape, at the input size, and re-running in a fresh process reproduces the
masks exactly.

What it does not establish: any quality on photographs, soft or hairy edges, occluded or overlapping
objects, negative prompts, multi-point prompts, the other two SAM candidates, ViT-L or ViT-H, the
upstream `segment_anything` package, GPU or MPS, or identical results on another machine or torch
build. The objects here have hard, clean edges and high contrast against the background, which makes
an IoU near 1.0 easy; the floor is not a general quality threshold.

Reviewer, decision, follow-up and invalidation triggers: a change in `facebook/sam-vit-base` revision,
transformers or torch pins, or the scene parameters in `generate.py` invalidates the `expected/` baseline
and requires a fresh `--record` with a new review. Recorded for the catalogue as the segment-anything
evidence entry; no adapter or skill is implied.
