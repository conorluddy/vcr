# Exiv2 metadata round trip

## Intent and scope

- Tool: Exiv2 0.28.9 (`/opt/homebrew/bin/exiv2`, Homebrew, C++ CLI). The catalogue card records `version_seen` as "Current repository README; release version/date not confirmed". The installed build is 0.28.9, and that is the version this run exercises.
- VCR job and claim: exiv2 writes predeclared XMP-dc Title and Rights, EXIF Artist and IPTC Caption to a generated JPEG through a command file (`exiv2 -m cmd.txt mo`); `exiv2 -pa` reads them back exactly; `exiv2 rm` strips them; decoded pixels are unchanged throughout; and exiftool 13.50 (already installed) reads the exiv2-written tags with the same values (cross-tool agreement).
- What this adds beyond `exiftool-metadata-roundtrip`: IPTC Caption, the exiv2 writer and reader, and the cross-tool read of exiv2-written tags. The exiftool fixture covered neither IPTC nor any other tool's writes.
- Exclusions: PNG (only JPEG is claimed); other XMP, EXIF and IPTC fields; MakerNotes, GPS and thumbnails; the exiv2 actions other than `mo`, `pr` (`-pa`) and `rm` (for example `in`, `ex`, `ad`, `mv`); the C++ library API; other output formats; reading by any third tool beyond exiftool; any Linux or Windows build; quality beyond bitwise equality of decoded RGBA samples; and edits to the user's own files (only generated copies are edited).
- Documentation and licence: https://github.com/Exiv2/exiv2 (card). The card licence is GPL-2.0-or-later. The installed binary prints the GPL banner "either version 2 of the License, or (at your option) any later version", read on 2026-11-24. The upstream README was not re-fetched in this run. No model, asset or font terms apply.
- Environment: macOS 26.6 arm64; Exiv2 0.28.9; exiftool 13.50; ffmpeg 9.0.2 (generates the input and decodes for the pixel check); Python 3.12.2 for the checks.
- Input: generated by `run.sh` from ffmpeg's `testsrc` lavfi pattern, one frame, 64x48, then re-encoded to JPEG at `-q:v 2`. No media is committed. The pattern is a fixed synthetic test chart, not a photograph.
- Installation: none. Exiv2 was already installed via Homebrew. Nothing is added to any `package.json`.
- Output: ignored `output/` holds the input, the tagged copy, the stripped copy and the command file. Only the summary in `expected/summary.json` is retained.

## Plan, before running

- Commands: `./run.sh --record` writes `expected/summary.json`; inspect the output; then `./run.sh`, which must print `exiv2-metadata-roundtrip: OK`.
- Command file (`output/cmd.txt`, written by `run.sh`):
  - `set Xmp.dc.title LangAlt lang="x-default" VCR metadata fixture`
  - `set Xmp.dc.rights LangAlt lang="x-default" CC0 fixture; no rights claimed`
  - `set Exif.Image.Artist Ascii VCR fixture`
  - `set Iptc.Application2.Caption String VCR caption fixture`
- Write: `exiv2 -m output/cmd.txt mo output/tagged.jpg` on a copy. Strip: `exiv2 rm output/stripped.jpg` on a second copy.
- Read-back: `exiv2 -pa` on the tagged copy. Each predeclared key must appear once. The `lang="x-default" ` prefix on LangAlt values is removed before comparison; no other normalisation.
- Cross-tool read: `exiftool -j -XMP-dc:Title -XMP-dc:Rights -EXIF:Artist -IPTC:Caption-Abstract` on the tagged copy.
- Predeclared checks, all of which must hold on every run:
  1. Exiv2 version is exactly `0.28.9` (first line of `exiv2 --version`).
  2. ExifTool version is exactly `13.50`.
  3. Input decodes to 64x48 RGBA: 12288 bytes.
  4. `exiv2 -m ... mo` and `exiv2 rm` each exit 0.
  5. `exiv2 -pa` on the tagged JPEG gives exactly `Xmp.dc.title` = "VCR metadata fixture", `Xmp.dc.rights` = "CC0 fixture; no rights claimed", `Exif.Image.Artist` = "VCR fixture", `Iptc.Application2.Caption` = "VCR caption fixture".
  6. exiftool on the tagged JPEG reads exactly `{Title, Rights, Artist, Caption-Abstract}` with the same four strings.
  7. `exiv2 -pa` on the stripped JPEG prints no line whose key starts with `Xmp.`, `Exif.` or `Iptc.`.
  8. exiftool `-j -a -G1` on the stripped JPEG has no key in the XMP, EXIF, IFD0, IFD1, ExifIFD or IPTC groups.
  9. Tagged and stripped bytes differ from the input and from each other.
  10. SHA-256 of decoded RGBA (`ffmpeg -f rawvideo -pix_fmt rgba`) is identical for the input, tagged and stripped JPEG.
- Expected failure modes and stop conditions: a missing or different read-back value, any predeclared key surviving `rm`, any pixel-hash difference, or a non-zero exit from exiv2. Each is a failure of the claim; predeclared values are not changed to fit a result. If exiftool and exiv2 disagree on a value, the cross-tool part is `partial` with the disagreement recorded, not a silent pass.
- Reproduce with `./run.sh`. Inspect with `exiv2 -pa output/tagged.jpg`, `exiftool -a -G1 output/stripped.jpg`, or by viewing `output/contact.png`.

## Observation, after running

- 2026-11-24, Exiv2 0.28.9, exiftool 13.50, ffmpeg 9.0.2, Python 3.12.2, Node v22.19.0, pnpm 10.29.2, macOS 26.6 arm64, `Conors-MacBook-Pro-2.local`. No browser, so no Playwright or Chromium version applies.
- `./run.sh --record` wrote `expected/summary.json`; a second `./run.sh` printed `exiv2-metadata-roundtrip: OK` (exit 0).
- `exiv2 -pa` on the tagged JPEG returned exactly `Xmp.dc.title` "VCR metadata fixture", `Xmp.dc.rights` "CC0 fixture; no rights claimed" (LangAlt prefix `lang="x-default" ` stripped by the checker), `Exif.Image.Artist` "VCR fixture" and `Iptc.Application2.Caption` "VCR caption fixture".
- exiftool 13.50 read the same four values from the exiv2-written file: `Title`, `Rights`, `Artist`, `Caption-Abstract`. No disagreement.
- After `exiv2 rm`, `exiv2 -pa` printed nothing and exited 0, and exiftool `-a -G1` showed no key in the XMP, EXIF, IFD0, IFD1, ExifIFD or IPTC groups.
- Decoded RGBA SHA-256 was `44dfe21a...dbe8a3` for the input, tagged and stripped JPEG, the same hash the exiftool fixture recorded for its JPEG. Decoded length 12288 bytes (64x48 RGBA). Tagged and stripped bytes differed from their inputs.
- Visual check: `output/contact.png` (input, tagged, stripped side by side, 800% point-filtered) shows the same colour-bar test chart with a gradient strip in all three panels. No blank, clipped or shifted frame. The metadata itself is not visible, as expected; the picture check only confirms the pixels were not altered.
- Result: pass for the declared claim on JPEG with Exiv2 0.28.9 and exiftool 13.50.
- Not established: PNG or other formats, fields beyond the four above, MakerNotes, GPS, thumbnails, other exiv2 actions or the library API, readers other than exiftool, Linux or Windows builds, or the Exiv2 release history (the card's recency is still unconfirmed). Input is a synthetic test chart, not a photograph.
- Deviations: none from the plan. Read-back runs inside `check_output.py`; no `readback-*.json` files were written.
- Side effects: `output/` (ignored) and `expected/summary.json` only. Nothing installed; Exiv2 and exiftool were already present. The catalogue build and validate were run; generated files were restored to HEAD and not committed.
